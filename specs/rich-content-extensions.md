# Rich content extension contracts

Status: planned portable and web delivery, roadmap 25. Reuse roadmap 07 implementations and roadmap 21 public interfaces; this work adds the named gaps rather than replacing qualified modules. Full native/TUI integration consumes these contracts in roadmaps 31–36 and is not an upstream prerequisite.

## Ownership and public boundary

Rust remains authoritative for content, schema, commands, validation, source reconciliation and history. Highlight tokens, table layout, decoded media, menus and drag geometry are derived presenter state. Platform caches may be discarded without changing the document. Optional processing/presenter dependencies are absent from minimal consumers when disabled.

Expose each feature through the owning Rust crate and documented `@edit-ac/core`/`@edit-ac/web` exports. Reuse existing extension descriptors, command preparation, scoped subscriptions and presenter lifecycle. A new crate/package requires an explicit consumption/size reason. Define versioned feature records and capabilities for data preservation, view, edit, copy, source, accessibility and optional network activation.

Portable presenter ports carry stable node identity, content revision, source/profile, selection/readonly capabilities and bounded patches. Results carry request identity/revision; stale, canceled or disposed results cannot mutate or repaint a replaced target. Define prepare/apply actions separately from derived appearance updates. Publish fixtures that Swift/Kotlin/desktop/terminal presenters can consume without browser types.

### Captured touch formatting

The existing v5 prepared-format owner admits the six ordinary inline marks on validated reference labels, asset fallback text and inert-extension source text. Formatting preserves the complete descriptor, source bytes, backing-text identity and opaque attributes; ordinary URL, code-precedence, revision, authorization and history rules still apply. Tables require their scoped cell commands. Literal code blocks, arbitrary unknown tuples, malformed carriers and unsupported versions remain unavailable targets.

Labeled command controls expose all enabled marks without shortcuts in both legacy and configured editors. A whole content-node selection can retain its complete backing-text range for formatting and its undo/redo controls; ordinary capture, node deletion and clipboard routing keep their existing node-action semantics. Capture occurs before pointer/Tab focus leaves the surface, internal menu/link controls retain the target, and a foreign editor or changed revision invalidates it. Table rectangles likewise retire when a foreign editing control takes focus; their own link/format controls preserve the rectangle. These portable browser mechanics do not qualify native menus or target-platform input/accessibility.

## Code blocks and highlighting

Persist literal code and a validated language identifier. Highlight spans, grammar/theme caches and syntax trees never become collaborative marks or another writable document. Preserve unsupported labels and provide immediate plain-code editing when a language is unavailable, loading, over budget or disabled.

Qualify a maintained Rust-capable backend and exact grammar/query versions before selection. Tree-sitter is an initial candidate, not a promise of performance or coverage. Test Rust, TypeScript and JSON initially; every additional language names grammar license/version, bounds and evidence. Optional browser-only alternatives may be compared, but do not imply portable native tokenization.

Own backend code, grammar dependencies, caches and compile probes in the optional `editac-highlighting` Rust companion crate. It is independently consumed by native hosts and optional browser worker bindings; the semantic engine has no dependency on that runtime. Small descriptor/offset/span records may remain public engine contract types. Reuse existing npm package exports for optional loading until measured consumption justifies another npm package.

The highlighting port accepts immutable block text/edits plus prior cache identity and returns validated token spans and a cache handle. Cache keys include block/revision/language/grammar/query/theme versions. Test UTF-8-to-UTF-16 conversion, overlapping/invalid spans and multiline state changes. Incremental output must equal the selected backend's full recomputation for the same input. Bound retained trees/tokens and invalidate on identity/language/profile changes.

Browser workers are optional scheduling adapters, not owners of document state. Record startup, transfer, processing and DOM-application costs separately; coalesce obsolete requests, bound queues and terminate owned workers on disposal. Highlighting never delays input, local persistence or collaboration. Rendering preserves selection and leaves the active composing subtree browser-owned until safe reconciliation. A highlighting failure remains a visible plain-code fallback, not lost source.

## Table editing, layout and source formatting

Keep bounded rectangular tables and simple cells; merged cells, spreadsheet formulas and a general layout engine remain outside this contract. Extend the existing module with explicit row/column insert/remove, header/alignment, cell selection, keyboard movement and cell-range copy/paste commands where missing. Record behavior when deleting the last row/column and for readonly/invalid targets. Every accepted operation has one intentional undo group.

The public `tableRectangle` editor command routes exact-descriptor clear (`cells: null`) and literal row/column matrices through the existing Rust rectangle preparation (128 affected cells, 1 MiB replacement). Dimensions must match; expansion, merged cells and nested fragments reject. Host-owned protected coordinates accompany the captured descriptor; whole-document authorization remains the host commit owner's responsibility. Browser cell selection is transient and explicit, separate from native cell text selection. Shape changes remain explicit `tableStructure` commands. The browser exposes separate cell-selection buttons (Shift-click extends the rectangle), preserving the native textarea Tab order. Alt+Enter in a cell explicitly enters cell selection. In cell-selection mode arrows move its focus, Shift extends from its captured anchor, Home/End address the current row and Control+Home/End address the table edges. Selection is bounded to 128 cells; an oversized extension preserves the previous selection. Movement beyond an edge is an announced no-op and never inserts a row or column. Tab and Shift+Tab retain native focus traversal, including at the last textarea. Enter enters the first selected cell; typing replaces that cell only. Delete/Backspace clears the rectangle, while structural removal currently requires one selected row or column. Clipboard output is explicitly literal HTML/TSV/plain text; marked transfer is unqualified. Literal input normalizes CRLF row separators, retains explicit row/column boundaries and requires exact dimensions. TSV and its declared plain fallback quote fields containing tabs, LF or quotes and double embedded quotes; quoted tabs remain inside a cell, and empty trailing fields retain columns. SFR-1.1 admits LF within existing v1/v2 runs without adding rows or cell blocks. CR remains rejected by shared commands/descriptors; native textarea input and explicit literal cell paste normalize CRLF/CR to LF before preparation. Enter and Shift+Enter insert one cell LF through the same prepared command; marks, source provenance, history and bounds follow [formats.md](formats.md). Single-block cell copies expose quoted literal fallbacks alongside the internal run matrix; multiple cell blocks retain only structured transfer rather than losing block boundaries. Clipboard processing is bounded to 128 cells and 1 MiB UTF-8 per offered/produced representation. Literal HTML must contain exactly one simple table with no discarded surrounding content or executable attributes; only unit row/column spans are admitted. Unsupported HTML markup, merges or nesting reject even when accompanied by a flattened fallback. No table resize/drag preview is introduced; nested controls retain their own input/selection/gesture owner beside the optional block reorder controls.

Commands use stable table/row/cell identities and the frozen structural concurrency policy. Qualify concurrent row/column changes, cell edits and deleted destinations. Deterministic core projection resolves invalid remote structures; presenters do not emit their own repair transactions.

The portable `tableAttributes` command captures the exact table descriptor and a nonempty rectangle of at most 128 cells. `header` is an optional explicit boolean applied uniformly to those cells (including mixed-header selections); `alignment` is an optional `none`, `left`, `center` or `right` value applied to the entire intersected columns. At least one attribute is required. Host-protected cells reject the whole action: header checks the rectangle, while alignment checks every row in the affected columns. Readonly, stale, non-table, unsupported/unknown descriptors and merged cells reject before a live write. Host authorization and table-codec capability are checked by the existing edit service at preparation and commit.

V1 retains its implicit first-row header and all existing cell runs. A header action that cannot be represented by those implicit flags promotes the same atom to the already admitted v2 format, preserving source, cell coordinates and formatting; other attribute edits preserve the descriptor version. No separate collaborative cell IDs or schema are introduced. One exact-descriptor commit preserves the table owner/anchors and has one undo group. Concurrent tuple changes follow the existing whole-atom winner policy, not a field-wise merge. V1 alignment round-trips through `edit-ac-gfm-v1` pipe delimiters. V2 header layouts use the existing `rich-table-source-fallback` diagnostic and complete typed recovery; Markdown source alone cannot encode arbitrary per-cell header flags and is not a lossless v2 import claim. Unknown data is retained or rejected, never normalized into an admitted table by this command.

Cache geometry/indexes per table and invalidate only affected tables/cells. A cell edit must not scan or rerender every table in the document. Native/TUI ports expose cell rectangles/selection and semantic navigation separately from browser DOM geometry. Copy/export preserves hidden/unknown bounded content or reports a recoverable limitation.

The Markdown table formatter is an explicit selected-table source operation. Use the retained source baseline and revision-checked reconciliation; preserve surrounding bytes, code spans, escaped pipes, alignment, empty cells and final-newline policy. Record the Unicode display-width policy used for aesthetic padding. Formatting is deterministic and idempotent on its own output, with one undo group. It does not normalize an entire file or run automatically on every cell edit.

The initial `SourceBaseline::prepare_table_format` accepts one retained top-level v1 GFM table owner with its codec enabled. It compares the exact opening replica revision, source span and descriptor, and independently reparses the candidate to prove unchanged document semantics. Both preparation and commit (including no-op commit) reject a stale revision. The existing prepared engine command/history owner applies `TableSource` as a bounded, exact-descriptor source-metadata replacement: rows, alignments, owner and backing text remain untouched. Codec validation belongs to the optional Markdown owner; the low-level command stores inert source only and does not parse or execute it. Session admission requires the existing table capability and write authority. No new schema, wire DTO or shared review/transfer API is introduced.

Padding counts every Unicode scalar as one aesthetic column, including combining characters, tabs and ZWJ; it makes no font/terminal display-width promise and performs no Unicode normalization. Trim only outer ASCII space/tab in cell lexemes; retain escapes, backtick delimiters and inline source. Use explicit outer pipes, at least three delimiter dashes and retained column alignment. Preserve each original LF/CRLF line ending and the original presence/absence of a final newline. Missing trailing cells become explicit empty cells. Reject excess ignored cells, bare CR, nested/container source and ambiguous mappings without mutation. Source/output remain bounded to 1 MiB under existing table dimensions. `source_with_current_table` rejoins current descriptor source with the untouched baseline bytes after normal engine undo/redo or checkpoint restore; it rejects changed represented content or owner order. Hosts retain write/readonly/protected-content policy as with other source actions.

### Scoped cell formatting and rich rectangles

`tableFormat` and `tableRichRectangle` are bounded prepared commands over an exact v1/v2 descriptor and at most128 selected unmerged cells. Both require table capability and the existing write/revision admission. Protected coordinates reject atomically. Formatting uses the ordinary inline owner's six marks, normalized safe links and precedence: applying code clears other marks, applying another mark over code rejects, and toggle removes only when every selected run already has the requested value. A formatting-only edit retains backing text/anchor identities. Rich rectangle replacement validates the entire resulting tuple before mutation and retains geometry, alignment, source and owner; one commit has one history intent. V2 formatting applies across admitted paragraph/heading blocks while retaining each style and header; literal code blocks reject inline formatting. Rich rectangles carry complete admitted v2 cells, reject span changes, and promote a v1 destination only for an explicit v2 offer or block-style action. Untouched cells, original source and destination column alignment remain preserved.

Trusted content-factory view elements own their descendant decoration/status mutations through the renderer WeakSet, as registered module decorations already do. Authored attributes cannot confer this ownership; native source outside those registered elements retains the ordinary input owner. Owned formatting commits retain the captured directional cell rectangle after synchronous engine observation, while unrelated/remote descriptor changes clear it.

The browser cell toolbar exposes those scoped marks and an explicit default-off literal-paste control. The version1 `application/x-edit-ac-table-cells+json` flavor carries exactly `version` and a rectangular `cells` run matrix. It takes precedence over literal HTML/TSV/plain flavors; malformed/unsupported structured offers reject rather than silently lose formatting. Literal mode bypasses this flavor and uses the existing literal decoder. Neither path interprets formulas, executes document code or fetches assets. The version2 flavor carries the same exact envelope with complete v2 cell records instead of v1 run arrays. Copy of multi-block cells omits the literal flavors rather than flattening block boundaries. Version1 offers pasted into v2 retain destination headers with an explicit paragraph payload; v2 offers carry their own per-cell headers. Column alignment belongs to the destination table and changes only through its explicit scoped attribute action.

The browser v2 presenter renders admitted paragraph/heading1–6/code blocks, offers scoped paragraph/heading1–6/code-block commands plus explicit header/body and alignment actions, and retains its directional rectangle after owned commits. Converting marked text to a code block rejects without stripping marks. Single-block text controls use the existing table-cell owner; multi-block cells preserve their full previews/clipboard but expose readonly native text with an explicit unavailable-edit description. Block conversion of multi-block cells rejects. Lists, merged geometry and unknown styles/codecs remain explicit unsupported/source fallbacks; no formula or document-supplied code executes. The [RCH-1.23 portable browser return](../evidence/rich-presenters/formatting/qualified-return-20261017/receipt.json) qualifies the composed table, marked caption/reference/asset/inert and registered math transfer matrix, including scoped actions in a mixed document, atomic history, source recovery and durable reopen. Its receipt distinguishes full-command failures from unchanged passing cases and repaired-case proof. Native consumers and original roadmap aggregates retain their separate qualification gates.

## Attachment and blob lifecycle

Define file/image/media descriptors with stable host asset identity, bounded filename/media type/size/hash metadata, alt text/caption where applicable and a safe fallback. Temporary object URLs and expiring signed download URLs belong to presentation, not persistent shared identity. A filename, MIME declaration or hash alone does not grant download rights.

The v1 portable asset descriptor is `Content::Asset` (`module:editac.asset`, version1) in `editac_core::modules::assets`. It complements the existing source image descriptor. Identity is a host namespace (1–64 ASCII letters/digits/underscore/hyphen) and opaque host key (1–256 of the same characters); hosts allocate non-secret durable IDs. URL-shaped identities and extra access/credential fields reject. An opaque key is not a bearer token; a host must never deliberately encode secrets into it. Unknown source is retained verbatim and inert, while a separate nonempty plain-text fallback (≤8192 UTF-16 units) is escaped on export, with a binary-unavailable diagnostic and typed recovery.

Metadata bounds are bytes: filename1–1024, MIME1–127 (lowercase type/subtype without parameters), alt/caption≤8192 each, source≤1MiB. Filename paths/control characters reject. Optional byte length/duration are exact unsigned integers≤2^53−1; SHA-256 is64 lowercase hex digits. Dimensions are paired positive integers≤1,000,000; files have no dimensions/duration, images have image MIME and no duration, media has audio/video MIME. Declarations never attest actual media or authorize decoding. Asset validation runs on disposable command preparation; fallback text and descriptor commit together through existing fragment/atomic commands. Direct Content conversion requires matching unmarked fallback text.

Availability (`local`, `queued`, `available`, `failed`, `missing`, `revoked`, `locked`) belongs to an identity-scoped host observation, not the shared descriptor. Another replica with no observation displays the retained fallback as missing; parsing shared metadata causes zero requests. Local/queued state is not advertised as remote byte availability. Host request records version1 carry identity, a bounded non-secret idempotent operation ID, explicit action and byte-work limit. A host grant scopes every action to one identity; metadata alone grants none. Authorize/ingest/read/cache/publish/resolve-url/cancel/release-reference and later open/download consumers use these records. They define the port vocabulary, not a durable lifecycle implementation. Asset publication receipts bind operation and identity separately from document receipts. Resolved URLs are ephemeral, capability-checked host responses without serialization into descriptors; object URLs/signed HTTPS URLs must never become stable identity. Existing encrypted BlobHost ownership and downstream E2EE policies are unchanged.

The host asset port handles authorize, ingest, read/cache, publish, resolve URL, cancel and release-reference operations with explicit capabilities. Upload/account/storage products remain host responsibilities. Define local-only, queued, available, failed, missing, revoked and locked outcomes, including what other replicas display before bytes become remotely available. Asset commit and document update receipts remain distinct.

Journal resumable local work and bound blob/cache/outbox storage. Crash, full disk, auth expiry, offline reconnect and deletion during upload preserve recovery data without resurrecting deleted nodes. Idempotent host operation IDs prevent duplicate upload intent; transport retry semantics are explicit. Shared binary deletion/garbage collection requires host ownership/refcount policy rather than an editor deleting data on every removed node. E2EE ports preserve the security profile across originals, thumbnails, caches and exports.

The Session asset lifecycle extends the existing per-document MemoryStore/SQLite snapshot transaction, not the semantic update journal or wire. `AssetWork` admits ingest/read/cache/publish only with an explicit identity/action grant; the host allocates unique non-secret operation IDs across its scope and retains local source bytes before acknowledging ingest. Intent and asset publication receipts never acknowledge a document update. No startup/recovery automatically contacts a host. One explicit dispatch reauthorizes and persists its attempt before host execution; offline/expired-authority/errors retain the same pending ID and recovery bytes. At most eight explicit attempts are allowed; there are no automatic retries. Ambiguous commit is resolved by rereading/retrying the same ID, with the host responsible for idempotent execution after a crash between host effect and receipt persistence.

The store bounds asset intents/tombstones to256 each, cache reservations to64MiB, and includes intent metadata in its existing record/total quotas. Host caches must enforce the reservation against actual encoded bytes, encryption and their own storage budget. Completed IDs/tombstones are retained for deduplication; exhaustion returns backpressure, never evicts recovery state. Cache reservation is held through cancellation and released only after the host acknowledges scoped release-reference cleanup; this never attests global binary deletion. There is no implicit binary eviction. Credentials and temporary URLs never enter this journal. Prepared originals are the bounded local-byte exception described below; they never enter the semantic document, update journal or wire.

Before dispatching after a node deletion/cancellation, the owning host calls `AssetWork::retire` with the captured reference and identity. It atomically fences pending work and queues idempotent cancel/release-reference actions; persistence failure must leave the host operation unacknowledged and recoverable. Hosts reconcile retired/deleted references before resuming recovered uploads, and never infer live nodes from asset work. A late valid publication receipt for canceled work is ignored; already-issued upload effects are reconciled by scoped release, never node recreation. Release dispatch/acknowledgment waits for successful host cancellation; that acknowledgment must fence outstanding effects on the reference. The release action identifies this document/reference only; the host owns global reference counting, shared binary deletion and cache reclamation. Lifecycle APIs perform no semantic writes. The browser presenter integration must wire deletion/recovery to these explicit host hooks before claiming automatic UI lifecycle support.

The optional browser `AssetSession` (`@edit-ac/web/assets`, or the existing storage lifecycle's `enableAssets`) stores the opaque, document-scoped Rust AssetJournal and retained local bytes atomically in the existing IndexedDB database. `EngineHandle.assetWork` is its bounded synchronous transaction codec, not a host dispatcher or document commit. The Rust `begin_dispatch` boundary persists one authorized attempt before asynchronous host work; `run_one` uses that same boundary. Explicit `runOne` reauthorizes; open/recovery never dispatches. Live `enqueue` requires an already existing descriptor at the captured stable node ID with matching identity; the job-owned pre-insertion APIs below are separate admission paths over the same journal. The browser binding reversibly hex-encodes node IDs as opaque AssetWork reference keys; the journal keeps no parallel node model. Deletion/replacement is reconciled before dispatch and completion; retirement persists cancel/release fencing and never writes a node. Undo does not reactivate a retired reference. Live retained bytes are immutable per reference and bounded to64MiB per document, remain recoverable through errors/suspension, and are removed only after scoped release acknowledgment. Host transports must enforce idempotency and fence outstanding effects before acknowledging cancel. Operation receipts have `kind: assetOperation` and cannot satisfy document persistence.

### Prepared import originals

`AssetWork::stage_original(job, reference, ingestRequest, grant, bytes)` retains an immutable job-owned original and its explicit ingest grant in the existing per-document asset transaction. It requires no descriptor or live node, writes no document/revision/history, and performs no host work. The same transaction admits the existing ingest intent; it creates no second journal. Job/reference/operation keys, matching identity/action authority, nonempty source, request byte limit, total retained originals (64MiB), intent cleanup capacity and existing store record/total quotas are enforced before commit. The current synchronous WASM transaction additionally bounds its complete JSON input to2MiB, including recovered journal and staged byte arrays; exceeding this limit is a typed rejection, never truncation. This is a bounded local prerequisite, not packed browser adoption qualification.

A reference already owned by live work or another job cannot be claimed. An exact stage retry is idempotent; changed bytes, request, grant or job conflict, and retired references cannot be reused. Persistence failure preserves caller-owned source; an ambiguous acknowledgment requires reopening/reading or retrying the same immutable input. A successful stage makes exact bytes/identity/grant recoverable in MemoryStore/SQLite snapshots without consulting a host. `prepared_source` requires a fresh matching read grant and returns a copy; captured ingest authority does not authorize reads or future dispatch. Old journals decode with an empty prepared collection.

Reconciliation distinguishes active prepared references using Rust-owned prepared metadata (`is_prepared`, and `EngineHandle.assetWork`'s `prepared` summaries); absence from the live document cannot retire these job-owned references. Explicit retirement still fences their work and preserves recoverable originals; it does not delete sibling or globally shared binaries. The codec exposes `stageOriginal` and `preparedSource` for the shared browser owner. The public pre-insertion stage/read/fence APIs are described below. Binding adoption to the real shared insertion/history transaction and packed runtime qualification remain subsequent gates; no descriptor-first insertion or compensating undo is permitted.

`AssetWork::fence_job(job)` durably closes even an empty job in the same asset transaction. Later staging under that job conflicts, including after reopen or a delayed authorization callback. It atomically retires every uncommitted original owned by that job, reserves unique bounded cancel/release IDs, preserves sibling/live work and retains original bytes with their captured grants for explicit recovery reads. A failed transaction publishes neither a partial fence nor partial retirement; ambiguous acknowledgment is resolved by rereading or an exact retry. Job tombstones are bounded to256 and never evicted or recycled. Legacy journals default to an empty fenced-job collection. The WASM codec exposes `fenceJob` and `fencedJobs` summaries; public `AssetSession.stageOriginal/preparedSource/fenceJob` persist these Rust results through the existing IndexedDB asset transaction. Session retirement closes stage/enqueue/dispatch admission before asynchronous teardown, shares teardown completion across concurrent disposals, and fences prepared jobs without decoding opaque prepared references as live node IDs. Queued stages recheck admission inside the existing storage transaction. The pure Rust `AssetJournal::prepare_adoption(job, bindings)` prepares a candidate over the same journal without mutating storage or content. Every binding must identify an active original of that exact job, match its asset identity, and target a unique unowned/unretired reference. It transfers the existing intents and immutable operation IDs, records the adopted reference beside the original source/grant, retires unused job originals, and closes the job against later stages. Sibling/live refs are unchanged. The candidate is **not** an insertion receipt: the shared insertion planner must derive and verify the targets and persist the candidate with its exact prepared content update in one transaction after comparing the input journal. No browser adoption API exposes this primitive before that atomic binding is implemented. Cancellation of an already adopted job cannot retire its committed references; document reconciliation owns their later retirement. Rust derives `host_reference` from the retained original/adopted binding: host effects keep the original scoped reference used for ingestion even after their content-facing journal reference transfers to a live node. The codec exposes this as `AssetIntent.hostReference`, including begun attempts. Cancellation/release must use it so adoption cannot orphan the ingested host reference or release a sibling.

Prepared references cannot use the browser live-node `node_` namespace. Explicit `runOne` can ingest an active prepared original through the existing persisted attempt/complete owner, with fresh host authority and exact retained bytes. It rechecks the durable job fence before dispatch and completion; late callbacks cannot reactivate it. No automatic host work is introduced. Read authority remains distinct from ingest authority.

For atomic browser insertion, `EngineHandle.reserveAssetCommit(plan, journal, job, references)` admits only a current shared editor/fragment plan. Rust previews its exact update without live mutation, derives every new asset target from the candidate document in visible order, and validates one same-identity job original per target, unique ownership and completed explicit ingest. Existing asset replacement, missing/extra bindings, stale plans and fenced work reject. The browser holds semantic admission until commit/abort; other content/history/replay/disposal mutations reject during that interval. This is a short admission reservation, not another lifecycle journal. Caller-owned original bytes, grants and immutable operation IDs remain in AssetJournal.

`AssetSession.commitPrepared` prepares the update checksum before opening storage, compares the captured input AssetJournal inside one strict IndexedDB transaction over `assets` and `updates`, and writes the candidate journal plus exact shared content update together. It applies the same reserved Rust plan once only after transaction completion; storage failure or pre-completion cancellation aborts without live content/history and fences only uncommitted job work. Transaction completion linearizes adoption: later cancellation preserves committed refs. Reopening after a crash between durable commit and live application replays the exact content update and sees the adopted journal without host/network work. The existing journal update identity/checksum resolves duplicate storage admission; conflicting writer/sequence bytes abort. `LocalStorageLifecycle.commitPreparedAssets` flushes prior local work, uses this same database and observes its already-durable receipt rather than appending the patch again. History remains owned by the one Rust editor commit; undo reconciles work without granting new host authority, redo cannot resume retired effects, and originals remain recoverable with a fresh read grant. Packed qualification and consumer media-import acceptance remain separate until their complete evidence passes.

Storage teardown defaults to asset retirement and aborts pending transports. Explicit `assetPolicy: suspend` permits recovery with pending IDs/source bytes and still aborts transports; reopening reconciles deleted targets before any explicit dispatch. The host must resume cancel/release cleanup explicitly after a retirement. Capability denial, unsupported actions and source conflicts abort the entire browser transaction. This shared boundary does not implement picker/capture UI or qualify platform delivery; MEX-1.5-C4/MWX-C17/C18 consumer proof remains separate.

## Image, file and embed presentation

Images enforce encoded-byte, decoded-pixel, dimension and concurrent-decode limits. Validate the actual media type under host policy; handle malformed/SVG/animated content explicitly. Render alt text and missing/offline/locked fallback. Dispose object URLs, observers, decoders and requests. External image loading requires host asset policy; parsing/opening a document does not authorize arbitrary URL fetches.

File attachments expose accessible filename/status/size and an explicit host-authorized open/download action. Clipboard/source export uses the declared stable identity/fallback and reports unavailable binary data. Native attachment view and terminal fallback records are part of the public presenter contract, not an assertion that those presenters already ship.

PDF export is a separate requested output capability. An attached PDF remains an opaque file asset; optional host preview is not PDF import, OCR or conversion into editable content. The semantic core requires no PDF reader. Do not add a PDF ingestion prerequisite to attachment handling.

Embeds store a bounded URL/provider identity and safe fallback, never executable HTML/code. Separate a metadata card from an activated interactive embed. Hosts register allowlisted presenter templates and an isolated/sandboxed activation policy; raw oEmbed/provider HTML never enters the editor DOM. Apply the [link resolver contract](link-resolution.md) to metadata and secondary media URLs. Roadmap 25 uses prepared resolver fixtures; actual resolver integration and native/TUI presenters are qualified downstream. Unsupported/offline/readonly modes retain identity and safe content.

Browser embed envelope (RCH-1.15): the existing bounded inert-extension carrier holds `['module:editac.inert-extension',1,{type:'editac.embed',version:1,dataVersion:1,source,payload:{url,provider,fallback}}]` with exactly those envelope/payload fields. URL is bounded to4096 UTF-16 units, provider to64 ASCII identifier units, fallback to8192, source plus the entire carrier to1MiB UTF-8. No executable markup field is admitted; source is an inert readonly textarea. This is an optional presenter, not a new semantic node family or Markdown importer. Unknown/unavailable presenters retain the normal opaque source fallback. Native/TUI consumers remain downstream.

`contentModules({embeds})` accepts the existing public LinkHostPorts resolver, a current authenticated LinkHostContext getter and at most32 unique provider templates. Rendering/reopen/remote/replay does no lookup. Explicit Refresh card requests ephemeral metadata; explicit Activate embed performs a fresh lookup and authority check against the captured node, scope, provider and locator. Readonly presents source only. Only bounded text title/description are displayed; provider HTML, canonical URLs and secondary media are ignored. The host performs URL/connection/redirect/egress validation and cancellation under link-resolution.md. No implicit retry or persisted enrichment occurs.

Templates are host-trusted HTTPS endpoints without query/fragment/credentials/custom port, copied at factory creation. Activation adds the original locator as a URL-encoded `url` parameter; metadata cannot choose an endpoint. Iframes use sandbox `allow-scripts` only (no same-origin, navigation, forms, popups or downloads), no-referrer, denied camera/microphone/geolocation/fullscreen and the credentialless attribute where supported. Hosts must configure cookie-free isolated endpoints and enforce egress/CSP/redirect restrictions; sandbox does not itself remove network access or guarantee credentialless behavior on all engines. This prepared-browser proof does not qualify production providers. A Deactivate action, descriptor replacement, readonly transition or disposal removes the iframe and aborts owned work; current host scope is revalidated at response/effect time. Hosts must deliver permission/account changes by view update/remount. Default concurrency8/max32 and timeout15s/max30s bound pending work without queues. Unsupported/offline/forbidden/missing/locked outcomes retain source and fallback.

## Slash, references and reorder

Extend the existing slash menu with explicit trigger context, code/literal exclusions, IME lifecycle, selection replacement and query-length/result-count bounds. Filtering is scoped to current input context. Focus restoration, escape, empty/error states, touch/pointer selection and screen-reader labels are tested; remote edits/replay never open the menu. Async providers follow the shared cancellation/revision contract.

Custom references retain stable target identity and user-authored fallback text. Their presenter consumes the host resolver's public/private/forbidden/missing/locked outcomes, without inventing target access or sharing private titles. Lookup, disclosure and cache policy live in [link-resolution.md](link-resolution.md). The feature supports configured `@`, `[[` or other bounded triggers through the existing registration interface, with plain-text fallback and explicit activation.

Block pointer reorder uses a derived drag session: threshold, hit testing, auto-scroll, valid destination, cancellation and current target anchors. Hover does not mutate CRDT state; final acceptance prepares one semantic move and one history group. Preserve content identity and selection under concurrent edits/deletion. Provide keyboard movement and a simple click/tap alternative such as Move before/after; keyboard alone does not replace the non-drag pointer alternative. Announce destination/result through platform accessibility ports.

## First-party document search and code conveniences

These optional features extend track 25 and reuse the semantic engine, public commands and existing presenter contracts. [Desktop research](../evidence/desktop-editing-research.md) supplies precedents; [desktop cases](../tests/desktop-editing-cases.md) define the chosen scope. Their absence does not disable ordinary native/browser Find or baseline editing.

Document Find searches logical content, including unmounted blocks, through a bounded revisioned index. Default matching is literal and case-sensitive, without Unicode normalization or invisible content rewriting. Expose whole-document and captured-selection scopes; matches cannot cross atom, table-cell or block boundaries unless an explicitly documented query profile supports those boundaries. A case-insensitive profile must declare Unicode/locale rules and map matches back to complete original characters. Regex/wildcards, format matching and workspace-wide search remain unsupported until separately bounded and qualified. Search highlight is transient presentation, not a persisted mark or remote edit. Enter/Shift+Enter in the search field navigate next/previous; Escape closes it and restores the appropriate editor selection without overwriting later deliberate navigation. Empty queries clear results without generating zero-length replacements. Result wrap and count are explicit and accessible.

Replace Current acts on the anchored current match after revision/permission revalidation, not the find input's selection. Replace All enumerates nonoverlapping matches in the captured scope of one revision, prepares a bounded compound operation and commits once with one undo group; it never recursively searches its own inserted replacement. Record match/count/byte limits before execution. On limit, stale target or unsupported structure, keep the document unchanged and offer a narrower scope; do not silently perform a partial replace-all. Async scanning is cancelable and rejects stale results. Existing marks outside replaced ranges remain unchanged; inserted text follows the captured destination typing-mark policy. Protected/read-only ranges are excluded with explicit counts before confirmation or cause atomic rejection according to the named profile, never silent skipping. Remote edits require revalidation/recomputation before any destructive commit. Native OS find UI may use this provider after the platform task qualifies its scope/history and focus behavior.

The initial optional `editac.document-search.literal.v1` provider is exported from `@edit-ac/core/extensions`; `documentSearch()` adds explicit browser Find/Find in selection controls. Native Ctrl/Cmd+F is untouched. It searches ordinary text owners across standard formatting runs, excluding opaque module payloads and module-annotated runs. Metadata, table payloads/cells, captions and custom inline atoms have no admitted structural query/replacement profile; their fallback labels are not silently interpreted as editable source. It cannot join blocks, atoms or cells. Limits are 256 UTF-16 query units, 10,000 visible blocks, 1,048,576 scanned units, 256 nonoverlapping matches and 1,048,576 aggregate UTF-8 replacement bytes. Scans yield every 32 blocks, publish only a current complete result, and expose work counts. Over-limit queries publish no partial match set. Inserted text uses the existing engine destination inheritance policy. Whole-set host authorization defaults to document authority; hosts with protected ranges must supply `authorize`, which rejects the whole operation. The caller's commit port remains responsible for current document write authority and persistence. Browser highlights use the optional CSS Custom Highlight registry; navigation/count provide the fallback on runtimes without that API. Virtualized hosts may supply an explicit `reveal` port; scanning never depends on mounted DOM. Portable fixture records live in `core/fixtures/document-search/`, with native platform wiring still unqualified.

The code convenience profile provides move selected logical lines up/down, duplicate logical lines, indent/outdent, and explicit surround-selection with a supported paired delimiter. A selection ending at the start of the next line excludes that untouched line. Preserve LF, tabs, trailing spaces, marks allowed by code, directional selection and EOF without a terminal LF. Moving past block boundaries is a no-op; do not merge code with prose or move table cells. Each accepted operation has one undo group and complete prepared validation. Enable line comments only for a declared language/comment grammar; unknown languages expose an unavailable command. Automatic pair completion is a separate explicit opt-in: suppression during composition, paste, correction, remote replay and literal input is mandatory; overtype/backspace behavior is fixed by the profile. Visible command access and remappable platform bindings take precedence over borrowing conflicting IDE keys. Multi-cursor, AST refactoring, language servers and macro recording are outside this profile.

The initial `editac.code-conveniences.v1` profile exports `executeCodeCommand` from `@edit-ac/core/extensions` and the opt-in `codeCommands()` browser factory from `@edit-ac/web`. The source and output limit is 102,400 UTF-8 bytes and UTF-16 units per code block. The existing code semantic profile admits unmarked literal text; code with unsupported run attributes rejects rather than stripping them. Indent inserts two spaces; outdent removes one leading tab, up to two spaces, or nothing. Comments toggle a declared `//` prefix for Rust/TypeScript/JavaScript and `#` for Python/Bash after existing indentation, inserting/removing one prefix space. Other language labels retain plain editing with an explicit unavailable comment action. Surround supports parentheses, brackets, braces and single/double quotes and retains the original selected text inside the pair with its direction.

`autoPair` is a separate option, false by default. The initial bounded policy pairs only a collapsed trusted direct key followed by matching cancelable `insertText` before whitespace, EOF or a closing delimiter. It never surrounds a replacement selection automatically. Overtype/backspace apply only to the immediately owned empty adjacent pair at the same revision; overtype moves selection without a text/history update and Backspace removes both delimiters in one explicit group. Other typing uses ordinary input. Composition, paste, correction, literal insertion, remote replay, navigation, permission changes and disposal invalidate pair admission. No parser or language-server behavior is implied. Visible actions and optional modified-key bindings use the same prepared commands; Tab/Shift+Tab remain with the baseline keyboard owner: code Tab inserts one literal tab per touched line, with bounded dedent and Escape then Tab focus escape as defined in editor-interactions.md. Explicit convenience controls and modified bindings retain this profile's two-space indentation. Bindings cannot reserve Tab, Escape or Enter. Browser event replay proves this integration, while OS input/accessibility and downstream native wiring retain their separate qualification gates.

Table commands distinguish a text range from a cell rectangle. Delete/Backspace on a cell rectangle clears editable contents while retaining table geometry; Remove Rows/Columns is an explicit structural action. Mixed protected cells, partially selected merged cells if supported, rectangular paste dimension mismatch, literal TSV and nested native controls require declared outcomes before mutation. Unsupported merged cells never get flattened silently. These extend RCH-1.6/1.8 rather than introducing a second table model.
