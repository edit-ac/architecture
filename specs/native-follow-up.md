# Native SDK follow-up boundary

Qualification amendment (user decision, 2026-10-14): Named target-platform simulators/emulators and desktop OS VMs/test hosts may satisfy platform and release gates when physical hardware is unavailable. Follow the [platform qualification policy](../specs/verification.md#platform-qualification-with-simulators-emulators-and-vms) for required runtime checks, tested virtual equivalents for hardware-only observations, counts and physical/virtual provenance. Earlier physical-only/manual-only wording in this document is superseded. This changes accepted evidence, not required implementation or correctness.

NAT-1.7 turns the [measured preparation evidence](../evidence/native-preparation.md) into a delivery boundary for later native owners. The Rust engine, UniFFI 0.32.2 ABI and actual UIKit/Android control probes are feasible foundations. No full mobile SDK or cross-platform parity is qualified. This document does not change any roadmap acceptance criterion or authorize implementation beyond roadmap 09.

## Entry and architecture

Recheck the platform's original roadmap entry gates at the then-current source and package revisions. iOS consumes NAT-1.1/1.2/1.3/1.5; Android consumes NAT-1.1/1.2/1.4/1.6. Qualified shared sessions, storage, synchronization and extension contracts remain separate prerequisites. Reuse prepared corpus expectations and real native controls; no WebView implementation or competing writable model.

Preserve the [ABI](native-abi.md): opaque ownership, UTF-16 public positions, detached owned data, bounded batched commands, typed failures, relative asynchronous anchors and explicit cancel/dispose. A UI scheduler must keep expensive synchronous bridge work off the input path while preserving serial document ownership and main-thread platform UI rules. Cancel stale host work by captured session/revision/target; do not cancel an accepted commit by pretending it rolled back. Dispose subscriptions, queued patches, plans, anchors, renderers and services together. Keep foreign callbacks outside Rust transactions and locks.

The observed whole-node decoding/scalar diff and full-control composition cancellation are preparation limitations. Establish a projection strategy and queue bounds before claiming efficient large-document editing. Measure generated, Rust staging and platform costs separately; the probe counters cannot freeze a zero-copy, latency or memory guarantee. Keep runtime/generator compatibility and Kotlin's four temporary error-property transformations visible until distributable bindings are requalified.

## Platform-specific constraints to resolve

iOS preparation used Xcode 26.6/Swift 6.3.3 and an arm64 iOS 26.5 Simulator static library, with explicit SDKROOT selection. It did not build a distributable device/simulator XCFramework or qualify deployment targets. TextKit 1 and legacy window-host warnings are candidate-host facts; choose and qualify the final control stack rather than generalizing to every TextKit version. Retain anchor ownership until prepared commands commit. Define composition behavior with remote updates, OS replacements and multiple editors before declaring an input capability.

Android preparation used Gradle 8.14/AGP 8.10.1/Kotlin 2.2.0/JDK 17.0.20.1, NDK r27b and one arm64-v8a APK on Android 16/API 36. The API 35 linker and API 36 app/emulator are distinct build/runtime facts. A macOS JNA host is not an Android artifact; the emulator APK is not a distributable SDK AAR. Resolve generated error-property compatibility, ABI coverage, dependency notices, consumer shrinker/native loading and min/runtime API policy in packaging. Direct InputConnection calls do not qualify vendor keyboards or candidate windows.

## Qualification and release separation

Browser release follows its own SDK, interactions, mobile-web and release gates. It neither waits for native SDK parity under preparation scope nor supplies native platform evidence. The later full-client milestone still requires its mandatory native capabilities; missing IME, clipboard, accessibility, attachments, persistence, reconnect or packaging must remain explicitly unqualified until their own gates pass.

Later platform owners produce exact source/package/fixture hashes, declared OS/device/keyboard/locale/assistive versions, nonzero executed/passed/failed/skipped counts, immutable logs and failure retention. Named target-platform simulator/emulator/VM observations and tested virtual equivalents may satisfy release qualification under verification.md. Use actual target-OS APIs where available and executed platform-boundary/accessibility checks for unavailable hardware-only observations. Preserve physical versus virtual provenance; no virtual result is a physical-device observation. Missing implementation or failing required behavior remains unqualified.

Footprint, startup, input-to-visible latency, main-thread work, long-node projection, queue bounds and repeated mount/dispose memory remain unmeasured. Preserve existing performance/release targets and obtain artifact-equivalent raw samples on declared physical or virtual runtime profiles; copy counters cannot replace those gates. Clean package readiness is separate from signing, publication and deployment, which require their explicit release authorization.

User-content migrations remain deferred under the controller decision. All automated scenarios use deterministic fixtures/prepared transports; no paid synthetic inference, `.secrets` loading or automatic fixture recording. This plan grants no live-content dogfood or public release side effects.
