## Initial feature profile and delivery order

1. **Ask AI and fill text:** invoke a visible command, selection toolbar or slash action; submit a custom instruction with an explicit context scope. Ask AI can return an answer without changing the document. Fill text generates at an explicitly captured caret/empty block or replaces a captured selection; continue writing extends a captured passage. Preview all replacements and insertions before acceptance.
2. **Selected-text actions:** spelling/grammar correction, rephrase, simplify, shorten, extend, tone adjustment, summarize/key points and translation with an explicit target language. Reuse one bounded operation envelope and proposal presenter. Preserve supported formatting and protected atoms; report unsupported structure rather than flattening it silently. These command names describe requested behavior, not measured model accuracy.
3. **Autocomplete while writing:** optional, disabled by default, host-enabled inline ghost text with configurable debounce, bounded local context and one current request per editor. Manual completion is available. A displayed suggestion is transient; only explicit acceptance commits text.

Deliver explicit actions before background autocomplete so context selection, proposal review and request limits are established first. Each platform advertises its own qualified subset; browser delivery can proceed without waiting for native devices. A disabled extension leaves baseline editing and minimal bundles intact.

## Host transport, context and request limits

Inject a versioned transport with operation/request IDs, bounded instruction/context/response envelopes, format/language options, cancellation and typed errors. Credentials and model/provider selection stay with the host's backend. No ambient key discovery, direct client secret, provider SDK in the semantic core/minimal client, automatic provider fallback or background retry. Optional host adapters may use version-pinned SDK dependencies. A disabled or unconfigured transport issues no requests and shows an actionable availability reason.

### Default Vercel AI SDK backend adapter

Use Vercel AI SDK Core as the default TypeScript host/backend implementation behind the portable transport, with a mock-backed reference recipe. [The evaluation](../evidence/ai-extension-research.md#vercel-ai-sdk-evaluation-and-default-decision) recommends it for shared generation, streaming, provider adapters and prepared mocks across the requested writing features. Alternative host implementations remain compatible with the public transport. Pin a released stable SDK/provider-adapter combination and qualify its runtime/API behavior during implementation; this plan does not install a package or select a model/provider. The SDK remains optional for the editor consumer, Rust engine and native clients.

For Ask AI and fill/continue, use `streamText` to feed bounded ephemeral answer/proposal state; no tools or agent loop are needed for the initial single-request flow. For autocomplete, begin with a short bounded `generateText` response and display a complete transient suggestion; only add streamed ghost text if measured UX/latency evidence justifies the extra lifecycle work. Debounce, IME protection, context selection, latest-request invalidation, review and semantic acceptance remain edit.ac responsibilities. The SDK's completion UI helper is an optional transport/state convenience, not evidence of editor-specific inline completion support.

Map SDK output, errors, finish/abort and available usage metadata into the bounded transport envelope. Forward cancellation through the client request, host runtime and SDK `abortSignal`; stopping the local preview alone does not establish server/provider cancellation. Explicitly set `maxRetries: 0` and disable additional stream/provider automatic retries supported by the pinned versions. Apply host quotas and context/output/time bounds before dispatch; SDK defaults do not establish request or monetary limits. Supply an explicit host-selected provider/model rather than relying on implicit gateway routing. No tools, agent loops, fallback providers or retrieval are enabled by this adapter.

Native and terminal clients consume the same host protocol and do not require a JavaScript runtime. Optional React/AI SDK UI helpers may handle transport/status only when useful; they do not own the editable document or replace the shared proposal session. The default backend requires neither Vercel hosting nor an implicit AI Gateway; use an explicit host-configured provider adapter. Qualify the SDK adapter with prepared mock models and simulated streams, including abort and retry-count assertions, without credentials, live providers or automatic fixture recording. SDK adoption makes no claim of lower model cost, completion latency or model quality; these depend on the selected host/model and separate qualification.

Expose context scope before dispatch: selection, bounded surrounding passage, or explicitly selected document. Additional documents require explicit host authorization, permission checks and bounded immutable references; no implicit workspace retrieval, URL fetching or tool execution. Treat document text and model output as untrusted data. Apply normal safe-import/schema/link rules to supported formatted responses; scripts, tools and unknown executable payloads cannot execute.

Before enabling background completion, the host configures a hard request cap, input/output/time bounds and quota admission. Reject missing or exhausted limits before dispatch. Regenerate and retry are new requests subject to the same limits. Cancel superseded work; cancellation may not reverse provider billing, so no replacement request can bypass admission. Report request usage separately from cost; unknown monetary usage remains unknown. No document context, prompt or unaccepted answer enters document updates or telemetry by default. Respect protected-document host policy and deny remote transmission when authorization is absent.

## Proposal lifecycle and collaborative edits

Capture document/session epoch, stable anchors, base revision, operation generation and relevant context before dispatch. Stream into bounded ephemeral preview state; chunks never become committed document text. Handle partial responses, duplicate/out-of-order chunks, timeout, disconnect, malformed/oversized output, empty completion and cancellation. Failure leaves the document/history unchanged and may retain bounded recovery text for an explicit copy action.

On acceptance, recheck host permission, read-only state, target anchors and the context revision relevant to the operation. Unrelated remote changes may rebase through existing anchor rules; changed target text, deleted anchors or changed generation context require refresh/review or a stale outcome. Never redirect a late result to the current caret, another document or document end. Apply a validated proposal exactly once through existing semantic prepare/commit and one intentional undo group; undo preserves unrelated remote edits. Accept/reject/stop are always available; regenerate requires a new admitted request. Disposal, document switch and read-only transition invalidate pending acceptance and release resources.

## Completion and accessible presenters

Suspend autocomplete during IME/marked text, dictation composition, active pointer selection, noncollapsed selections and excluded block contexts such as code or protected atoms unless the host explicitly enables a qualified profile. Invalidate on local edits, caret moves, relevant remote changes, blur, permission loss and disposal. Do not intercept typing or navigation when there is no applicable suggestion. Tab accepts only a visible applicable suggestion under a configurable keymap that preserves indent/table navigation; Escape dismisses it. Mobile, native and screen-reader users have visible Accept/Dismiss commands without relying on Tab.

Ghost text does not participate in document offsets, selection, copying, export, CRDT updates or undo until accepted. Announce availability and meaningful status without reading every streamed token. Panels retain the captured editing selection while focus moves to prompts or review; focus restoration cannot override a later user focus change. Keyboard, touch, RTL, Unicode, contrast and reduced-motion behavior use existing platform contracts.

## Qualification and packaging

Automated validation uses prepared responses, deterministic chunks and mocked provider transports only. No paid inference, ambient credentials, `.secrets`, live subscription proxies or automatic fixture recording. This roadmap authorizes no live-content dogfood. Any later dogfood is a separate manual workflow requiring exact real-content scope, a user-approved hard request/monetary cap and stop condition, and the Assign workspace's paid-inference testing policy read before any call.

Assert content, selection, history, focus, status, request counts and unchanged state on rejection. Cover stale targets, remote edits, Unicode, composition, budget exhaustion, unsafe output, late/duplicate results, accept/undo/redo, disable/re-enable and teardown. Prepared responses qualify integration behavior only; they prove no model quality, real usage, settlement or launch readiness.

Publish a versioned optional AI profile through existing package boundaries with exact commands, host requirements, keymap precedence and supported platform subsets. Qualify actual keyboard/touch/accessibility behavior independently using a mock backend. Measure enabled and disabled bundle/resource contributions and high-risk combinations with tables, links, protected content and collaboration. Minimal consumers make no provider requests and load no AI assets. Documentation records pending/unsupported capabilities accurately; no all-platform support claim follows from web fixtures.
