# Everyday editing behavior

Device sequencing (superseding user decision, 2026-10-18): every device/target-runtime/OS-input/AT observation in this document is owned by [final roadmap43](../roadmaps/43-physical-device-verification.md) under the [web feature-first policy](../operations/web-feature-first-20261018.md). Feature implementation keeps focused deterministic correctness/data-safety checks; device rows and D observations run later on accepted simulators/emulators/VMs/OS hosts without waiting for physical hardware. Preserve original case IDs and criteria; deferred observations remain unchecked and do not block web feature completeness. Exhaustive qualification/performance follows the stated later phase.

Status: development contract; behavior is unimplemented until the owning task and its evidence pass.
Scope: the default rich editor, with explicit code, list, table and literal-text contexts. Hosts may publish named keyboard profiles; silent platform-dependent content semantics are unsupported.

The [research](../evidence/editor-interaction-research.md) records primary documentation and historical regressions. The [case catalog](../tests/editor-interaction-cases.md) supplies stable IDs and expected outcomes. [Track 38](../roadmaps/38-editor-interactions.md) owns implementation and regression qualification after the baseline tracks; it is a browser release prerequisite. Existing engine, browser and format contracts remain authoritative for schema, transactions, event reconciliation and parsing. If a behavior needs an unqualified primitive, record the engine/schema dependency and qualify it before implementing that behavior; a DOM-only workaround cannot satisfy it.

## State and command ownership

The [baseline browser guarantees](web.md#baseline-typing-and-rendering-guarantees)
already own basic whitespace presentation and heading-end Enter before a list.
This contract adds the broader variants and qualification layers; a failing basic
case is repaired and verified in baseline work as soon as it is found.

Rust owns text, marks, blocks, structural changes and semantic undo. Browser/native controls own temporary composition, layout-dependent caret movement and OS input integration. Public offsets remain UTF-16; user-facing character deletion uses qualified grapheme boundaries. An edit includes its resulting selection: assert anchor, focus, direction and affinity as well as content. Cursor movement alone produces no content/history/persistence update.

One user intent commits once, regardless of whether it arrives as keydown, beforeinput, input, composition or an observer notification. Route keyboard, toolbar, menu, touch and assistive actions to the same applicability-checked command. Consume an event only when the editor handles it; preserve platform shortcuts, AltGraph, dead keys and composing Enter. Resolve conflicts in order: active composition/OS input, active popup, context-specific command, editor command, native navigation/focus. Read-only policy applies at the command boundary as well as the UI.

Expanded selections use stable endpoints, including backward selections. A toolbar must capture selection before focus moves, revalidate it at activation, and return focus predictably. Asynchronous actions carry session identity, cancellation and relative anchors; a deleted target returns a recoverable result. Never redirect an old action to the current caret.

## Enter and line breaks

| Context | Enter | Shift+Enter |
|---|---|---|
| Paragraph | Split at selection into sibling paragraphs; caret at new start | Insert a semantic hard break inside the same block |
| Heading | Split in the middle retaining heading level; at the end create a paragraph; an empty heading becomes a paragraph | Hard break inside the heading |
| Nonempty list item | Split item and continue list; new task item is unchecked | Hard break inside the item's text, without creating another item |
| Empty list item | Outdent one level; at outer level exit to paragraph | Insert an in-item hard break |
| Quote | Split a nonempty quoted paragraph; empty final quoted paragraph exits one quote level | Hard break in the quoted paragraph |
| Code block | Insert literal LF; do not create another block | Insert literal LF |
| Table cell | Insert an in-cell hard break; do not split the table | Insert an in-cell hard break |

Selected text is replaced before the above action in the same transaction. A cross-block replacement retains unselected prefixes/suffixes under the engine's prepared structural policy. A hard break is distinct from a new paragraph and a Markdown source soft break; its wire/storage representation must pass schema admission and round-trip tests. Repeated/trailing hard breaks and the caret after the last break must survive rendering, copy, export and restore. Renderer filler nodes are never document content. Portable marks continue across a hard break where applicable; inline code is literal and link-boundary behavior follows the formatting policy below.

## Formatting and alternative representations

Selected formatting transforms exactly the selected semantic text, including backward and multi-block ranges; it preserves selection direction, unrelated marks and surrounding content. Applying a toggle to a mixed selection applies the mark uniformly; toggling a uniformly marked range removes it. Toolbar state is on/off/mixed/disabled rather than inferred from a single DOM ancestor.

A collapsed mark toggle changes local pending typing marks without inserting empty spans or a document/history transaction. Moving to another selection recomputes pending marks; typing applies them once. Bold/italic/strike survive hard breaks and remain pending for immediate typing after ordinary Enter where the destination permits them. An empty destination does not persist these pending marks as content: moving away and returning recomputes marks from that destination. Structural splits filter inherited pending marks by the destination block's allowed marks. At the end of a link, ordinary continued typing defaults outside the link; typing inside a link retains it. Inline code suppresses Markdown shortcuts and incompatible marks. Clear-formatting removes supported presentational inline marks, preserves text and links, and leaves block kind unchanged; removing a link is a separate command. Unsupported/custom marks are preserved unless the named command explicitly targets them.

Formatting actions, including links, colors and future underline/highlight/subscript/superscript, must declare schema capability, applicability, serialization and fallback. Disabled features are not approximated with Unicode lookalikes. Grammar-equivalent CommonMark spellings (eligible emphasis delimiters, backtick/tilde block fences, ATX/setext headings at supported levels, and equivalent list delimiters) import to equivalent supported semantics; inline code and fenced code blocks remain different structures; serialization may use canonical spelling. Underline, color and other non-Markdown semantics require a documented preservation format or an explicit loss diagnostic. Locale casing, Unicode normalization, smart punctuation and emoji substitution are not implicit formatting.

## Deletion, navigation and tabs

Backspace/Delete remove the selection or one qualified user-perceived character backward/forward. Cover combining sequences, variation selectors, emoji modifiers, ZWJ families, flags, CRLF import and Indic clusters. No operation leaves a half surrogate. Word/line deletion uses the platform profile; do not implement it as repeated UTF-16 deletion. At a block boundary, structural join/outdent/exit follows applicability and preserves marks; at the document boundary it is a no-op. A noneditable atom adjacent to a collapsed caret is selected first, then deleted on the next deletion; a selection already containing it deletes it once. Unsupported joins reject without partial mutation. Static checklist markers and view decorations are not content atoms or deletion targets. Supported block content atoms use the existing atomic-content command with the exact descriptor and a final `selectionAt` in the same prepared batch. Removal leaves its core-defined empty paragraph; the returned semantic selection places the caret and supplies the redo bookmark. Semantic history bookmarks at the atom owner restore a node selection when undo makes that noneditable presenter visible again. Module text controls retain their own editing ownership.

The prepared `deleteGraphemeAt` command accepts an owner, UTF-16 offset and backward flag. It reuses the core extended-grapheme helper on staged content, rejects interior/invalid cuts atomically, and returns the resulting caret. A document-edge range is empty and creates no history. Browser character deletion uses this command; word/line deletion maps the browser profile's supplied range into one prepared range edit rather than repeating character commands.

Retain native visual navigation when it is correct: arrows, Shift+arrows, Home/End, PageUp/PageDown, platform word/line/document modifiers, Select All and selection collapse. Test wrapped lines, vertical movement's preferred x position, RTL/bidi visual order, empty blocks, atoms and scroll-to-caret. Logical storage order does not define visual left/right. Keyboard shortcuts use semantic keys and platform conventions, not US physical-key assumptions. Browser find, zoom, navigation and OS/screen-reader commands remain available. Escape closes the highest active editor popup, then returns to ordinary editing without deleting text.

Tab in ordinary prose moves focus; Shift+Tab moves backward. Lists indent/outdent only when a structural action is applicable. Code Tab inserts one literal tab at a collapsed caret; a selection indents touched lines by one tab and Shift+Tab removes at most one leading tab or the configured indentation width (the baseline profile removes up to four spaces). Existing whitespace is preserved. Table Tab/Shift+Tab moves among cells; forward Tab at the final editable cell creates one bounded row if allowed, otherwise exits; Shift+Tab at the first cell exits. Code/list/table profiles expose visible keyboard help and a one-shot focus escape: Escape dismisses the active editor popup if present and arms the next Tab/Shift+Tab to leave the editor forward/backward. Any other edit/navigation clears that escape state. IME-owned Escape is not intercepted. No exit route requires a mouse. Switching focus or opening menus must not strand composition.

The default shortcut profile uses `Primary` = Command on macOS and Control on Windows/Linux. Bind only while the relevant editor control owns focus and an applicable command exists; hosts may remap explicitly and expose the mapping in keyboard help.

| Keys/action | Required dispatch |
|---|---|
| Primary+B / Primary+I / Primary+K | Bold, italic and link editor using captured semantic selection |
| Primary+Z / Primary+Shift+Z; Windows Control+Y | Semantic undo/redo; deduplicate browser history input events |
| Primary+A / C / X / V | Scoped Select All and native clipboard operations with the declared import policy |
| Platform plain-text paste shortcut | Same operation as visible Paste as plain text; unsupported shortcut still has command access |
| Primary+U and other optional formatting bindings | Consume only when the registered formatting capability and profile support that binding; expose disabled reason through controls |
| Primary+Enter, Escape and host submit bindings | A host explicitly configures submit behavior; ordinary Enter never implicitly submits. IME/popup ownership is resolved first |

Qualify macOS Option+arrows/Backspace (word), Command+Left/Right/Up/Down (line/document), and Windows/Linux Control+arrows/Backspace, Home/End and Control+Home/End under each platform's actual profile. Shift extends the corresponding range. Platform/screen-reader remapping takes precedence over an assumed universal key table.

## Input, whitespace and Unicode

Use observed input events and target ranges, not the assumption that all edits produce keydown. Reconcile noncancelable/missing beforeinput through input/DOM fallback. Dictation, autocorrection, spelling replacement, handwriting and virtual keyboards may insert or replace arbitrary ranges. Do not invent an `insertFromDictation` inputType or infer microphone state from text events. Defer composing/commit Enter to the OS/IME before editor split/menu actions. Account for observed sequences where compositionend occurs before the final Enter or isComposing is already false; use the qualified composition-session state and narrowly bounded event correlation, not a blanket time-based swallowing of the next deliberate Enter. The desired intermediate composition model is temporary; commit/cancel/undo policy must be fixed in the qualified input ADR before adapter implementation. The ADR is a required development output, not assumed existing evidence; any platform exception updates its fixtures and acceptance together.

Preserve typed leading/trailing/repeated U+0020 spaces, tabs, NBSP, narrow NBSP and user-supplied zero-width/bidi characters. Layout filler spaces and placeholder breaks must be distinguishable from authored content. Literal import normalizes CRLF/CR to LF once; it does not trim, collapse whitespace, normalize Unicode, expand tabs or apply Markdown. Preserve precomposed and decomposed text byte/code-point distinctions where the format permits. Offer optional visible-invisibles diagnostics without rewriting the content. Reject malformed encoding or unsupported controls using explicit diagnostics; preserve recoverable source. Keyboard modifier handling must allow Hungarian accented letters, AltGraph punctuation, dead keys and non-Latin layouts.

The portable web input profile admits TAB, CR and LF and rejects other C0/C1 controls (including DEL), plus unpaired UTF-16 surrogates, before passing strings through JSON/WASM or HTML tokenization. Diagnostics identify the UTF-16 offset and retain recoverable input. Literal paste converts CRLF/CR to LF once. The renderer's opt-in `setInvisibleCharacters` shows a bounded native tooltip listing invisible code points and UTF-16 offsets; it adds no text nodes or document/history changes. Clipboard HTML declares whitespace-preserving presentation, while internal fragments and plain text retain the exact characters.

## Slash commands

Open only from a local, noncomposing typed slash at a valid text boundary (start of block or after whitespace), with a collapsed selection and no literal/code/link-target context. A URL/path slash, escaped slash, pasted slash, imported content and remote updates do not auto-open it. Preserve the literal query until a command actually succeeds.

Arrow Up/Down moves among enabled results; Home/End moves to first/last result while the popup owns those keys. Enter commits exactly once; Shift+Enter closes the popup and inserts a same-block hard break. Tab dismisses and follows normal focus/context policy; it does not silently accept a suggestion. Escape dismisses with query intact and does not immediately reopen. Backspace filters the query and deleting the trigger closes it. Enter with no results or all-disabled results is consumed by the active popup without mutation; it must not fall through to paragraph splitting. Pointer and keyboard selection execute the same command and restore its resulting caret.

Use an anchored trigger/query range, cancel outdated lookups, and recheck the current query/session before accepting a response. Caret movement outside the range, incompatible selection, read-only transition, focus leaving the editor/popup composite and destruction dismiss the popup. Internal pointerdown → editor blur → item activation and assistive focus transitions must preserve the anchored command until activation or explicit cancellation; do not cancel an item click merely because the editor blurred. Only a successful command replaces its own trigger/query range in one undo group. Async errors preserve the user's query. The presenter must name its control, expose active/disabled result state and announce bounded result changes; choose the appropriate listbox/combobox or menu pattern and qualify it with actual assistive technology rather than mixing incompatible ARIA roles.

## Clipboard and parsing

Keep the precedence and explicit host Markdown-paste policy in [formats.md](formats.md). Paste-as-plain-text is a discoverable command usable without a platform-specific shortcut. Capture data/range once and commit once; permission denial, cancellation, parse failure and stale anchors preserve the original document. Cut modifies content only after a successful clipboard operation under the supported browser path. Cross-block cut/paste restores text, supported marks, breaks and selection with one undo.

Fixtures include same-editor fragments; unsupported/malformed fragments; HTML from Word/Google Docs/Apple Notes; plain text from terminals/PDF extraction; Markdown; TSV tables; URL/email punctuation; code; and nested lists. Store sanitized synthetic payloads with provenance, never private clipboard captures. Compare semantic fidelity and explicit fallback, not proprietary source markup. Multi-line literal paste maps LF to hard breaks within a text block and to LF in code; table-cell literal paste stays in the captured target cell. Enter and Shift+Enter both insert LF in an editable table cell through the existing prepared table command. The explicit literal cell paste action normalizes external CRLF/CR to LF before preparation; tabs remain literal. Shared descriptors reject CR and malformed UTF-16, and retain table version, surrounding cells, marks, one semantic history unit and exact persistence/source recovery as specified in [formats.md](formats.md). Formatted/Markdown import determines paragraph/list structure through the parser. Inline-code paste retains literal characters and uses the schema's declared multiline fallback with a diagnostic if multiline code spans cannot be represented.

Typing shortcuts are a finite local rule set with exact triggers and context exclusions. Slash auto-open and typing rules require positively identified eligible direct typing from a qualified event sequence. Input with ambiguous provenance, including identical insertText without a correlated eligible typing/composition-commit policy, remains literal; visible commands stay available on keyboards/platforms that cannot safely establish eligibility. Never infer dictation identity from a fabricated source flag. They prepare the final semantics of eligible local text atomically, never during IME, paste, dictation/replacement or remote replay. Escape, literal mode and code contexts preserve delimiter text. Backspace immediately after an automatic conversion reverses that conversion according to a recorded input-rule history boundary; normal undo then reverses the preceding typing. Partial syntax, unmatched delimiters and invalid links remain literal. Rules and paste parsing have separate switches.

## Acceptance and extension boundary

The case catalog is a minimum regression set, not a claim to enumerate every browser/OS interaction. Each case asserts document state, caret/selection, history behavior and emitted mutation count; rejected/canceled/navigation actions assert zero mutations. Pair high-risk cases with read-only, remote edits, empty/end positions and undo. Record exact engine/browser/OS/locale and fixture revisions. Preserve failures and explicit unsupported cases.

Baseline keyboard access, screen-reader editing and native dictation belong to the editor with no extension enabled. The [assistive-input extension](assistive-input.md) adds host-controlled status, discoverable commands and optional assistance UI; it cannot repair missing baseline semantics by maintaining another text model. Real OS/screen-reader/voice checks qualify support separately from deterministic event replays. [Track 39](../roadmaps/39-assistive-input.md) owns optional extension integration and its evidence.

## Desktop selection and text transfer

The [desktop research](../evidence/desktop-editing-research.md) and [additional cases](../tests/desktop-editing-cases.md) extend the existing contract. Selection followed by Enter was already required by BRK-04; qualify it across forward/backward ranges, marks, whole-document selection, multiple blocks, empty boundaries and supported code/list/table contexts. The complete replacement plus split/break is prepared before mutation. An incompatible cross-structure replacement rejects without first deleting its selection. Page breaks, section breaks and paginated layout are not inferred from paragraph/hard-break input types.

Pointer selection preserves native single-click caret placement, Shift-click extension, double-click word selection, supported paragraph/line gestures and word-drag extension under a named OS profile. Do not impose one triple-click convention on every platform. A press inside an existing selection may begin text dragging; do not collapse the range before drag threshold arbitration. A click without a drag follows the platform collapse policy. A context-menu gesture inside a selection retains its target; outside selection follows the documented platform policy. Menus capture stable semantic targets and restore focus only if the originating editor still owns the interaction. Selection autoscroll stops on pointer cancel, lost capture, blur or disposal; geometry respects nested scroll containers, zoom, transforms, bidi and virtualization. Offscreen selection content must not be clipped to mounted DOM nodes.

Text transfer is distinct from block-handle reordering. Within one document, a move prepares source removal, destination insertion and resulting selection as one semantic transaction and one undo group; a copy inserts once and retains the source. Map the drop position through source removal. For `ab[CD]ef`, moving before `a` yields `CDabef`, moving after `f` yields `abefCD`; a move to the source range or either boundary is a no-op. Preserve supported marks, breaks, atom identity rules and unselected content. Select the inserted fragment after a successful desktop drag; native presenters may expose their documented platform selection policy, asserted explicitly in receipts. An incompatible destination rejects the entire operation.

Capture document/session identity, source anchors, source revision or content identity, and allowed effects at drag start. Resolve the actual destination and current copy/move modifier at drop. Revalidate source and destination, edit permission and allowed schema before committing. An unrelated remote edit may remap stable anchors; a changed/deleted source, ambiguous target or permission loss cancels with recoverable feedback. Do not delete the current selection on dragend. A canceled drag, Escape, unsupported payload, outside drop or stale async decode leaves source content intact. Temporary indicators and canceled gestures create no history, persistence or collaboration updates. Correlate drop, insertFromDrop, deleteByDrag and observer notifications as one intent; their availability/order must be qualified per browser, never assumed from the standard alone.

The browser uses the same prepared fragment-transfer primitive as the native owner. `fragmentTransfer` takes retained source/destination ranges and an explicit copy effect, validates the complete operation before mutation, and returns the inserted selection. The adapter captures the existing lossless clipboard representation and revalidates it before final preparation. A per-gesture nonce correlates only an active drag in the same engine object; matching document IDs or serialized fragments never authorize deletion. `captureTextTransfer().dropAtSelection(copy)` exposes the same operation for keyboard-accessible host controls; the destination must be an explicit collapsed selection. Capture and destination execution happen while the respective editor owns its selection, before moving focus to a native control. Cancellation releases the captured target. A prose fragment cannot replace a code destination’s presentation; incompatible code targets reject before source removal. Complete selected separator removal is staged with the existing atom admission, while ordinary structural Join remains unchanged.

Multiple views of one editor session share one document transaction and one semantic history owner while retaining view-local selection. Undo from either focused view consumes that shared entry once; another view cannot independently undo the same transfer again. Independent sessions/replicas of the same document retain their existing origin-scoped collaborative history and require the transfer contract for their actual session relationship; matching document IDs alone do not establish a shared transaction. Cross-document and external transfers default to copy. A host may advertise cross-document move only with a qualified destination receipt, source identity/permission revalidation and explicit per-document recovery/undo policy; an OS dropEffect alone is not a durable receipt. Destination failure cannot delete the source. Source-delete failure after destination success preserves both copies and reports the incomplete move. Never claim cross-document atomicity or shared undo that the stores do not provide. Outbound external transfers offer only effects whose source-deletion contract is qualified; do not silently delete on a foreign acknowledgement. External HTML/text/file drops use existing import, authority and size limits; a forged internal fragment type conveys no trusted session or schema authority.

Expose Cut/Copy/Paste and keyboard-accessible move alternatives for users who cannot drag. Preserve native touch text selection and system drag where supported; block handles cannot steal selected-text gestures. Drag previews, autoscroll and hit testing belong to adapters; the engine owns the prepared content operation, never pointer coordinates or platform modifier policy.

## Native command surfaces and optional editing tools

Apply the [platform editing contract](platform-editing-services.md) and [ENV variants](../tests/platform-editing-cases.md): spelling prefers platform/user defaults with off/custom modes and independent autocorrection. Preserve platform IME/dictation, clipboard, selection and accessibility facilities through the existing input/command owners. Cmd/Ctrl+Z, declared redo keys, browser history events and native menus/gestures must each reach the same semantic history exactly once; duplicate key/input paths and native projection updates cannot create a second history. Respect composition and nested-control ownership.

Route keyboard shortcuts, platform Edit menus, context menus, accessibility actions and toolbar controls through the same focused-editor command applicability checks. Native spell/correction/reconversion replacements use their reported target range, which may differ from the visible selection; they never fall back to the latest caret. Find fields, table widgets, embedded code controls and host inputs own their commands while focused. Focus changes, popup closure and canceled dialogs must not retarget delayed work. Preserve browser/OS Find unless the host explicitly enables and exposes the first-party document-search profile.

The portable browser command catalog supplies canonical names, labels, aliases and default chords to the existing keyboard/formatting/history adapters. `BrowserEditor` and host-owned surfaces expose the same `commands` and `captureCommand(name, suppliedRange?)` ports. Hosts capture before a menu or toolbar takes focus, activate synchronously, and dispose on dismissal. A captured command owns copies of its semantic anchors, rejects a changed revision or intervening editable-control focus, rechecks read-only/composition and command permission at activation, and executes at most once. `replace` requires explicit supplied text and never substitutes a newer caret for invalid supplied anchors. CLI/agent hosts may invoke this semantic port; queued UI delivery alone is not an execution receipt. This API does not qualify a CLI process or native UI transport.

Portable shortcut profiles may reserve canonical chords or remap them to catalog names/aliases; host/OS ownership wins over editor bindings. The catalog remains available for labeled menu/toolbar alternatives when a chord is unavailable. Find-field Enter navigates search results while retaining field focus; later Select All, undo and cut still belong to that field. Native menus, OS replacement ranges, non-US layouts and assistive-technology remaps require their separate observations and remain unqualified by deterministic profiles.

The optional first-party search and code-command contracts live in [rich content](rich-content-extensions.md). They reuse engine preparation/history and public selection APIs. Multi-cursor/discontiguous editing, rectangular text selection, overwrite mode, application-wide search, macros, track changes and paginated page/section layout are capability decisions, not implied support from an IDE/Word comparison. Their controls/shortcuts remain absent or explicitly unsupported until their own semantics, serialization and platform evidence are qualified. No extra semantic model or general plugin event framework is needed for the scoped additions.

## Changed-field formatting surfaces

[WCF-19](../tests/wordcraft-regression-cases.md) refines INT-1.3 for existing/claimed formatting surfaces; it does not require a new Word-style property dialog.
