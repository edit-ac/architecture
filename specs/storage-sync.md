# Storage and synchronization contract

Device sequencing (superseding user decision, 2026-10-18): every device/target-runtime/OS-input/AT observation in this document is owned by [final roadmap43](../roadmaps/43-physical-device-verification.md) under the [web feature-first policy](../operations/web-feature-first-20261018.md). Feature implementation keeps focused deterministic correctness/data-safety checks; device rows and D observations run later on accepted simulators/emulators/VMs/OS hosts without waiting for physical hardware. Preserve original case IDs and criteria; deferred observations remain unchecked and do not block web feature completeness. Exhaustive qualification/performance follows the stated later phase.

The engine emits immutable update bytes and document/epoch/schema/origin metadata. Browser and native CLI storage/transport adapters consume these independently. Baseline versions and wire layout are frozen by the foundation protocol task, using the [engine contract](engine.md). The [CLI contract](cli.md) defines filesystem durability, Markdown working buffers and hosted target resolution; browser-specific storage mechanisms are not native filesystem guarantees.

## Local durability

Journal key: document ID, epoch, writer ID and monotonic per-writer sequence. Store immutable update bytes, checksum, schema version and pending receipt identity. Generate distinct live CRDT client IDs and writer IDs for simultaneous tabs. Restoring document bytes never restores a shared active client identity.

`localCommitted(updateId)` means the transaction containing that update completed. Queueing, creating a request and scheduling a timer are insufficient. Request strict durability where supported and report actual capability. The guarantee covers tested process crashes; browser eviction, user deletion and arbitrary hardware/power failures remain outside it. No unload-handler dependency.

A checkpoint consists of CRDT state, coverage metadata and hash. Publish checkpoint/coverage atomically. Keep the previous valid point and a recoverable tail until replacement is safely published. A checkpoint may cover unacknowledged local updates, but the outbox must still retain their identities and retransmittable bytes. JSON export is never used as a checkpoint that silently changes CRDT identity.

`flush({target:'local'})` captures the pending set and resolves once all those updates complete storage; later updates need not extend the barrier. A failed transaction rejects the barrier, clears saved status and exposes a recoverable error. Keep in-memory state/export available. Destroy policy explicitly flushes or reports unsaved state; destruction must not imply saving. Explicit host recovery via `flush({target:'local', retryFailed:true})` retries only failed updates in that captured set, once per call, using their original identity/origin/bytes through the same journal. Concurrent callers share an in-flight attempt. No automatic/background retry is introduced. A repeated denial still rejects and retains recovery; successful completion clears the recovered error and reports saved only when no retained writes remain without changing the live replica or history. Ordinary flush continues reporting retained failures until explicit recovery.

Use deterministic failure injection before/after each write/transaction/publication boundary, plus actual browser process termination after acknowledgment. Test two tab writers, duplicate/reordered replay, corrupt latest checkpoint, quota/permission rejection, schema mismatch and missing document identity. Preserve failures in evidence.

Prepared-media insertion uses the same update journal and checksum/receipt identity. The browser atomically compares/replaces the AssetJournal and appends the exact Rust prepared update in one transaction across `assets` and `updates`, before any live content/history mutation. Semantic admission stays reserved until completion or abort. A crash after durable completion but before live application recovers through ordinary checkpoint/tail replay, without host work. Existing storage failure policy still applies, and unresolved cleanup failure reports both the insertion and fence errors with recoverable originals retained. Durable receipt matching includes identity, writer, sequence, origin and exact bytes so reentrant observer edits cannot inherit another update's acknowledgment. See [prepared originals](rich-content-extensions.md#prepared-import-originals) for the shared ownership and cancellation contract.

## Bounded recovery failure work

[WCF-01](../tests/wordcraft-regression-cases.md) extends LOC-1.6 and the shared CAP-1.5 lifecycle. Retain the last valid checkpoint, recoverable journal tail and outbox after rejected recovery work. A stable permanent rejection (input/profile/resource condition) suppresses unchanged expensive serialization/write retries; a changed eligible input or repaired condition permits retry. Transient quota/I/O failures use bounded backoff and an actionable state, not a timer-driven write storm. Measure attempts and bytes through the existing storage port. Do not replace CRDT checkpoints with JSON or clear unsaved state on failed persistence.

## Network

Transport is optional and attaches to the existing engine. It must not reinitialize the document, import a second snapshot or replace selection/history on connection. Use transaction origins to avoid echo. Define bounded receive/send queues, frame sizes, retry/backoff and reconnection behavior. Defer unauthorized uploads but retain recoverable local edits.

The [composable collaboration facade](extension-dx.md#optional-collaboration-per-editor) preserves this port contract. Enabling sync for one mounted editor cannot create providers, retry/awareness work or authority for another. Local input/persistence/history and readiness work without a provider. Transport and presence are independent capabilities; detach/dispose invalidates late callbacks while preserving local recovery and unsent edits. Lazy orchestration must retain legacy attachment compatibility and the same immutable update/schema/receipt contracts. SDK-1.11/1.12 and FIT-1.11 own these new facade requirements; historical sync receipts do not establish facade loading or overhead.

Profile four independently versioned contracts: v1 update bytes, baseline sync messages, awareness messages, and edit.ac document schema. The pinned JS fixture operates on the same schema. A Yrs handle is not a JS `Y.Doc`; use a direct wire adapter or an explicitly tested provider adapter. Yjs compatibility does not imply Tiptap/ProseMirror schema compatibility.

Awareness is ephemeral, expiring and throttled. It cannot advance document durability. Relative peer selections resolve against current state and fail safely when targets disappear. Presence remains optional and is never journaled as document state.

### Optional awareness bridge

The internal browser adapter uses the pinned `y-protocols` 1.0.7 awareness payload: varuint entry count, then client ID, monotonic clock and UTF-8 JSON state per entry. Host routing separates these payloads from baseline sync frames and authenticates participant identities; client IDs alone are not authorization. Supported state is `null` (leave) or `{selection: null | {anchor, focus}}`. Each portable anchor contains `version: 1`, complete immutable document metadata, `source`, `sourceIdentity`, and the Yrs/Yjs JSON relative `position` (`item`, `type` or `tname` plus `assoc`). JS may include the owning type alongside an item; admission validates its shape and normalizes to the authoritative item for the Yrs bridge. The original source identity and resolved branch remain mandatory. Local engine tokens never cross the wire. Read-only export/import validates lineage, original shared source, relative branch, UTF-16 boundary and current semantic owner before retaining a local token. Unknown/deleted/unresolved cursors fail safely; a retained cursor whose target later disappears renders no selection.

Awareness is optional and host-driven: no adapter timers, document subscriptions or storage access. Defaults are 64 peers including retained expiry tombstones, 64 KiB frames, one send attempt per 50 ms, 30-second expiry and renewal at half expiry. Host calls flush/expiry with monotonic time only while presence is enabled. Local bursts coalesce into one pending state; backpressure retains that state. Expiry/leave/replacement/disposal releases imported anchors; tombstones retain clocks to reject old duplicate resurrection and count against bounded capacity. A new adapter starts a new host-authorized presence session. Admission validates the entire payload before changing peer state. Presence never becomes an update, journal entry, receipt, history operation or durability acknowledgment.

## Durable receipts

`remoteCommitted(updateId)` requires an explicit negotiated application receipt, emitted after the service's durable storage commit. A synced event, state vector or socket delivery does not meet this contract. Receipt identity includes document, epoch, writer/sequence and content identity; wrong identity cannot prune the outbox. Receipt capability absence means remote durability is unknown.

The local reference service is integration infrastructure: loopback by default, prepared auth fixtures, transactional storage, duplicate handling and restart recovery. Do not deploy it as a production service by implication. Host/service is responsible for authentication, authorization, rate limits and retention. Revocation leaves local work exportable and does not erase it.

Remote schema/epoch mismatch returns an explicit incompatibility state. Migrations use a declared new epoch and session transition; old offline updates cannot be silently applied after a rewrite. Checkpoint compaction retains reconnect identity according to the pinned protocol.

## Additional clients and protected profiles

[Client contracts](client-contracts.md) extend these ports to native/CLI sessions and explicit cross-tab/process delivery; sharing storage alone is not live synchronization. [Security profiles](security-encryption.md) can wrap local storage and transport while preserving acknowledgment identity. Ciphertext receipts certify stored bytes, not plaintext schema validation or endpoint authorization. Agent requests add durable request/result deduplication in the host/session boundary.
