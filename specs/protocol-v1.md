# Protocol profile v1

Status: frozen foundation admission contract; production transport, persistence and structural cross-language qualification remain separate gates.

## Exact profile and metadata

Profile ID `editac.yrs-yjs.v1`; schema `editac.registry.v1`; protocol version integer `1`; update encoding integer `1`; offsets string `utf16`. Qualified dependency candidates are exactly Yrs `0.28.0` with `small-client` and explicit `OffsetKind::Utf16`, Yjs `13.6.33`, y-protocols `1.0.7`. Rust/compiler and rustdoc are `1.97.1`; deterministic JS runtime is Node `24.19.0`. Update v2 or upgraded libraries require a new qualified profile, not optimistic acceptance. The dependency pair's existing XML/text interoperability is verified; structural qualification remains FND-1.12.

Document metadata is an immutable external envelope, stored alongside checkpoint/journal bytes, not additional CRDT roots: `{profile, schema, protocolVersion, updateEncoding, offsets, documentId, epoch}`. `documentId` and `epoch` are lowercase canonical UUID strings; assign independently when creating a new document. They identify logical document and lineage, never a Yrs/Yjs writer. The fixture uses fixed UUIDs. Neither identifier changes during restore, offline merge, or ordinary edits. JSON/Markdown import, explicit destructive reset or migration to incompatible schema creates a new epoch (and import creates a new document identity). Preserve the old lineage as recovery; never mix epochs by applying their bytes.

An update envelope additionally includes `writerId` (integer 0…4294967295), `sequence` (nonnegative JS-safe integer, monotonically increasing per writer/epoch) and opaque binary `bytes`. Duplicate/reorder tolerance comes from the CRDT; sequence supports journal/receipt bookkeeping, not a new LWW clock. State vectors and updates use v1 binary codecs; a vector is neither a durable acknowledgment nor an exact deletion-sensitive revision token. Metadata authenticity/resource limits belong to downstream admission ports. This freeze supplies no networking implementation.

## Initialization and restoration

The creator authorizes one initializer for an epoch. Initialize all roots and initial content once, publish its checkpoint and immutable metadata, then let independent writers apply that state. Never let peers independently seed the same logical text. Schema bootstrap, node IDs and seed are specified in [schema-v1.md](schema-v1.md). A fresh user document may be empty: initialize the five typed roots, with no pair until both reserved members exist.

Existing metadata is the authority for existence; empty state vector, empty visible content, no received network response, or absent root entries does not authorize initialization. Restore creates a replica with a fresh independent writer identity, requests the five root types, and applies checkpoint plus journal under restore origin. It never writes seed content again. Partial restore/missing initializer metadata is a recovery state; do not edit or seed while guessing whether the epoch already exists. Persist allocation counters with writer sessions, and never reactivate one writer ID in two tabs.

## Negotiation and unsupported inputs

Before any live mutation, exchange the complete immutable metadata. Require exact equality of profile/schema/version/encoding/offsets and the expected document/epoch. There is no fallback, highest-common-version negotiation, downconversion or automatic migration in v1. Unknown profile/schema or wrong encoding/offset/version: return `unsupported-profile`; document mismatch: `wrong-document`; epoch mismatch: `wrong-epoch`; malformed/missing metadata: `invalid-metadata`. A failed check must leave live content, history, state vector and journal unchanged. Empty-but-existing documents follow the same checks.

Keep rejected checkpoint/update bytes and their envelope in explicit recovery storage when restoring or recovering user content; never silently drop them, acknowledge them as committed, or project them as v1. Ordinary unauthorized inbound traffic may be rejected without storing unbounded attacker data. Decode and validate untrusted bytes on a disposable replica under bounded resource checks before admitting them to the live replica. Missing/invalid placements and parent references use schema-v1's retained read fallback; other malformed data or unsupported root/value/layout shapes return preserved recovery for user-owned state. The fixture admission function demonstrates metadata rejection before applying bytes; it is not a production binary validator or storage port.

Unknown node kinds and marks **within the valid v1 value shapes** are retained opaquely, with no extension download/execution. An unknown root/shared type or unsupported structural descriptor is not an extension mark: it requires explicit recovery, not a guessed schema. Offline known-profile updates remain recoverable on failed/unauthorized upload. Migrations and rollback are explicit new-epoch workflows retaining the old checkpoint; no in-place migration is qualified here.

## Origins, offsets and delivery

Origins are local transaction metadata, not encoded update fields or peer identities. Rust uses explicit origins; JS passes an origin to `doc.transact` / `Y.applyUpdate`. Normative classes are `local:<command>`, `remote`, `restore`, `initialize`. Fixture origins `fixture:edit`, `fixture:move`, `fixture:split`, `fixture:join`, `fixture:delete` map to local commands; `fixture:remote` to remote; `fixture:init`, `fixture:second-text`, `fixture:compose` to initialization. Only tracked local commands enter selective history. Remote/restore/initialize, presence and checkpoint loading are excluded. Adapter echo suppression uses the local origin class; neither network origin strings nor writer IDs grant authority.

Public offsets and run formatting lengths are UTF-16 code units, not UTF-8 bytes or scalar/grapheme counts. Prepare whole mutations and reject surrogate-interior offsets, unknown/deleted targets and invalid hierarchy before opening a live write transaction. Relative anchors identify original shared text and start/end affinity, as specified in schema-v1. No asynchronous operation retains an absolute offset as its target. Failure to resolve is explicit; it cannot redirect to document end.

Apply v1 updates idempotently, including duplicate and reordered delivery, with no projection writes. Byte receipt, Yjs `synced`, transaction completion and state-vector agreement do not prove durable persistence. `localCommitted` requires completed storage transaction; `remoteCommitted` requires an identified durable service receipt. Neither is implemented by these fixtures. FND-1.12 must qualify this exact schema/anchor mapping in both directions; FND-1.13 supplies the compiled WASM boundary. No Tiptap, arbitrary extension, production durability, performance or deployment compatibility claim follows from the freeze.
