# Independently mergeable tables

DRA-1.1 design decision, 2026-10-23. This is the chosen pre-publication target for DRA-1.2, **not implemented runtime behavior**. It replaces the whole-atom winner rule for editable tables. [Document durability](document-durability.md), [schema-v5](schema-v5.md) and [rich-content](rich-content-extensions.md) consume this descriptor. The deterministic [design fixtures](../fixtures/table-merge/cases.json) and [consumer review](../fixtures/table-merge/consumers.json) are authored inputs, not production merge evidence.

## Representation and admission boundary

Keep the current document identity, protocol 1, update encoding 1, UTF-16 offsets, document ID and epoch rules. A table remains one stable outer block owner, with immutable reference tuple `['module:editac.table', 3, {tableId, extensions}]` in `registry-block-attributes`. Here 3 distinguishes a genuinely different feature record, not another document profile. `extensions` is a bounded inert JSON object; ordinary commands cannot rewrite this reference or its unknown fields. Geometry, content, source and mutable attributes are not in the outer tuple. The fallback label is derived; it is never editable table source.

Add a fixed `Y.Map` root `registry-table-records`, containing immutable event-ID → JSON-array values defined below. Add named root `Y.Text` objects for cell blocks. A text root name is exactly `table-text/<tableId>/<rowId>/<columnId>/<blockId>`. IDs contain no slash: table `t:<writer>:<counter>`, row `r:…`, column `k:…`, block `b:…`, event `e:…`; writer/counter are canonical positive unsigned decimal u64 values. The implicit first block has blockId `base`. Cell identity is the canonical triple `<tableId>/<rowId>/<columnId>`; it is never an index or a hash. Tables, rows and columns have one immutable birth. An inserted axis belongs to exactly one table and never changes identity on reorder.

Table creation uses a fresh outer owner in one prepared transaction; it cannot concurrently reinterpret an existing paragraph owner. A named root solves concurrent creation: two peers first editing the same implicit empty intersection address the **same CRDT text**, rather than inserting competing nested `Y.Text` values under one map key. Never replace a text root, copy its string into a fresh text, or create a per-replica nested cell branch. Absent text means empty; projection must not write empty roots. Concurrent row and column insertion produces their Cartesian intersection with an implicit empty base block without a repair transaction. Initial import authors one text root per nonempty cell/block; later edits address those identities.

The ten ordinary v5 roots keep their existing meaning. This extension permits only the extra fixed record map and the validated text-root namespace; arbitrary roots/types are rejected. Table-free existing v5 documents remain admissible with no table root. All v1/v2 whole-table descriptors are retired **from production admission at DRA-1.2 cutover**, including embedded copies in semantic fragments/history; preserve their regression fixtures outside runtime. Do not select a reader by root sniffing, relabel old table bytes, or auto-adopt on open. Until cutover, the current tuple implementation remains unchanged and this descriptor is a design target.

This is an incompatible table-layout change. Discover any real table data before adoption. Opening an incompatible checkpoint returns typed `UnsupportedTableRepresentation` before live mutation, retaining the original checkpoint, journal and unacknowledged outbound updates. An explicitly reviewed offline converter may decode old bytes, allocate table/axis/block IDs in a **fresh destination epoch**, preserve text/runs/styles/header/alignment/source/unknown bytes and original recovery inputs, and compare results before adoption. No converter is authorized by this design parent. Merged geometry or a feature without an exact mapping makes conversion unavailable; preserve the original, never flatten it. There is one current table reader after cutover, not an old/new runtime switch.

## Immutable records and projection

Each event key is unique, allocated once by its author. Admission must inspect conflicting assignments as well as the projected map winner: a losing map assignment with the same event ID and different bytes is also invalid. Every array starts `[tag, tableId, lamport, ...payload]`; lamport is a positive safe JSON integer, greater than referenced birth/placement dependencies. Concurrent events are replayed in ascending `(lamport, numeric writer, numeric counter)` order from the event ID. Reuse of an ID with different bytes, invalid dependencies, cross-table references or an overflow rejects the entire staged change. No clocks are inferred from wall time. Duplicates are idempotent. Causal dependencies may arrive in a bounded restore corpus in any order; unresolved binary or semantic dependencies fail explicitly before live admission.

| Tag | Payload after the common prefix | Meaning |
| --- | --- | --- |
| `birth` | `ownerId` | Binds tableId permanently to its outer original block owner. One active table per owner. |
| `row` / `column` | `axisId, leftId|null, rightId|null` | Registers and places a new row/column. Anchors belong to this table and axis. |
| `place-row` / `place-column` | `axisId, leftId|null, rightId|null` | Moves the existing identity; never copies cell content. |
| `delete-row` / `delete-column` | `axisId` | Hides that axis and all its intersections; content/metadata remain retained. |
| `block` | `rowId, columnId, blockId, leftBlockId|null, rightBlockId|null, style` | Adds a cell block with paragraph, heading 1…6 or bounded code-language style. `base` exists implicitly as paragraph. |
| `place-block` / `delete-block` | `rowId, columnId, blockId` plus `leftBlockId|null, rightBlockId|null` for place | Retains block identity/text; deletion hides, not destroys. |
| `attribute` | `scope, key, value` | Scope is table, row ID, column ID, cell triple or cell/block address. Known fields: column alignment; cell header; block style. Other namespaced bounded JSON fields are inert and retained. |
| `source` | `basis, dialect, bytes` | Immutable original/formatted source snapshot plus exact covered semantic event IDs and text state vectors. Never an alternative writable cell model. |
| `control` | `targetEventId, enabled` | Reversible history control over a local event; cannot target a control, birth or immutable axis/block registration. |

Replay starts with births, then applies enabled placement events in total order, retaining hidden identities in the order list. For each placement remove the target from its current list, then insert immediately **before right** when right is specified, otherwise immediately **after left**, otherwise at the end. Both anchors must already have registrations, cannot be the target and need not remain adjacent after concurrent moves. A retained deleted anchor remains usable as a gap; there is no index rebasing or cycle because each axis is a flat ordered list. A later same-identity move wins its visible position; all losing moves remain inspectable. An axis birth's placement is immutable; subsequent placement events may be disabled, but undo never removes the registration. Undo of insertion authors a delete event instead (see below).

Any enabled delete hides its target, even against a concurrent move, attribute or text edit. Several independent deletes must all be disabled before visibility returns. Every text edit remains in the retained cell/block root and is reported in the hidden-content conflict inventory. Concurrent deletion of the last distinct visible rows/columns can produce a table with zero visible axes: show an explicit retained/deleted-geometry recovery state, never synthesize a row, flatten content or reseed. Local removal of the last visible axis rejects before mutation. Cell-block ordering uses the same rule within one cell: local deletion of its final visible block rejects, while concurrent deletes yielding no visible block expose `deleted-cell-content` recovery with all text retained. Clearing a cell edits its text to empty and does not delete its implicit base block. All inserts, moves, deletions and controls remain available in exact retained export/checkpoint, regardless of projection.

Attribute events use the same total order per `(scope,key)`; the last enabled event supplies the visible value. Unknown keys merge independently; earlier/conflicting values remain retained with event identity and appear in conflict/review export. A known field cannot change type via an unknown-field path. Controls themselves resolve per target by the same total order; competing control events remain retained. No projection emits a cleanup/repair transaction. Scoped content and attribute revisions are derived from relevant state; an unrelated cell change does not invalidate a captured cell range or require rebuilding every table.

Array arities above are exact. `style` is `['paragraph']`, `['heading', level]` or `['code', language]`. `scope` is exactly `['table']`, `['row', rowId]`, `['column', columnId]`, `['cell', rowId, columnId]` or `['block', rowId, columnId, blockId]`; the common tableId supplies table membership. Unknown metadata keys must be namespaced, at most 128 UTF-8 bytes, and use bounded inert JSON; reserved known keys retain their exact types. `basis` is `{events: [eventId, ...], stateVector: base64UpdateV1StateVector}` with unique events in replay order, covering the semantic snapshot before the source event itself. It records the document vector, not a fictitious independent Y.Text vector. `dialect` is an admitted external dialect identifier of at most 64 ASCII bytes; `bytes` is canonical base64 of the exact source bytes (the 1 MiB limit applies after decoding). IDs referenced in a basis must belong to the same admitted document/table state. Relative selection anchors use the engine's existing opaque anchor encoding, scoped by table/cell/block IDs. The [serialized example](../fixtures/table-merge/serialized.json) fixes one concrete spelling of every record family; convenience fixture actions are not wire DTOs.

## Text, selection, offline peers and undo

Cell blocks use the pinned Yrs/Yjs `Y.Text` UTF-16 sequence and inline formatting attributes. Concurrent insertions preserve all items; deletion removes only observed items, not unseen concurrent insertions. At one insertion gap, the pinned CRDT item ordering decides (the fixture uses writers 10 and 20, yielding `baXYse`). Formatting merges by the pinned per-item attribute rule; unrecognized bounded attributes survive unchanged. LF is literal within a block, CR is rejected by the semantic command boundary after explicit native/paste newline normalization. Block splits/joins require their own prepared mapping and are unavailable until implemented; multi-block imported cells retain their block identities without flattening.

Public cell actions carry table/row/column/block IDs, scoped revision and stable relative UTF-16 anchors. A textarea whole-value replacement is prepared as a minimal scalar-safe splice against its captured revision, not written as a new descriptor. Stale same-cell input rejects or is recaptured explicitly; it cannot erase a peer's unseen insertion. A rectangle resolves captured stable cell addresses and validates every protected target before any write. Native coordinate actions may resolve indices only during preparation; commit uses IDs and a scoped precondition. Local undo owns only local text items/format actions and local event IDs, excludes remote/restore origins, and groups the entire accepted command. Undoing one cell edit preserves unrelated peer edits, including same-cell remote items. Undoing an insert authors a reversible delete for its axis/block; undoing a delete disables only that local delete; undoing a move/attribute disables that event to expose the preceding retained state. Undo never replaces the table reference, text root or another author's event. A fresh writer lease may execute a retained local history action only through its authorized history owner; it references the old event/item IDs without reusing the old writer lease or rewriting provenance. Numeric writer equality is not a durable user identity or permission proof.

No table record or text root is garbage-collected at checkpoint or acknowledgement. A disconnected peer keeps the same table/cell identities across save/reopen and can submit updates against hidden rows/columns; their text is retained and surfaced as a conflict, not retargeted to a neighboring index. Restoration re-enables visibility without losing those updates. Outer block delete/undo likewise hides/restores this retained table. Generic Turn into, paragraph conversion and replacement of an existing table reference reject `UnsupportedTarget`; a future explicit conversion must prove a complete mapping and history/unknown-data preservation. Copying a table creates fresh destination IDs and copies content/unknown fields; moving it retains IDs. Pasting internal transfer never reuses source document identity as a live destination reference.

## Serialization, bounds and consumer acceptance

Checkpoint/update serialization is the exact CRDT records/text plus current envelope. Portable projection includes IDs, ordered visible axes/blocks, runs/styles, header/alignment, scoped revisions, retained conflict summaries and opaque metadata. Exact/internal transfer includes hidden content, losing events, unknown fields and source snapshots; it is not interchangeable with a visible runs matrix. HTML/Markdown/TSV are external representations: ordinary literal export explicitly reports lost identities/history/unknown data; lossless round trip requires a bounded typed recovery carrier preserving the exact table state. A recovery carrier is inert data, validated before activation. A standalone import creates fresh IDs; an internal same-document recovery preserves IDs only after identity/epoch validation. Pipe Markdown is exact for its supported simple visible projection only. Arbitrary header layouts, multi-block cells, dormant marks and unknown fields require the recovery carrier or a recoverable limitation; no stale source snapshot is exported as if current. Source formatting records a new snapshot only after revision-checked reconciliation; an older snapshot's original bytes remain retained.

Concrete delivery limits: at most 128 visible rows × 32 visible columns, 4096 cell intersections, 1024 visible cell blocks per table, 128 affected cells and 1 MiB UTF-8 replacement per command, 1 MiB source snapshot, 64-byte code language, existing safe URL/mark checks. Table retained JSON uses maximum depth 32, 1 MiB per value and 8 MiB aggregate per table; at most 65536 retained table events, 16384 retained text roots and 16 MiB aggregate UTF-8 cell text per table. Existing stricter document binary/graph/storage limits still apply; these are safety ceilings, not final size/latency qualification. DRA-1.4 must include these retained roots in lifetime policy; this design introduces no silent pruning or promise of unlimited storage. A prospective concurrent union beyond a limit returns typed `ResourceLimit` before mutation and leaves input/recovery bytes available; never clip rows, discard a remote event or accept partial text. Count retained/deleted CRDT structs against the existing binary budget as well as visible text against the text budget. Decode root names/types and JSON budgets before allocation/projection; validate references, all text attributes and aggregate counts on staging. Bounded work is O(events log events + retained text + cells); consumers cache per-table/cell revisions. Final resource and bundle caps are unchanged.

DRA-1.2 acceptance is the complete consumer matrix below, not just a new core type. Run `node --test tests/table-merge-design.test.mjs` from architecture for the authored design consistency check. The separate `tests/table-merge-yjs.test.mjs` probe requires the sibling core workspace's pinned Yjs install and checks only the selected named-text primitive (first-write addressing, same-gap ordering and independent roots). Neither proves the production table engine. Runtime proof must exercise both update orders, duplicate/reordered delivery, two simultaneous first writes, same-cell text/format/delete, concurrent row+column insertion, edit-versus-delete retained recovery, moves/undo, corrupt/oversized rejection, checkpoint and actual WASM/Session/internal converter round trips. `core/crates/editac-core/tests/table_concurrency.rs` owns focused production proof. QSH/QWB/native final owners retain full target-runtime qualification.

| Consumer boundary | Required result at DRA-1.2 |
| --- | --- |
| Core document, bounded decoder, replay | Admit only the chosen table representation, immutable events and validated text roots; staged rejection preserves bytes/history. |
| Core table preparation, projection, history | Edit addressed text/events; immutable outer tuple; scoped revisions/anchors; selective undo and retained conflicts. |
| Interchange, WASM bridge, Session, FFI | Same ID/revision/address DTOs and one engine owner; validate all serialized fields, no tuple reconstruction or independent table mapper. |
| Markdown/HTML/formats, clipboard, native formats | Fresh-ID import; explicit recovery/limitation policy above; exact IDs/content/unknown data preserved through declared internal round trips. |
| Web tables, Swift/Kotlin/desktop/terminal | IDs as keys, scoped patches/selection, hidden-content diagnostics and readonly preservation; geometry/cache never becomes committed state. |
