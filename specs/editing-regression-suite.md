## Prevention boundaries

| Guard | Required boundary | Falsifying test |
|---|---|---|
| G01 Intent correlation | Each observed input intent has editor/document epoch, input/composition session, origin and a terminal disposition. keydown/beforeinput/input/observer notifications may refer to one intent; identical text alone is never its identity | Replay duplicate notifications, then a deliberate identical second insertion; one commit for each real intent |
| G02 Compound preparation | Selected Enter, marked typing, cross-block replacement, rich paste and input-rule transforms prepare and validate all text/marks/structure before one engine mutation | Reject the final sub-operation; content, state vector/revision, history, publication and journal enqueue remain unchanged |
| G03 Resulting selection | A prepared action supplies a stable semantic selection result/policy, including direction and affinity; distinguish text ranges, node/cell selections and before/after-node insertion anchors. Browser geometry stays in the adapter. Resolve against the committed state | Assert exact range and next typed sentinel after split/format/paste, including backward selection and unrelated remote updates |
| G04 Pending marks | Pending typing marks are editor-local transient state: null derives from context, an empty set explicitly disables marks, and a nonempty set overrides them. Apply text plus allowed marks together; recompute on selection-context change and validate before changing pending state | Toggle collapsed mark with zero content edits, type, split, revisit empty destination, and reject an incompatible mark |
| G05 Composition ownership | The browser/native control owns its composing subtree. A qualified input ADR fixes buffering/finalization/cancel policy before adapter implementation | compositionend before commit Enter with isComposing=false must not cause a split; the next deliberate Enter must work |
| G06 Coordinate units | UTF-16 boundary validity, grapheme boundaries and visual movement are different contracts. Preserve original code points and authored whitespace | Reject surrogate-interior command ranges separately from grapheme deletion; test NFC/NFD, ZWJ, flags, Indic and bidi without rewriting text |
| G07 Origin and history | History admission classifies local user edits, remote updates, imports, recovery and renderer work. One transaction does not automatically mean one undo group | Type → remote edit → paste → undo: only paste disappears; undo restores the stored selection, not a later caret |
| G08 Notification isolation | Commit completes and releases transaction/locks before notifying host/renderer. Subscriber exceptions cannot roll back a committed edit or trigger duplicate persistence | Subscriber throws, unsubscribes, destroys or requests another edit; verify the declared deferred/rejected command policy and single publication |
| G09 DOM reconciliation | Renderer patches have scoped generation/origin ownership. Suppress only identified renderer echoes, not every mutation in a time window; preserve active native input | Render echo and unrelated genuine input in the same turn; only the genuine input creates a new edit |
| G10 Normalization termination | Preparation normalizers have bounded work and a convergent canonical form. A valid committed state is stable under repeated normalization | Normalize twice, test interacting repair rules and resource limits; no oscillation, silent loss or endless repair transactions |
| G11 Async target/lifetime | Captured anchors, request generation, session/epoch and cancellation govern completion. Current caret is not a fallback target | Resolve after target deletion/editor switch/disposal; recover/reject without redirecting, refocusing or committing twice |
| G12 Event ownership | Nested editable controls, clipboard handlers and drag/drop presenters explicitly own or decline an event. A consumed inner-control event does not edit the outer document | Paste in a node-view input, drop once through multiple listeners, then use the outer editor; each acts only on its owner |
| G13 Identity and rendering | Block identity/selection are independent of DOM tag/view instance; replacement presenters release old resources and adopt qualified mappings | Heading/tag/custom-view rerender at a selected caret, delayed mount and another keystroke; no content loss or stale target |
| G14 Evidence integrity | Tests observe actual adapters/engine, independent expected outcomes and nonzero intended assertions. Fixtures, screenshots and receipt validators have distinct evidentiary scope | Corrupt expected content, range, origin/count and platform receipt; each required assertion fails rather than regenerating the golden |

Current separate text/format/structure primitives and their stale-plan checks are useful foundations, but do not establish G02/G03/G04/G07/G08. Do not emulate one atomic action by publishing several commits and undoing partial work after failure. The responsible engine task must qualify a complete prepared operation and semantic selection policy first; the suite marks dependent recipes blocked until that capability exists. This contract does not invent a storage schema or require viewport/DOM state in Rust.

## Input and command protocol

An adapter classifies input, captures a stable target and permitted marks, prepares the semantic operation, checks applicability/read-only/session state, commits once, applies its selection policy, and then publishes a scoped result. Record causality separately from payload. Terminal states include handled, native-pending, committed, canceled, rejected and disposed; a handled keyboard event cannot independently replay the same edit through beforeinput. A native edit awaiting reconciliation is not already an engine commit.

The operation-correlation strategy must be proved against observed event traces, including observer-first and missing/noncancelable beforeinput. Scope tokens to an editor root and generation. Do not identify intents by identical data, a blanket debounce/time window, or a fixed assumption about event order. Reconciliation cannot discard a later legitimate identical keystroke. Composition-session evidence must distinguish the IME commit key from subsequent intentional commands without indefinitely suppressing Enter.

Fix the composition ADR before WEB-1.4–WEB-1.7 implementation. WEB-1.13 owns this prerequisite: use the delivered engine/storage/renderer/selection boundaries to qualify a minimal real-DOM/real-engine protocol probe and record `decisions/004-browser-input-composition.md` with passing evidence in `evidence/browser-input-policy/receipt.json`. This mechanical qualification permits production routing implementation; actual OS/IME/device support still requires its separate qualification. RGS-1.4 later reuses the qualified ADR/probe and proves the shared driver against the completed production adapter; track 08/42 completion is not a prerequisite for WEB-1.13. The default desired model is temporary native composition followed by a prepared final edit; any qualified exception for observed platform behavior must state how intermediate commits/history/remote changes are handled and update the corresponding acceptance. An absent ADR is a prerequisite gap, not evidence that a particular buffering policy already exists.

Define subscriber behavior explicitly: queue a requested edit for a later dispatcher turn or return a typed reentrancy rejection; never mutate inside the still-live transaction or synchronously recurse through render/observer/command callbacks. A thrown callback is reported independently of commit success. Dispose invalidates queued ownership, while already committed state remains recoverable. Tests assert the selected policy rather than accept either outcome nondeterministically.

Normalization belongs to bounded preparation and validated projection. Prefer rejecting unsupported input with preserved source over repeatedly mutating the committed document to repair it. For necessary repairs, document the decreasing measure or bounded convergence argument. CRDT arrival orders must produce equivalent admitted semantic state without choosing winners by callback order. Test unknown-node/mark retention and schema profiles separately from presentation fillers.

## Test layers and oracles

| Layer | Exercises | Oracle and limit |
|---|---|---|
| Plan/fixture integrity | Case ownership, recipe structure, source links, offsets, required expected snapshots | May pass now; proves no runtime behavior |
| Pure semantic | Real Rust prepared operations, schema and UTF-16/grapheme helpers | Hand-authored snapshots/selection plus version-pinned official Unicode vectors; never call the implementation to generate its own expected output |
| Sequence/history | Real command dispatcher and history with fixed clock/origins; related operations and negative paths | Assert every checkpoint, explicit undo/redo outcomes, atomic rejection and attributable effect counts |
| Property/interleaving | Seeded valid command sequences, schema constraints, normalization and two-replica update schedules | Algebraic invariants and convergence of admitted semantics; shrinking preserves preconditions and writes the minimal failing trace |
| Browser mechanics | Real packed WASM/adapter, DOM mapping, event ownership, focus and rendering | Production handlers with observed state/commit instrumentation; prepared native-event delivery is labeled synthetic |
| Browser interaction | WebDriver/Playwright key, pointer, selection, clipboard and layout actions supported by the browser driver | Actual document/caret/focus/DOM observations; jsdom or untrusted dispatchEvent cannot establish native defaults |
| OS/device/AT | Actual mobile keyboard, native IME/dictation, selection handles, Safari and screen readers | Exact reproducible device observations; no emulator, receipt checker or recorded trace substitutes for this layer |

Screenshots support layout/focus evidence but cannot prove semantic preservation. HTML/text serialization alone cannot prove selection, pending marks, block identity or correct undo. Cross-editor differential testing may help reduce a bug, but differences between editors are not failures until edit.ac's explicit policy identifies the expected result. Normalize only irrelevant representation differences; never normalize away content, Unicode, marks or stale selection to make a comparison pass.

Use a fresh engine/session/history and clean DOM/clipboard state per isolated case. Shared fixture state, deleted-node retention, previous history and leaked listeners can mask failures. Multi-editor/replica tests create those peers deliberately. Instrument committed local/remote transactions, history boundaries, public updates and persistence enqueues separately; rejected/no-op actions assert zero attributable effects, without pretending independent remote edits or OS finalization did not happen.

## Fixture format and replay

Recipes use schemaVersion 1 with an ID, layer, catalog coverage, required capabilities, session context, initial state and ordered action/expected checkpoints. The JSON is a logical testing projection, not the CRDT schema, wire format or a second runtime model. Each expected state contains blocks/text/marks/hard-break offsets, directional selection/affinity and pending marks (null for context-derived, [] for explicit none). A hard-break offset points to an LF in a paragraph's flattened test projection; code LF remains literal. Public positions use UTF-16. The driver maps the projection to a qualified engine profile and fails explicitly when that profile cannot express it.

Initial logical block aliases are bound to actual stable IDs at fixture creation. Newly created aliases bind to the creating command's result; do not infer identity by searching final text. The adapter reports a canonical semantic snapshot using those bindings. Expected states are authored independently; do not update them from actual output automatically. Invalid command arguments are permitted in actions designed to reject, while every initial/expected state must itself be valid.

Within applyBatch, each later operation addresses the virtually updated state produced by preparing the preceding operations. For example, insert X at offset 1, then mark [1,2), marks the inserted X. Preparation must resolve and validate all operations without publishing intermediate mutations, then commit once. Rejection leaves the original state intact. This coordinate policy belongs to the action contract; the driver must never infer it from expect.state.

The initial JSON recipe profile covers paragraph/code text selections; node/cell selections and widget insertion anchors remain required catalog cases with an explicit later fixture-profile extension, not silently flattened text offsets. An action clockMs is a deterministic driver-clock advance used in history cases. Each step specifies its expected outcome and attributable local/remote commit counts. Full integration expands those into update, history and journal assertions at the relevant port; it cannot infer them merely from the number of commands. History recipes use explicit undo/redo states to expose grouping errors. The initial recipe set exercises representative existing cases and new failure patterns; it is not executable coverage for every catalog row. A recipe covers list is traceability to related cases, not a declaration that every variant of those cases is satisfied. Complete runtime bindings must enumerate and execute the missing variants separately. Catalog entries without a driver/test binding remain planned.

The nativeInsert recipe describes a controlled DOM mutation plus input/observer notifications with an explicitly missing beforeinput event. Its browser-replay driver must mutate the DOM, deliver the stated sequence and observe the real adapter; it must never write expected text directly into the engine. This replay proves the fallback mechanism, not actual keyboard/IME compatibility.

## Determinism, properties and sensitivity

Drive a fixed scheduler/clock for debounce, grouping and asynchronous providers. Await step-scoped quiescence: immediate engine/patch/reconciliation work has drained, required persistence for that step has settled, and selection has reached its acknowledged generation. A staged action such as beginPaste deliberately retains its declared pending request so later steps can interleave remote edits or cancellation. Require terminal disposition at complete/cancel/dispose or recipe teardown, not at the staging checkpoint. Teardown must report leaked requests rather than silently resolving them. Add a bounded timeout with diagnostics; avoid arbitrary sleeps, assuming one frame is enough, retrying until a test happens to pass, or waiting for unrelated network work.

Seeded generators admit only actions valid for the current schema/selection unless testing rejection. Required properties include atomic rejection; selection resolves after every accepted operation; UTF-16 boundaries remain valid; local undo preserves independent remote content; import/export preserves the declared semantic profile; normalization reaches a fixed point; duplicate/reordered delivery converges; canceled async work produces no local edit; and unrelated patches preserve caret/focus. Record seed, operation trace, Unicode/schema/tool versions and minimizer output. A passing random run is supplemental, not a replacement for the fixed regression corpus.

Before trusting a new assertion, run a targeted negative control: change one expected character, selection direction, retained mark, transaction count, pending-mark state or source/platform revision and prove it fails. Introduce a bounded fault at the final prepare check, post-commit subscriber, duplicate observer notification, stale async completion or cleanup path. Keep production instrumentation out of release bundles unless it is already a documented diagnostic port. Avoid broad mutation-testing infrastructure until specific guards need it.

## Native history selection bookmark repair (UPG-1.2 / RGS-1.2-C3)

The existing prepared editor command batch admits an optional first `historySelectionAt` command. It validates both transaction-entry endpoints before any staged edit, preserving anchor/focus order and each endpoint bias. Prepared fragment edits capture their actual input selection automatically and retain the existing G03 right-biased result-caret policy. Undo restores entry affinity; redo restores actual result affinity. Native history retains those relative anchors together with the prepared result selection (or collapsed result caret), rather than caller-captured source offsets. Undo returns the mapped entry bookmark; redo returns the mapped result bookmark against the committed state. Unrelated remote changes rebase the bookmarks through native anchor resolution. On restoration, native history preserves the referenced CRDT clock displacement within a copied text item and refreshes the endpoint onto restored item IDs, correcting the pinned Yrs relative-position interior-offset loss without storing source offsets. Selection metadata alone creates no content commit or history group. Invalid entry/result endpoints and failed history admission leave content, revision, history and publication unchanged. Packed history returns owned endpoint tokens; capacity and token-counter admission precede mutation and callers release the returned tokens.

Qualification remains acceptance-open until original SEQ-03/07/13/14 and G03 endpoint, direction, affinity, rebase, sentinel and rejection assertions pass in native and packed production engines. Prepared primitive proof cannot replace those original expectations.

## Text grouping and host history bookmarks (RGS-1.3)

Prepared native text edits retain the validated input anchor/focus as the transaction-entry bookmark and a right-affine upper cut as the result caret. A coalesced typing group preserves its first entry bookmark and updates its final result bookmark. Explicit paste/cut operations remain separate even at the same caller-supplied clock value; origin/session and native boundary policy determine grouping. Undo/Redo returns owned mapped endpoints. The single-block fragment fast path, including cut, retains the original directional entry range and independent endpoint biases; its result is the right-affine collapsed replacement end. Production keyboard history applies both endpoints and their affinity after rendering, recaptures the selection and releases returned tokens. Structural keyboard commands supply the actual transaction-entry selection before their first operation.

REG-04 translates the pinned upstream paragraph range 6–13 to UTF-16 cuts 5–12 and insertion position 14 to cut 13. The engine uses native relative anchors and actual two-replica updates, with inverse Undo/reapplied Redo controls; ProseMirror step-map indices are not engine coordinates. Retain the remote insertion and permitted remote reparenting at every history checkpoint. These expectations do not waive the original full history and browser criteria.

## Align-left and preceding-separator typing profile (UPG-1.3 / RGS-1.2-C4)

Original REG-05 binds canonical left-aligned v5 paragraphs: their existing `["paragraph"]` tuple is the actual left presentation, without a new schema/root or table-cell metadata. The native prepared block command `setAlignment { owner, alignment: "left" }` validates a visible paragraph and preserves its presentation, source spans, text and marks. An already-left paragraph is a zero-update, zero-history no-op; it does not clear editor-local pending marks or change the caret. Nonparagraph owners and undeclared alignment values reject atomically. This bounded profile covers the original align-left variant; it makes no claim for other alignment values or renderer/device behavior.

Pending marks remain editor-local: null derives allowed context marks, empty disables them, nonempty overrides them. Align-left and deletion of a preceding rule trigger or separator preserve this explicit state. Separator deletion uses the existing prepared `deleteSeparator` command with actual native entry/result selection bookmarks on the unchanged editable owner; retained separator/source identities reappear on undo. Typing applies text and admitted marks together in one prepared action. Moving away/back and successful history navigation clear pending state and recompute from the resolved context, with no ghost span or default mark. Invalid alignment/targets or a rejected later operation preserve all persistent and transient state.

Qualification must bind the immutable original REG-05 row and SEQ-05 recipe, both pending empty/nonempty controls, context-derived typing, move-away/back, source/owner identity, one-action history, actual native selection endpoints/affinity and a following sentinel. Original REG-07 code/empty-root and selected code/text pre variants remain required; this profile does not reduce them. Native evidence proves committed semantics and bookmarks; packed host evidence additionally proves editor-local pending lifecycle.

## Presenter insertion result policy (RGS-1.7 / REG-17)

The existing v5 `insertParagraph` command beside a separator captures a right-affine result caret at the end of the newly staged paragraph's authored UTF-16 text. Capture occurs in preparation after creation/placement, so later commands rebase the relative anchor and rejection has no live effects. Explicit final `selectionAt` retains precedence. This result maps through the production DOM bridge; an exact DOM selection of a noneditable block is a node action, never an adjacent text range. Separator node deletion uses one prepared native command with a right-affine resulting adjacent text caret: the previous editable owner’s UTF-16 end, otherwise the next editable owner’s start; if neither exists, it creates one empty paragraph and returns its start. Explicit final `selectionAt` retains precedence; unsupported textual node actions reject without overwriting neighbors. These policies do not qualify table-specific or native gesture/device behavior.

## Presenter drag ownership (RGS-1.7 / REG-11)

The optional reorder presenter accepts a mapped custom-view drag grip only when the host explicitly sets `data-editac-reorder-handle` and `draggable="true"` on that noneditable grip. Ordinary embedded controls retain their event ownership. A grip lives in a registered presenter decoration, rather than authored text DOM, and does not grant ownership of canonical source. Drag scope/token binds the source to the active presenter; move uses one prepared native command and retains the source selection. Copy delegates the prepared payload to the clipboard adapter at the captured destination. Canceled, noncancelable, read-only or unavailable targets do not commit. Injected payload/duplicate-notification proof and trusted browser pointer/HTML-drag proof have separate provenance.
