# Text and block editing behavior profile

Status: development contract, 2026-10-24. New requirements below are planned until their implementation and scoped evidence pass. This document is not a certification of current builds.

## Scope and authority

This supplement selects the relevant outcomes from the [standards and editor review](../research/text-editing-standards.md). It adds precise residual requirements to [everyday editing](editor-interactions.md), [editing experience](editing-experience.md), [platform services](platform-editing-services.md) and [block actions](block-actions.md). Those documents remain authoritative for their already-defined behavior, especially Enter, Tab, link boundaries, conversion and history. The [planned queue](../runner-queues/editing-standards-20261024/README.md) maps residual work to existing owners; it does not enqueue itself or alter the active runner.

Keep one Rust semantic engine, prepared atomic mutation, shared local-origin history, stable relative anchors and the [one current durable format](document-durability.md). Native/browser input owns provisional composition and visual layout. A host/embedded control owns its application data and focused commands. Do not introduce a second browser history, Notion storage layer, alternate text model, automatic migration or renderer-specific persistent metadata.

The labels ES-* below are requirement identifiers, not implementation status. “Must” states our required product behavior. Standards references supply mechanisms; editor conventions inform the chosen profile without overriding existing decisions.

## ES-TEXT-1 — Positions, text admission and preservation

Every position-bearing boundary names its unit and target: document/session identity, owner, base revision or retained relative anchor, and endpoint affinity where supported. Public numerical text offsets remain UTF-16 code units. Ordered spans are half-open; anchor/focus are retained separately so a backward selection remains backward. Rust byte indexes, scalar counts, native storage coordinates, DOM element-child indexes, UTF-16 text-node offsets, source columns and screen coordinates must never be exchanged without an explicit conversion.

For `A😀é` (U+0041 U+1F600 U+0065 U+0301), the lengths are 8 UTF-8 bytes, 5 UTF-16 units, 4 scalars and 3 default extended grapheme clusters. The final grapheme occupies UTF-16 `[3,5)` and UTF-8 `[5,8)`. Use this and multi-owner variants at SDK/WASM/FFI/native/CLI boundaries. Reject interior-surrogate, out-of-range, wrong-owner and stale unresolvable targets before mutation. Character-deletion operations additionally use the engine's grapheme rule; this does not redefine all API ranges as grapheme indexes.

Preserve composed/decomposed sequences, authored spaces, tabs, NBSP, narrow NBSP, zero-width and bidi characters under the existing admission policy. Literal external CRLF/CR converts once to LF; authored hard breaks, paragraph boundaries, renderer filler and source soft breaks remain distinct. No implicit NFC/NFKC, smart punctuation, whitespace trimming or tab expansion. The existing web ingress rejects unpaired surrogates and unsupported C0/C1 controls with a UTF-16 diagnostic and recoverable input; native and import bridges must not silently turn rejected source into replacement characters before that check.

Byte-perfect plain-file preservation is a separate declared format capability. A rich-document round trip does not imply preservation of original encoding, BOM, newline convention or final newline. Unsupported input preserves original recovery bytes according to the format/storage authority. Existing current-format admission remains the gate; this requirement adds no old-format reader.

## ES-TEXT-2 — Segmentation and fallback

Record the deployed segmentation implementation, Unicode data version, tailoring and applicable operations. The current source-selected Rust profile is `unicode-segmentation = 1.12.0`, pinned exactly in [the core manifest](../../core/crates/editac-core/Cargo.toml) and authenticated by its archive checksum in [Cargo.lock](../../core/Cargo.lock). Its installed `src/tables.rs`, checked against that archive, declares `UNICODE_VERSION = (16, 0, 0)`. This declaration, rather than the crate version alone, establishes the Unicode **16.0.0** data profile. The researched Unicode 18 annexes are reference material, not an implemented upgrade or a new document-format identity.

[The anchors helper](../../core/crates/editac-core/src/anchors.rs) calls `grapheme_indices(true)`: default extended grapheme clusters under the crate's UAX #29 implementation, with no application tailoring or locale override. `move_grapheme` and `deletion_range` traverse those logical boundaries; they do not implement visual bidi movement, word/sentence segmentation, line breaking or shaping. `utf16_to_byte` checks scalar boundaries before returning a UTF-8 byte index; `byte_to_utf16` requires a UTF-8 scalar boundary. `validate_range` admits ordered scalar-aligned UTF-16 cuts, including cuts within a multi-scalar grapheme. Character deletion additionally rejects a non-grapheme cut; a document-edge deletion returns no range. Neither conversion nor segmentation normalizes text to NFC/NFKC. The byte/scalar/UTF-16/grapheme distinctions in ES-TEXT-1 therefore remain observable.

The source-selected engine identity is `editac.registry.editor` / `editac.yrs-yjs.editor`, protocol 1, update encoding 1, offsets `utf16`, selected by [`DocumentIdentity::current`](../../core/crates/editac-core/src/document.rs). This profile describes current source behavior, not admission of an arbitrary previously built WASM/native artifact. The existing [`anchors` fixture](../../core/crates/editac-core/tests/anchors.rs), `grapheme_movement_and_deletion_are_extended_and_logical`, covers combining marks, a supplementary scalar, ZWJ emoji, regional indicators, logical RTL, CRLF, edge no-ops and interior-grapheme rejection. It is a helper fixture, not full native-input or Unicode conformance proof.

The initial scoped coordinate/ingress audit below records the pre-delivery inspection. Its same-owner composition and optional-browser-API gaps are now implemented for the declared compatible scope; see the [current clause/owner/evidence and support map](../tests/editing-standards-conformance.md). Preserve the audit's ingress limits: selected deterministic cases do not establish malformed native-source preservation or OS input qualification.

Browser `Intl.Segmenter(undefined, { granularity: 'grapheme' })` uses host Unicode/ICU data and locale resolution; native text systems likewise vary with OS/runtime. Neither is pinned to Rust's Unicode 16.0.0 tables. At the initial audit, styled-span repair in `DOMSelection.#completeMovement` used the host segmenter and `Selection.modify` without the required feature checks and explicit iteration bound. ES-1.2 supplied those guards; ES-4.1 verifies selected API-absence/disagreement cases. Neither this inventory nor those cases establish agreement with every host's cuts. Swift/native malformed-source handling, direct SDK/FFI string ingress, Windows/Linux adapters, and CLI/import paths beyond the selected web ingress are not qualified by this audit; their existing adapter/format owners must establish conversion and rejection before claiming parity. No confirmed unit-conversion mismatch in the audited paths requires a new boundary implementation here.

Rust's accepted boundaries remain authoritative for semantic character deletion. Word/line intent can use the platform's supplied range under the current validation rules. Browser/native layout remains authoritative for visual movement. A browser ICU segmentation result must not silently redefine engine cuts. If comparison finds disagreement, preserve text and reuse the engine boundary helper through the existing prepared command, exposing a narrow read-only boundary query only if visual repair requires it, or return an explicit unavailable operation. Never delete an arbitrary code unit as a fallback.

The browser's styled-span repair must feature-detect `Intl.Segmenter` and `Selection.modify`, terminate boundedly, and avoid exceptions when either is absent. Keep ordinary native movement available. Do not approximate bidi visual order with logical `offset ± 1`, install another segmentation library merely to hide the discrepancy, or rewrite document text. If an adapter cannot safely repair a visual stop, retain a valid native selection and prevent unsafe mutations through the engine; make the limitation inspectable. A dependency/table upgrade requires affected-vector qualification, not an unrelated compatibility-format matrix.

Required coverage includes combining marks, emoji modifiers and variation selectors, ZWJ sequences, regional indicators, Indic clusters, styled-span boundaries, malformed-surrogate admission and API absence. Distinguish movement, range extension, Backspace, Delete, word deletion and literal text matching; they do not share one universal “character” definition.

## ES-TEXT-3 — Language, direction and visual layout

The initial selected capability is a **host-level** language and base-direction profile. Resolve explicit editor settings before inherited host settings, then native defaults; expose the effective profile and unsupported settings. Web roots use the corresponding `lang` and `dir` values, with `ltr`, `rtl` or native automatic direction as declared by the adapter. Native hosts map the same intent to their text system. Validate configuration without changing authored text. Changing this presentation profile produces no document transaction or history entry.

This does not claim persisted per-block language/direction. Adding that later requires a shared property, import/export semantics and durability acceptance in the one current schema. Copying a document or reopening it under another host must not be advertised as retaining a host-only setting. Preserve language/direction metadata already admitted by a supported format; report unsupported preservation explicitly rather than invent it during export.

Arrows and selection extension follow native visual layout; word/line/document modifiers follow the selected platform profile. Vertical movement retains preferred horizontal position; wrapped-line and bidi boundaries retain the adapter's supported caret affinity. Font fallback, ligatures and glyph shaping never supply source-text indexes. Reflow, zoom, font and viewport changes invalidate geometry without changing content or anchors. Scroll-to-caret and selection rectangles must remain consistent after rerender and across visible viewport boundaries.

The TUI intentionally edits logical-order source with its documented display-width and escaped-control policy. It is not a visual RTL rich-text renderer. This difference must be visible in its help and support profile.

## ES-INPUT-1 — Replacement and composition across compatible blocks

Hardware keys, native menus, dictation, spelling correction, handwriting, virtual keyboards and IME can express the same edit. They must reach one applicability-checked semantic command. Use reported replacement targets, not a newer visible caret. A noncancelable or absent `beforeinput` uses the existing reconciliation path. Event ordering is adapter evidence: the retrieved Input Events/UI Events drafts disagree, so neither order alone is a universal correctness oracle.

Extend selected replacement from one text owner to compatible prose blocks, including forward and backward selections across paragraph/heading boundaries. The exact supported container relation is the current prepared range/fragment policy; crossing a table's interior, protected content or an unqualified atom/container boundary rejects atomically with a stable reason. Do not silently flatten those structures to make composition start.

| Phase | Required result |
| --- | --- |
| Capture/start | Retain both endpoints, original direction, session and applicable context. Preserve all durable content. Starting composition must not commit deletion of the selected range. |
| Provisional updates | The adapter owns marked/preedit text and candidate geometry. Hold/reconcile the affected projection without producing persistent intermediate replacements or a second undo history. |
| Commit/direct replacement | Prepare one replacement at the retained target; preserve the unselected first-block prefix and last-block suffix under existing structural policy. One accepted intent yields one semantic transaction/history group and the returned usable caret. |
| Candidate Enter | Commit the candidate once; do not also split a paragraph or activate a menu. The next separate deliberate Enter keeps its normal meaning. |
| Cancel | Restore the precomposition document and selection, with zero semantic change. Preserve legitimate remote edits; never restore an obsolete whole-document snapshot. |
| Focus change | Apply the adapter's declared commit/cancel policy exactly once. Do not redirect delayed input into the newly focused control. |
| Concurrent outside edit | Re-resolve stable anchors and retain the intended replacement when still valid. |
| Concurrent overlap/deleted target | Follow existing conflict admission; on rejection preserve recoverable composed text and show a retryable result. No silent insertion at document end or current caret. |
| Undo/redo | Restore content and semantic selection as one local action while retaining unrelated peer edits. Provisional updates are not separate history entries. |

Web and native delivery use the existing Session/engine interfaces, extending the current interface where necessary. A same-owner guard is an explicit current limitation, not permission to advertise cross-block input parity. Existing EDX history/break repairs and platform owners must be consumed before duplicating their work.

## ES-KEY-1 — Conventional keys and command ownership

The existing catalog/profile remains the single keyboard authority. `Primary` is Command on macOS and Control on Windows/Linux. Preserve host reservations, assistive remapping, AltGraph, dead keys and non-US layouts, including Hungarian accented text. Bind interpreted semantic keys for editor commands; text entry is not reconstructed from `keydown` or physical `code` values.

| Action | Default rich-editor behavior |
| --- | --- |
| Arrow / Shift+Arrow | Native movement / extension, including bidi, wrap and selection collapse; no content transaction. |
| Word / line / document / page movement | Native platform profile, with Shift extending; no global replacement with logical storage traversal. |
| Primary+A | Select the focused editing scope. A search field or table interior keeps its own selection owner. |
| Backspace / Delete | Delete selected content once or a qualified grapheme; boundary joins/outdents follow existing structural rules. An adjacent noneditable atom uses the existing select-first policy. |
| Primary+B/I/K; optional U | Existing formatting/link catalog, captured target and capability checks. |
| Primary+Z / Primary+Shift+Z; Windows Ctrl+Y | One semantic undo/redo; correlate native history events so a key and input event cannot apply twice. |
| Primary+C/X/V; platform plain paste | Native clipboard gesture plus current semantic transfer policy and visible alternatives. |
| Enter / Shift+Enter | Existing context matrix: paragraph/list structure versus authored break; code literal LF; table in-cell break. Never implicit form submission. |
| Tab / Shift+Tab | Existing prose indentation, list structure, code indentation or table navigation; boundary behavior remains explicit. |
| Escape then Tab | Existing popup dismissal and one-shot editor focus escape. IME-owned Escape wins; a block feature must not hijack this contract. |
| Find, zoom, browser navigation and OS commands | Host/native ownership unless the user-visible document-search profile explicitly reserves a supported command. |

Keep macOS Option word commands and Command line/document commands distinct from Windows/Linux Control word/document commands and Home/End. Expose actual bindings in keyboard help and an accessible command surface when a chord is unavailable. Do not apply Notion's global Escape/block shortcuts wholesale.

On the web, modified Backspace/Delete stays native until `beforeinput` so a reported deletion range retains precedence, including a range crossing compatible blocks. Without reported ranges, cancelable word/soft-line/hard-line deletion at a collapsed paragraph/heading/code outer edge delegates once to the existing backward/forward structural command: join compatible siblings, backward outdent/exit a list or quote, or select an adjacent atom first. Exactly selected atoms use the existing deletion command. The correlated physical key respects host reservations/remaps, composition and AltGraph; native menu/virtual-keyboard input can supply the same typed intent without a key. In-text units and code-internal line boundaries stay browser-owned, with no word segmentation inferred from keydown. Unsupported joins retain the existing nonmutating refusal; noncancelable or absent input notifications use bounded native reconciliation and explicit recovery if the DOM changed incompatibly.

The TUI adds a named terminal profile for reported Ctrl/Alt word movement, document Home/End, PageUp/PageDown and their supported Shift extensions. Word deletion may be bound only when the terminal reports a distinct chord and the existing source-edit path can implement it safely. Respect global save/commit/history/reload controls and terminal/OS interception. State ambiguous or unavailable encodings in help; never silently map them to a different destructive edit. Source draft history and semantic committed-document history remain distinct under the TUI contract.

## ES-SEL-1 — Text, block and embedded selection

Model the command target separately from persistent document content. Retain existing relative text anchors and history machinery. Add only the current ephemeral target/bookmark distinctions needed by supported commands; do not store UI selection in the CRDT schema or introduce a parallel selection engine.

| Target mode | Meaning and boundary |
| --- | --- |
| Caret/text range | Existing stable endpoints, ordered operation span and independent direction/affinity. It may span compatible blocks. |
| Single content atom | Existing exact noneditable-block target, not a fabricated zero-length text range. |
| Contiguous block selection | One or more adjacent siblings, each including its actual subtree. A heading's outline section is not automatically its subtree. |
| Embedded selection | The table/code/extension's scoped target. An interior cell or embedded control is not the containing document block. |

Select block is a visible, keyboard-accessible action in the existing command/menu system. It captures the intended block before focus moves. It must work for editable prose and admitted noneditable blocks. Within block mode, Up/Down moves selection focus to the adjacent block and Shift+Up/Down extends through contiguous siblings in document order; neither reorders content. Reject or stop at incompatible parent/root boundaries rather than silently flattening them. Normalize an explicitly supplied ancestor-plus-descendant target to the outermost selected subtrees, with no duplicate mutation.

Enter on an editable selected block returns to its retained valid text caret or the first admitted text position; a noneditable block exposes its existing activation action or a stable unavailable result. Escape closes an active popup first and otherwise exits block mode to a valid prior editing target while preserving the existing next-Tab focus escape. Text selection, IME activity and embedded control focus must not be stolen by a block handle. Discontiguous block sets and multi-cursor text editing remain outside this profile.

Captured targets carry identity, permissions and appropriate structural revision, then revalidate at activation. Intervening unrelated text edits must not unnecessarily invalidate a structurally safe move; deleted/reparented/stale targets must not become a different current selection. Mode changes and selection movement alone create zero semantic commits/history entries. Selection announcements, focus return and post-undo mode must be defined through the existing result-selection/bookmark ports, including a meaningful text fallback when a selected block disappears.

## ES-BLOCK-1 — Mixed selection applicability

Use this worked shape as the cross-context oracle: a selection starts inside a paragraph, completely covers an image or table block, and ends inside a list item's text. Test the same range backwards. Preserve the unselected prefix, suffix, list siblings, nested descendants, supported marks and opaque data. Actual operations remain subject to the existing prepared fragment and content policy.

| Command | Text range spanning supported whole objects | Whole block selection | Embedded interior |
| --- | --- | --- | --- |
| Copy | Clip partial text endpoints; include complete supported objects and necessary container context. No fabricated text substitute for unsupported data. | Serialize admitted selected subtrees in order, with explicit external-format fidelity. | Owner's table/code/extension transfer contract. |
| Cut | Prepare/write clipboard successfully before one deletion. Failed copy or stale source leaves source intact. | Same success rule, one prepared deletion, preserved required empty-document structure. | Owner handles it; do not delete containing block. |
| Delete/Backspace | One prepared selected-range removal, preserving surviving tails. Reject an unsupported/protected mixed target before mutation. | Remove selected roots once; respect subtree and minimum-document invariants. | Owner edits its selection or reports unavailable. |
| Typing/Enter | Replace compatible selected text using ES-INPUT-1 and the existing break context. Complex unqualified mixed structures reject without partial deletion. | A non-text block-mode target does not silently become a text range; enter editing mode first or use an explicitly admitted replacement command. | Owner decides text/row/cell semantics. |
| Inline formatting | Apply to selected editable text and explicitly admitted atom backing-text ranges, preserving payload/structure. Atoms without a qualified markable range have no inline mark action. Protected/unqualified text segments reject the whole action. | Apply only if a declared command can target selected text descendants or admitted atom text atomically; otherwise expose unavailable. | Owner's formatting policy. |
| Turn into | Use only the current conversion mapping and precise captured block targets; a text range is not permission to convert unrelated descendants. | Apply qualified mappings atomically, or return the existing availability/impact result. | No implicit enclosing-block conversion. |
| Text drag / block move | Existing selected-text fragment transfer and its source-success policy. | Existing structural move semantics and ES-BLOCK-2. | Embedded owner; no document drag theft. |

Partial atomic content is not a valid whole-object fragment. A text selection through a table block and a table-cell rectangle are different targets. Formatting skips non-markable content without changing it; the existing rich-content contract still permits supported marks on reference labels, asset fallback text and inert source text through their admitted backing ranges. Transfer or deletion cannot silently omit a protected or unsupported selected object. Any rejected compound operation leaves content, selection, history and publication state unchanged except for an explicit recoverable diagnostic/focus response.

Result selection is part of every accepted command: record owner(s), UTF-16 endpoints or block IDs, direction, affinity and focus owner. Honor the core's existing atom-removal placeholder and structural-survivor policy rather than inventing an adapter fallback. A next typed sentinel must land at the advertised result; undo and redo must recover the intended mode/range without undoing peers.

## ES-BLOCK-2 — Identity, movement and conversion preservation

| Operation | Required preserved state | Allowed change |
| --- | --- | --- |
| Split | Existing source/text identity mapping, marks, anchors and unaffected neighbors under current durable split witnesses | New structural owner and defined resulting caret. |
| Join | Retained source identities/anchors, unselected text, admitted marks and peer edits under current join policy | Supported structural boundary disappears; no lossy stringify/reparse. |
| Move | Selected root/descendant IDs, payloads, text, marks, comments/reference targets and internal order | Parent/sibling placement through a valid acyclic destination; one undo group. |
| Paragraph/heading conversion | Exact text/breaks, marks, block/source identities, metadata, descendants and reference targets | Only declared presentation attributes; unchanged target is a no-op. |
| Advanced conversion | Existing explicit mapping's preservation guarantees | Only classified transformations; review-required loss uses the existing concrete impact approval contract. |
| Delete/undo | Existing retention and recovery rules, unrelated peer changes | Selected content becomes absent/restored through semantic history; no deletion of external asset/database ownership by implication. |

Every admitted kind exposes applicability for select, copy, cut/delete, move, convert and interior edit with a stable unavailable reason. The existing move implementation's limited kind list is a current restriction. Extend it to supported module content only after current placement/admission, identity, subtree, reference and opaque-payload invariants are proven. Table movement changes placement, not its cell storage; it consumes the current table contract. Unknown content remains inert and preserved. Move can be offered for an unknown kind only with a demonstrated opaque structural-preservation path; rendering a fallback label is insufficient.

This matrix describes semantic admission, not a promise that every browser control exposes it. Copy always uses its existing fragment identity contract, not the whole-owner Move guarantee. All write columns remain subject to current scope, permission/read-only, stale-plan and resource admission. Missing codecs or mappings return the existing unavailable result; selecting an object grants no new capability. The five admitted atom families share one descriptor validator at Move and Place admission. Placement writes only the existing structural intention; it does not decode/reencode the stored tuple, replace backing text, or transfer external ownership. A validated same-parent/current-next-sibling placement emits no intention, update or history entry. Unknown fields survive wherever the admitted carrier allows them; malformed known descriptors remain inert and refused. Tables and arbitrary custom tuples are not added to this Move allowlist.

Keyboard move controls and pointer reorder use the same captured structural target and move command. Cycle, stale destination, protected content and invalid parent failures are atomic; moving to the same position is a no-op. Move-versus-peer-text, split-versus-insert, join-versus-format and delete-parent-versus-descendant-edit remain current durability/concurrency obligations. Do not duplicate that engine in the browser.

Conversion is already owned by BTA/BTU/BTQ. Checked task → heading → task must not acquire an undocumented dormant-property rule: a mapping either preserves the relevant state explicitly, reports its loss under the existing review contract, or is unavailable. Generic Duplicate is deferred: code-line duplication does not imply block duplication. A future block duplicate would need fresh IDs and explicit internal-reference/asset ownership policy. Link, embed, synchronized appearance, snapshot and cross-page move are distinct host capabilities, not synonyms for local Move or Copy.

## ES-FMT-1 — Formatting, insertion state and search

Retain existing mixed-toggle rules, local pending marks, clear-formatting semantics and directional selection preservation. At a link's end, continued typing defaults outside the link; within the link it retains the link. This is our deliberate profile, even though CKEditor offers a different highlighted-boundary interaction. Do not add a second invisible insertion-affinity rule to imitate it. Toolbar/link dialogs capture the range before focus changes and revalidate it; cancel/unchanged acceptance makes no content edit.

Find/replace uses the enabled first-party search contract and declared scope. Distinguish literal, case/locale-sensitive and optional canonical-equivalent or regular-expression matching. Do not claim modes that are not implemented. Search normalization, if explicitly supported, operates on a comparison view and maps matches back to original UTF-16 ranges; it never silently normalizes stored content. Replacement uses current target validation and one declared semantic history action. Search-field keys and undo remain owned by that field. Whole-document search must not silently mean only mounted DOM text; unsupported hidden/embedded content is reported by the declared search scope.

This review found no new reproduced formatting/search defect. Existing INT/rich-content owners retain implementation; final standards coverage fills only missing assertions.

## ES-AX-1 — Accessible editing and command surfaces

Keyboard users must enter, inspect, select, operate on and leave supported text, blocks and embedded controls. Each block action has a labeled command alternative to dragging. Focus stays visible; mode/type/count announcements describe block selection without pretending it is text. A popup/toolbar can own keyboard focus while the document retains a semantic target. Escape, cancellation and activation return focus predictably. Toolbar arrow navigation must not steal keys required by an embedded text field or spin control.

Expose current text, structure, selection, editable/read-only state, meaningful object labels and change notifications through each adapter's accessible representation. Preserve admitted accessibility metadata through conversion and transfer. A textbox role, hidden mirror, screenshot or passing synthetic event does not establish accessible authoring across viewport boundaries. ATAG's authoring and output concerns and WCAG requirements remain separate declared acceptance areas.

Deterministic checks prove state/command mechanics. Real screen-reader, OS text service, IME, keyboard-layout and virtual-keyboard observations belong to existing platform owners and final roadmap43, including accepted simulators/emulators/VMs where applicable. Record browser/OS/locale/input method and limitation; never turn “not run” into “supported.”

## ES-INT-1 — Interchange, history and durability boundaries

Internal fragments, sanitized HTML, plain text and file import are different transfer paths with the existing precedence/limits. A claimed internal MIME type is not authority to bypass admission. Current format contracts own sanitization, permitted schemes, size bounds, source fidelity and loss diagnostics. Distinguish preserved, transformed, flattened, omitted and unsupported content per format and object type. No new CF_HTML, DOCX/ODF or generic patch implementation is required by the presence of those standards in the research.

Structural block move preserves selected block/subtree identities. Selected-text transfer follows the existing fragment and atom identity policy; it does not promise that every source block ID survives extraction and insertion. Cross-document/external transfer defaults to copy under the existing receipt contract. Destination failure cannot delete the source. A source-delete failure after a valid destination preserves both and reports the incomplete move. Copying an embedded view does not authorize copying or deleting its host records, permissions or asset ownership.

Undo, reviewed suggestions, revision restore, crash recovery and operation audit answer different questions. One accepted local action must enter existing semantic history once; native projection, remote changes, selection-only movement, cancel and rejected operations must not create local content entries. Restoring history also restores the declared selection/pending-mark policy. Existing origin and durable structural rules determine overlapping peer behavior.

“Saved” retains the storage contract's exact local/remote receipt meaning. A transport acknowledgement, state vector, rendered view or successful command return does not replace a durable save receipt. New editing paths must preserve current checkpoints/journal replay, unknown data and original failed-input bytes. No silent reset, relabel or migration.

## Completion oracle and non-goals

For every changed intent, record independently specified before/after content, block/source IDs, unaffected neighbors, marks/opaque payload, selection/focus, next-input location, semantic commit/history/publication counts, undo/redo, rejection and recovery. Reuse current deterministic fixtures and passing receipts when inputs are unchanged. Test development and comprehensive cross-context matrices belong to the final planned testing file; narrow functional delivery checks and compilation of the changed boundary remain required first.

Overall completion requires the [queue's](../runner-queues/editing-standards-20261024/README.md) residual functional and final deterministic acceptance, plus accurate handoff of outstanding platform observations. Compilation alone is not behavior qualification, and deterministic completion does not close unexecuted roadmap43 observations. The existing current-consumer, conversion, table and durability owners remain prerequisites only where actually consumed.

Excluded from this supplement: a new editor framework or shaping engine; paginated Word parity; synced blocks/databases; arbitrary discontiguous editing; macros/overwrite mode; a new review/revision system; automatic old-format support; paid synthetic inference; runner launch, publication or deployment. These exclusions leave their separately authorized owners intact.
