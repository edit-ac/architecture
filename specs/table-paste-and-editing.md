# Table paste and direct cell editing

Status: PLANNED — user correction, 2026-10-25. The user reported pasted tables looking like a collection of textboxes. This is a required product outcome, not an assertion that the current presenter, clipboard sources or all platforms already pass. The default rich browser editor is the initial delivery scope. Native table profiles consume the same semantics with their platform controls; a terminal source profile retains its documented source representation.

## Product outcome

A supported table pasted into the document looks like a normal document table: one coherent grid with cell text, formatting, headers, padding, borders, wrapping and meaningful column layout. Clicking text edits that cell in place. The idle table must not look like a form containing an always-visible textarea/input in each cell, repeat content in both a preview and a field, or show editing buttons and scrollbars in every cell. Contextual cell/rectangle controls appear when useful, with discoverable keyboard and accessibility equivalents.

The current textarea-per-cell presenter is an intermediate implementation. Styling those textareas to remove their borders alone does not satisfy direct rich cell editing, native selection, composition or paste fidelity. Reuse existing shared prepared cell commands and cell-range history; do not introduce another document replica, independently writable per-cell model, persistence owner or undo stack. An accessible active editing host may legitimately expose a textbox role; the requirement concerns repeated form widgets and visible field chrome, not removing necessary assistive semantics.

## Paste behavior

1. Outside a table, an admitted internal fragment or sanitized HTML table inserts one real semantic table through the existing fragment/import owner. Preserve supported surrounding prose and formatting; do not create a grid of form controls, screenshot, flattened text or one editor instance per cell. Word-like, document-editor-like and spreadsheet-like HTML use sanitized synthetic fixtures, not private clipboard captures.
2. Spreadsheet TSV follows the declared table-paste/profile policy and explicit Paste as table action when recognition is ambiguous. Preserve rows, columns, empty and trailing cells, Unicode, quoted tabs/newlines and literal formula-like text. Paste as plain text remains literal and bypasses richer offers. Do not infer a table from arbitrary prose or enable a spreadsheet formula engine.
3. Inside a cell, distinguish a captured text range from an explicitly selected cell rectangle. Ordinary text replacement stays in the target cell. Rectangular internal/HTML/TSV input uses existing bounded preparation and declared dimension policy; never accidentally nests a table, creates one input per pasted field, deletes the selection before validation or silently enlarges the table. Expansion requires the existing explicit structural action. Protected, stale, readonly, malformed, oversize, incompatible or unsupported merged/nested input preserves content, selection, history and storage and reports a recoverable reason.
4. Preserve admitted inline marks, links, paragraph and authored-line-break boundaries, cell header/body and alignment semantics. Admitted multi-block cell content renders and edits as content, not a permanent readonly source textarea or duplicated preview. Unsupported features retain a recoverable representation and explicit limitation; do not advertise them as working rich cells. Do not invent a second cell schema, old-format reader or automatic stored-data conversion.
5. Use the existing clipboard flavor precedence, sanitation, rich/literal modes and bounded format codecs in [formats](formats.md) and [table editing](rich-content-extensions.md#table-editing-layout-and-source-formatting). Form controls, script/handler/CSS payloads, unsafe links and formula-like text gain no execution or resource access. Unsupported markup follows the format owner's explicit rejection/fallback policy; it is never instantiated as document-supplied interactive fields.
6. Copying the pasted/edited table emits supported internal, HTML and TSV/plain representations of cell content, with no editor controls or field chrome. Unsupported/lossy destinations report limitations; do not silently flatten paragraphs, merge cells or strip supported formatting. New pasted objects get identities through existing semantic creation; internal exact recovery uses its existing declared carrier.

### Addressed rectangle admission

Rich rectangle replacement uses one public current-format Rust prepared command, shared by Session/WASM bindings and the TypeScript engine. Capture stable table/axis/cell-block identities and affected cell revisions/structure; validate bounds, visibility, protection and admitted blocks/marks before staging. Revalidate captured targets without making unrelated cell edits a whole-table conflict. Use engine-owned fresh block identities and retained structural events for replacement, preserving the table reference, other cells, unknown/hidden data and one selective history boundary. Return a usable cell selection. Stale, readonly, protected or unsupported requests refuse before changing content, selection, history or storage. Whole-table reimport and JavaScript batches against private generated identities do not satisfy this boundary. The focused DRA-1.2-I1/I4 repair is tracked in `runner-queues/table-rectangle-repair-20261025/00-addressed-rich-rectangle.md`; UDM-1.9 owns clipboard capture and presenter integration after that operation has passing public binding evidence.

The public invocation is `captureTableRectangle(snapshot.identity, table, rowIds, columnIds)` followed by one editor command `{ type: "tableReplaceRectangle", capture, tuple, protected }`. `tuple` is existing admitted converter `Content::Table`/`Content::RichTable` input, not a production table reference or a replacement document. `protected` contains host-protected stable `[rowId, columnId]` pairs. The capture carries document/epoch, table/axis identities and a row-major cell matrix; each cell has a Rust-issued `structureRevision` plus its visible block address/revision list (which may be empty after concurrent deletes). Structure tokens cover immutable relevant event IDs and their controls, including retained losing events, without including unrelated cell edits. They are opaque preconditions, not persisted document data. Dimension policy is exact replacement of at most 128 intersections; no expansion, merges or nested blocks. Cell header data and paragraph styles/marks are admitted; existing table/column attributes stay with their current owners. The result uses the ordinary `cellSelection` field at the first fresh block, UTF-16 offset zero. Session policy is checked during preparation and again at apply.

## Direct editing and layout

Use semantic table/header/cell structure and the existing current cell identities. The active cell routes beforeinput, hardware keys, soft input, IME and accessibility actions to the same prepared command boundary. Composition remains browser-owned until commit; rerendering must not replace its active subtree. Preserve directed UTF-16 selection, graphemes, marks, neighbors and stable target capture. Enter/Shift+Enter follow the existing cell-break contract; Tab/Shift+Tab and Escape use the declared cell/rectangle/focus policy without focus traps or surprise row insertion. Keyboard users need one coherent table entry/navigation model rather than unrelated always-visible form fields.

One accepted paste/replacement is one intentional semantic/history action. Undo restores the replaced content and selection, redo restores the pasted content and usable caret; typing a sentinel proves the result. Cell/row structural history returns entry/result bookmarks to the same adapter after projection. Cell selection, movement, cancel and rejection have zero semantic/history/journal effects. Save/reopen and supported clipboard/export round trips retain content, formatting and table structure under the one current document identity.

Visual acceptance includes idle, selected, actively edited, empty, multiline and readonly cells; narrow/wide widths, zoom, RTL and forced colors. Text wraps naturally or uses the declared bounded table overflow. No per-cell textarea resize handles, field borders, clipped duplicate content or unnecessary per-cell scrollbars. Do not sacrifice selection visibility or accessibility to hide controls. Native consumers use platform-appropriate equivalents and separate target-runtime proof; they do not import browser DOM or block independent web UI delivery.
