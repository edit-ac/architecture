## Architecture and optimization constraints

Maintain one canonical browser kernel, not a binary per preset. Cargo features
exclude unused host/source services; dynamic JS/Wasm companions handle bounded
codec, analysis and presenter work through data/command contracts. They do not
receive raw Rust pointers or own another mutable document. Any optional semantic
planner seam must keep validation/commit authoritative in the existing kernel and
preserve history, authority, stable targeting and failure atomicity. Retain tightly
coupled invariants in core rather than claiming a split that duplicates semantics.
If a material API/wire/ABI redesign is required, propose it before implementation
and update its spec and acceptance together. No shared-memory/dynamic-linking
framework or general plugin sandbox is assumed.

Disabled extensions retain stored data and honest fallback through reopen, sync,
copy/export and re-enable. Unknown data grants no execution or editing authority.
One current document format remains; no migration, data reseeding or schema per
preset. Loading a shared artifact grants no sibling editor a capability.

Source 03 starts only after sources 01 and 02 deliver their physical boundaries
and focused checks; comprehensive test development follows all functionality in
sources 03a/04. Preserve one shared 45-minute/two-materially-different-hypothesis
optimization limit across WEX-2.7 and source 03, failed experiments and original
hard gates. WEX-1.2 establishes that ledger; source boundaries cannot reset it.
Do not repeat earlier rejected
optimizer hypotheses unchanged. Investigate pinned wasm-opt settings, gzip/Brotli
precompression, JS minification and glue deduplication against the post-split
baseline; record CPU/startup/compile/memory tradeoffs. A custom decoder must count
its own JS/Wasm and cannot bypass CSP, MIME, streaming or browser requirements.

Attribute Wasm sections and rooted retention as well as package edges. Twiggy's
upstream is archived; use it only if an available version supports our artifacts,
with maintained wasm-tools and targeted IR/consumer-graph inspection as fallback.
Profiles guide selective generic-body sharing, cold formatting/serializer cleanup,
and measured inlining decisions. The candidate menu includes `s` versus current
`z`, supported Binaryen size pipelines, JS/glue tree shaking and Zopfli/Brotli
precompression. Select from it using current evidence; do not execute a full sweep.
Current LTO/codegen/strip/panic settings and Brotli quality 11 are already baseline.
Keep the current allocator; do not adopt unmaintained wee_alloc, unchecked/trapping
error shortcuts, blanket trait-object rewrites or a nightly custom-stdlib workflow.
