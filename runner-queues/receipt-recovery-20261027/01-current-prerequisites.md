## Receipt and failure rules

A setup/build receipt records actual preparation/build inputs and outputs; it is not a passing behavioral receipt. Validate the exact schema consumed by existing code, current source/main applicability, immutable archive member hashes, installed regular-file paths, executable identity and toolchains. Never copy a differently scoped proof into an absent path, fill success fields by hand, overwrite immutable historical evidence, relabel an old build as current or accept a source alias as an installed package. New proof has explicit current dated provenance and an explicit consuming binding. Missing/stale/incompatible inputs remain failed prerequisites.

A passing behavioral receipt needs a real nonzero existing case selection, zero failures/skips/cancellations, applicable source/artifact/runtime pins and verified browser/server/child teardown. Authenticated reuse records its exact applicable consumed boundary; matching package names or an old exit code is insufficient. Keep failed attempts and exact resume conditions. A blocked parent stays unchecked; use a valid bounded structured defer and independent ready work, never an unchanged retry or hidden blocker. A true BLOCKED worker requests guarded stop. SDK packaging (RCP-1.1) and native owner production (RCP-1.2) can progress independently.
