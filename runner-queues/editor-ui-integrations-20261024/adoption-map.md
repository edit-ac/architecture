# Staged integration and ownership map

Status: STAGED. UIC-1.6 freezes ownership and the receipt contract below. Acceptance additions await the existing coordinator's safe-checkpoint adoption; they do not mutate existing plans or active runner state. Existing task IDs and completion evidence remain intact. No start/enqueue/resume command is issued by this plan.

## Adoption protocol

1. The existing coordinator verifies the guard and a safe checkpoint, identifies the actual source revision/current progress and inventories dirty paths. Do not edit an active snapshot, restart a worker, stash unrelated work or change queue order from a UI task.
2. Reconcile package paths/API names using UIC-1.1/1.6 and UNC-1.1/1.4. Each acceptance delta below is attached to its existing owner at that checkpoint. Where an existing parent is complete, preserve its evidence and create a bounded amendment owned by the same lane; do not uncheck unrelated completed work or represent new acceptance as already passed.
3. Existing lifecycle/bridge tasks remain reusable prerequisites, not tasks copied into this queue. If they lack an interface, return a narrow repair with exact missing method/event and acceptance to that owner. New UI parents stay blocked only on interfaces they actually consume. A complete backend-language roadmap is never an entry gate for a UI library.
4. Adopt a ready subset in dependency order through the existing guarded root coordinator only. Keep unavailable native hosts out of the way of independent web delivery. A serial queue cannot bypass a blocked file automatically. Preserve current global feature/native/docs/qualification sequencing; the numbered order here is a future topological plan, not a reprioritization of active work.
5. Existing final BNT and roadmap43 owners receive exact new profile/case requests. UI final tasks author only UI/installer cases and consume the owners' results. Record artifact/runtime/selector/revision matches in ignored progress. No source summary hashes or generated qualification evidence in Git.

## Source/interface receipts

Before adopting a row, the existing coordinator records the selected parent ID, source revision and exact additional requirement in that owner's progress. Its normal ignored path is `.roadmap-runner/backend-sdk-adapters-20261024/<linked-source-basename>.progress.md`, relative to architecture. Preserve implemented evidence, historical failures and original IDs. An open parent or absent receipt is unavailable evidence, not an ownership ambiguity. A completed old acceptance is never proof of a new delta.

Each consumed interface receipt must contain:

1. **Source identity:** owner/task and operation IDs; named parent criteria and delta; owning repository revision plus exact authored path hashes, including dirty inputs; current-format identity. Match the consumed inputs, rather than invalidate proof solely for an unrelated commit or delivery note.
2. **Public interface:** actual package/export or native module/class/method/event names and declared types; the table's existing deliverable and reconciled ledger path; pinned host/framework/peer versions and optional dependency boundary. For web, name the instance/state subscription and cleanup plus explicit overlay-container hook. Lifecycle-only imports exclude optional UI/CSS and other framework peers.
3. **Native ingress:** for a native row, name the existing Session/surface handle, readonly command-state observation, capture/rejection/disposal events, selection geometry coordinate space and owner UI executor. Name the bounded theme DTO ingress using `core/contracts/ui-theme.schema.json` (4096-byte serialized limit), atomic rejection and existing theme-resource mapping. Declare unsupported hooks; never send closures/CSS/DOM across the bridge or invent a fallback renderer.
4. **Validation state:** exact selector/command, runtime, exit, elapsed time, executed/passed/failed/skipped counts and evidence path. Count source inspection, production compilation and runtime observations separately. BNT receives exact UI profile/case IDs and returns matched runtime/OS/AT receipts; UTH supplies its completed handoff before BNT-1.7 aggregate closure. An inspection or DTO example does not qualify native ingress, an endpoint, a packaged consumer or a platform.
5. **Missing prerequisite:** exact absent method/event/type/platform, existing row owner, affected consumer, evidence and changed-input unblock condition. Return a bounded repair to that owner. Keep only the consuming boundary gated; independent web work proceeds under the coordinator's existing sequencing. No duplicate bridge package, independent runner, enqueue or snapshot edit is authorized.

The focused command from core is `node scripts/ui-integration-delivery.mjs UIC-1.6`. It reads only this table, linked parent definitions, the package ledger, queue manifest and web/native receipt authorities. It reports resolved/unresolved owner rows; it does not execute owner tasks, infer receipt availability or qualify a runtime. Actual receipt paths, consumed hashes and row counts belong in ignored UIC-1.6 progress/evidence, not source delivery prose.

## Required versus candidate support

Mandatory: plain browser, React/Vue/Svelte and named UI libraries/shadcn variants; existing Astro/Angular client compositions; Laravel frontend and non-React Filament field; native Apple/Android/Windows/Linux controls; bare RN and Expo iOS/Android development builds plus Expo web; Flutter iOS/Android with Material/Cupertino and Flutter web. Framework/theme peers are pinned at implementation; a plan is not shipped support.

Candidates: RN macOS/Windows, Flutter desktop per OS and additional independent design-system adapters. UFW-1.4 must record a real feasibility decision and exact implementation owner/unblock condition. Declaring an unsupported candidate does not permit dropping mandatory native SDK, RN/Expo mobile or Flutter mobile/web work.

## One final owner per acceptance family

`manifest.json` maps each requested UI outcome to implementation parents and exactly one new final owner. Those owners cover UI/installer behavior only. BNT owns reused semantic/input/lifecycle/recovery/host measurements; roadmap43 executes target observations. New source case definitions may be tracked; generated runtime results, images and reports remain ignored. An accepted receipt is reused only while its consumed inputs are unchanged.
