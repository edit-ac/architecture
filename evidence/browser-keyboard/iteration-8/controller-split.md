# Proposed controller prerequisite for WEB-1.8

Original authority: immutable source `source-e70e728e1701.md`, revision `78ed60d4dd3fa0c8055ffe2dbc957703e144f2e69172c0e26e1cb112e953c2ab`, WEB-1.8 context-appropriate Enter acceptance. Heading-end Enter must keep the original heading and create a following paragraph, with the caret at its start, as one applicability-checked semantic transaction and one undo group.

Current gap: `packages/web/src/input/keyboard.ts` rejects this action with `heading-end-needs-engine-command`. `packages/core/src/engine.ts:18` exposes split with owner/anchor but no destination attributes or reference to the generated owner. Rust `prepare_editor` (`crates/editac-core/src/commands/editor.rs:253`) generates the split internally. WASM Enter (`crates/editac-wasm/src/bridge.rs:602`) dispatches ListCommand::Enter, which requires a list/quote container (`commands/lists.rs:439`). The adapter cannot convert the generated heading into a paragraph in that same prepared request. Guessing generated IDs or committing split followed by format would violate the original atomicity/history boundary.

Preserved failure: `../iteration-7/initial.log`, original canonical `npm run test:browser -- keyboard`, heading-end case on all three pinned engines. The same explicit adapter rejection and packed engine contract remain. Iteration 8 did not rerun this unchanged failure. Its 120 passing implemented keyboard cases explicitly exclude heading-end, so they do not close WEB-1.8/I1/V1.

Proposed ordered split (controller approval/source revision needed):

1. Engine/WASM prerequisite: add a qualified atomic contextual heading-end command, or a validated destination-attributes option on split. Preserve the original heading level, insert an empty paragraph immediately after it, return/resolve the resulting stable caret, and prepare before mutating. Support the compound selected-replacement path that leaves the cut at the heading's end. Qualify read-only/stale rejection, one local update/history group, peer-preserving undo and the packed API with deterministic tests. The controller decides the owning engine task and exact ABI contract.
2. WEB-1.8 adapter continuation: replace the explicit rejection with that command, preserve selection through the result, retain the existing authored heading-end test, then run its named narrow case and the full unfiltered canonical keyboard suite on Chromium/Firefox/WebKit plus invalidated shared regressions. Keep every original criterion open until those checks pass.

No core semantics, ABI, roadmap source, publication or inference budget was changed by this proposal. WEB-1.9–1.12 remain dependency-deferred; they cannot bypass WEB-1.8. Current implemented behavior is internal development evidence, not device/IME or release qualification. The Firefox `keyboard.type` tab-composition setup failure is retained in iteration-8/multiline-repaired: native Tab indentation is now tested against authored whitespace seeded through the real packed recovery fixture; injected composition support is not claimed.
