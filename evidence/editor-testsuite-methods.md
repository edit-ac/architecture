# Editor testsuite methods research

Checked: 2026-10-11. Primary-source research and proposed test methods only. No editor implementation, browser qualification, device qualification, fuzz campaign or runtime test was executed. These methods complement the existing interaction, assistive-input and mobile case catalogs; a catalog entry is not an executed test or proof of support.

## Independent external oracles

Unicode segmentation has a reference corpus independent of an editor implementation. [UAX #29 revision 49](https://www.unicode.org/reports/tr29/tr29-49.html) corresponds to Unicode 18.0.0 and explains that default boundary test files are useful but not exhaustive, and that tailoring is permitted. Pin the engine's declared Unicode version and tailoring profile, then use the matching [GraphemeBreakTest](https://www.unicode.org/Public/18.0.0/ucd/auxiliary/GraphemeBreakTest.txt) and [WordBreakTest](https://www.unicode.org/Public/18.0.0/ucd/auxiliary/WordBreakTest.txt) data. The discovered latest version does not silently change edit.ac's contract. Segmentation conformance alone does not establish visual caret movement, word navigation or deletion policy.

[Input Events Level 2, 2026-05-01 Working Draft](https://www.w3.org/TR/2026/WD-input-events-2-20260501/) describes input intentions, target ranges and composition/cancelability distinctions. Its status explicitly identifies the test suite and implementation reports as work in progress. Use it to design assertions and record observed deviations; publication does not prove browser support.

[WPT's deletion-selection test](https://github.com/web-platform-tests/wpt/blob/48866a98b0022b880d2221e2992fb606df817051/input-events/input-events-delete-selection.html) drives keyboard actions and checks `beforeinput`/`input` ordering and deletion types for caret versus selected text. [WPT testdriver documentation](https://web-platform-tests.org/writing-tests/testdriver.html) distinguishes automation from web-API-only tests and supports manual input outside automation. Adapt narrowly relevant mechanisms and assertions, with provenance and licensing review before copying code. A passing browser-platform probe is evidence about that browser; it does not qualify edit.ac's reconciliation or command semantics.

For generated sequences, [fast-check's model-based testing guide](https://fast-check.dev/docs/advanced/model-based-testing/) describes command preconditions, actions/assertions, readable command serialization and shrinking. It explicitly warns against copying the implementation into the model. A small text/selection/history reference model can cover a declared subset; structural cases outside that subset need another oracle, not invented expected results.

## Proposed layered execution design

This section is an engineering recommendation, not an observation that upstream projects all implement the same architecture. Authoritative edit.ac behavior remains in the linked specifications and case catalogs.

| Layer | What it proves | Required result and limits |
|---|---|---|
| Semantic command fixtures | A command transforms a particular valid state as specified, or rejects/no-ops without mutation | Compare the full semantic tree, marks, selection, pending typing state, relevant anchors, history boundary and mutation count. Include disabled commands and invalid/stale inputs. No DOM required. |
| Property and conformance tests | Declared laws hold over bounded generated input domains | Validate schema, offsets, identity and anchors after each committed step. Run the pinned Unicode corpus. Record generated/executed/rejected counts and constraints so an empty effective domain cannot pass silently. |
| Sequence/state-machine tests | Correct individual operations remain correct when combined | Exercise typing → selection → formatting → break → delete → undo/redo; composition → remote edit → commit/cancel; paste → stale anchor → retry; and normalization/history interaction. Compare intermediate states and side effects, not only the end. |
| Browser adapter tests | Browser events, DOM reconciliation, selection and semantic commits agree | Drive genuine browser input for the supported pathway. Observe event traces and model state independently. Run Chromium, Firefox and WebKit with pinned versions and selected feature/capability profiles. Synthetic event replay remains explicitly labeled. |
| Application E2E | Real controls connect to supported semantics across a user workflow | Reach the editor through its visible UI; use keyboard, toolbar, touch-accessible controls, clipboard and recovery pathways. Keep narrow diagnostic state available without using private commands to substitute for the action being qualified. |
| Actual-device/manual qualification | Platform input and accessibility behavior absent from desktop automation work on a stated device | Record hardware, OS, browser/webview, keyboard/IME, locale, assistive technology and input method. Include composition, autocorrect, selection handles, software keyboard occlusion, dictation and screen-reader workflows where required by the case. Desktop mobile emulation cannot satisfy this layer. |

Run cheap command/conformance checks on relevant changes and a bounded deterministic sequence corpus on every appropriate CI run. Broader seed exploration and browser/device matrices may have separate schedules, but release gates must name the required evidence. An unexecuted or unsupported matrix cell remains explicit; retries cannot erase its original failure.

## Oracles and invariants

The [existing interaction contract](../specs/editor-interactions.md#acceptance-and-extension-boundary) already requires document, selection, history and mutation assertions. The harness should expose one observation record containing those fields, plus scenario-specific composition, anchor, input-provenance and persistence/sync state. This is an assertion interface, not permission to copy editor internals into expected output.

1. Hand-authored fixtures supply reviewed expected states independently of the command under test. Fixture parsing gets its own small tests and must not call that command or the production normalizer to construct the answer.
2. Direct invariants reject invalid trees, disallowed child/attribute relationships, invalid offset units, duplicate identities, dangling anchors and out-of-range selections. Check after each committed transaction. Transient DOM composition state uses its own allowed-state contract rather than being forced prematurely into committed-state invariants.
3. Conditional laws test round trips, replay and inverses only within their defined domains: undo/redo restores promised semantic and selection state; normalization is idempotent at a stable state; serialization round trips preserve the declared supported subset; a rejected command preserves state and emits zero mutations. Two mutually buggy conversion functions can round-trip, so these laws supplement explicit expected examples.
4. Change-locality assertions protect unrelated text, marks and nodes. Duplicate-event sequences test exactly-once semantic commits. Read-only, cancel, stale-anchor and navigation variants assert absence of unauthorized changes.
5. Cross-editor differential tests are optional investigative tools. Declare a shared schema, offset representation, supported command subset, mark policy, history grouping and canonical projection first. Different list schemas, Enter policies, Unicode tailoring or undo boundaries are not automatic bugs. Normalize only representational differences explicitly permitted by the contract; do not trim whitespace or discard selection/history to force equality.

## Determinism, quiescence and isolation

Use fixed clocks, deterministic IDs, prepared documents and mocked external transports. Reset document state, selection, pending marks, undo/redo, composition state, event listeners, mutation observers, storage, collaboration queues and host callbacks between isolated cases. Test intentional persistence in separately named sequences. Disposal must be exercised so detached listeners cannot satisfy the next fixture.

Define completion per layer: semantic transaction committed; scheduled normalization/render work drained; expected DOM selection visible; relevant persistence or peer acknowledgments observed when the scenario requires them. A stable revision and an explicit empty-work condition are better evidence than a fixed sleep. Bound the wait and capture queues/state on timeout. Do not wait for permanent network idleness on an editor with active collaboration, or drain an in-progress composition that the case intentionally inspects.

Separate ordinary production scheduling tests from harness-forced synchronous steps. Otherwise a synchronous fixture can conceal batching, ordering and observer regressions. Retain intermediate event order, `inputType`, target ranges, cancelability, composition state and semantic mutation counts when investigating browser failures. Do not fabricate input provenance that the real adapter cannot determine.

## Fuzzing, shrinking and test sensitivity

Generate valid documents and commands under explicit size/depth/step bounds, plus a separate invalid-input corpus with a specified rejection contract. Bias toward high-risk boundaries: empty/end positions, adjacent unlike blocks, mixed/backward selections, atoms, combining sequences, ZWJ emoji, whitespace, read-only regions and remote changes. Fixed regression seeds and a bounded exploration seed set serve different purposes; report them separately.

Save generator/version, seed, shrink path, initial document, complete command sequence, schedules, capability profile, invariant/oracle failure and final minimal reproducer. Retain the original failing trace as evidence. Shrinking should reduce operations and document structure while preserving selection validity and the failure's preconditions; a shorter invalid scenario is not necessarily the same bug. Promote a reviewed minimal case into the stable regression corpus. Fuzz results establish bounded explored coverage, not universal correctness.

[Stryker's mutation metrics](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/) distinguish killed, survived, uncovered, timeout, error and ignored mutants; code coverage alone does not show that assertions detect a defect. Apply the same principle to a small set of edit.ac fault probes: drop a mark, reverse selection direction, use the wrong offset unit, merge an undo boundary, double-apply an input event, accept a stale anchor or skip a schema check. Each probe should cause the intended test assertion to fail. Report the defect, detecting test and outcome; infrastructure/compile failures are not semantic detection. Review survivors and equivalent mutants rather than treating a percentage as release qualification.

## Evidence and provenance requirements

Every executable case should reference its catalog/spec requirement and layer, stable fixture ID/revision, engine revision, harness version, expected oracle, supported schema/capability profile and environment. Browser/device evidence additionally needs exact browser/OS/device/keyboard/locale versions and whether input was synthetic, browser-driven or actual OS input. Generated cases add seeds, bounds and generator revisions. External corpora add original URL, version, checksum and license.

Report planned, discovered, executed, passed, failed, skipped, unsupported and quarantined counts separately. Preserve first failures, retries, timeouts and minimized artifacts. Upstream test source commits above pin the inspected file revisions; mutable documentation is date-qualified. A future implementation should pin its own dependency/browser versions and recheck sources before using them as a compatibility promise.

All automated examples, probes, fuzz campaigns and mutation checks use deterministic fixtures and mocked provider/network transports. They do not load credentials, call paid inference, record live provider fixtures or grade real provider quality. Real-content AI dogfood remains a separate explicitly authorized workflow under the repository policy.
