17:One user intent commits once, regardless of whether it arrives as keydown, beforeinput, input, composition or an observer notification. Route keyboard, toolbar, menu, touch and assistive actions to the same applicability-checked command. Consume an event only when the editor handles it; preserve platform shortcuts, AltGraph, dead keys and composing Enter. Resolve conflicts in order: active composition/OS input, active popup, context-specific command, editor command, native navigation/focus. Read-only policy applies at the command boundary as well as the UI.
39:A collapsed mark toggle changes local pending typing marks without inserting empty spans or a document/history transaction. Moving to another selection recomputes pending marks; typing applies them once. Bold/italic/strike survive hard breaks and remain pending for immediate typing after ordinary Enter where the destination permits them. An empty destination does not persist these pending marks as content: moving away and returning recomputes marks from that destination. Structural splits filter inherited pending marks by the destination block's allowed marks. At the end of a link, ordinary continued typing defaults outside the link; typing inside a link retains it. Inline code suppresses Markdown shortcuts and incompatible marks. Clear-formatting removes supported presentational inline marks, preserves text and links, and leaves block kind unchanged; removing a link is a separate command. Unsupported/custom marks are preserved unless the named command explicitly targets them.
47:Retain native visual navigation when it is correct: arrows, Shift+arrows, Home/End, PageUp/PageDown, platform word/line/document modifiers, Select All and selection collapse. Test wrapped lines, vertical movement's preferred x position, RTL/bidi visual order, empty blocks, atoms and scroll-to-caret. Logical storage order does not define visual left/right. Keyboard shortcuts use semantic keys and platform conventions, not US physical-key assumptions. Browser find, zoom, navigation and OS/screen-reader commands remain available. Escape closes the highest active editor popup, then returns to ordinary editing without deleting text.
84:Typing shortcuts are a finite local rule set with exact triggers and context exclusions. Slash auto-open and typing rules require positively identified eligible direct typing from a qualified event sequence. Input with ambiguous provenance, including identical insertText without a correlated eligible typing/composition-commit policy, remains literal; visible commands stay available on keyboards/platforms that cannot safely establish eligibility. Never infer dictation identity from a fabricated source flag. They run after committed local text, never during IME, paste, dictation/replacement or remote replay. Escape, literal mode and code contexts preserve delimiter text. Backspace immediately after an automatic conversion reverses that conversion according to a recorded input-rule history boundary; normal undo then reverses the preceding typing. Partial syntax, unmatched delimiters and invalid links remain literal. Rules and paste parsing have separate switches.
94:For touch selection, software keyboards without modifier keys, browser viewport/occlusion and platform APIs, apply [mobile web](mobile-web.md) and the [mobile case catalog](../tests/mobile-web-cases.md). Track 40 builds on the semantics here without changing the Rust character/selection model. Explicit touch controls keep commands reachable when conservative input provenance suppresses automatic shortcuts.
112:Route keyboard shortcuts, platform Edit menus, context menus, accessibility actions and toolbar controls through the same focused-editor command applicability checks. Native spell/correction/reconversion replacements use their reported target range, which may differ from the visible selection; they never fall back to the latest caret. Find fields, table widgets, embedded code controls and host inputs own their commands while focused. Focus changes, popup closure and canceled dialogs must not retarget delayed work. Preserve browser/OS Find unless the host explicitly enables and exposes the first-party document-search profile.
114:The optional first-party search and code-command contracts live in [rich content](rich-content-extensions.md). They reuse engine preparation/history and public selection APIs. Multi-cursor/discontiguous editing, rectangular text selection, overwrite mode, application-wide search, macros, track changes and paginated page/section layout are capability decisions, not implied support from an IDE/Word comparison. Their controls/shortcuts remain absent or explicitly unsupported until their own semantics, serialization and platform evidence are qualified. No extra semantic model or general plugin event framework is needed for the scoped additions.
