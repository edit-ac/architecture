6:## User workflow and targets
22:## Markdown and shared state
24:Use the dialect, safety limits and diagnostics in [formats](formats.md). Literal text mode retains literal text and does not run Markdown typing shortcuts. One Yrs replica owns committed semantics during a session. The source buffer and parsed candidates are temporary input projections, as native text controls are in other hosts; there is no parallel writable editor model.
26:Keep the exact source baseline alongside semantic identities and stable anchors. Compare edited source with that baseline, prepare a bounded semantic change using the shared Rust parser/engine, validate it, then commit through the shared command/history boundary. A no-op preserves file bytes, whitespace and source spelling. Successful local source edits preserve the user's edited Markdown spelling; normalized Markdown serialization is an explicit export action. Importing a local file into a fresh session is permitted; re-importing a whole hosted snapshot on each save is not.
28:The shared source-reconciliation API must be qualified before advertising editing: source ranges alone do not prove stable identity mapping. Preserve unchanged nodes, marks and unknown module data. If a proposed Markdown change cannot retain unsupported semantics or map safely to current anchors, reject the commit with diagnostics and retain the edited source for recovery. A deliberate lossy export must be a separate explicit action. Invalid UTF-8, malformed input, resource-limit failures and rejected edits never partially mutate the live document.
30:Hosted exports use the deterministic Markdown representation, not the original author's source spelling. Retain the opening projection and its identity/anchor mapping as the edit baseline. Parse only user-edited source; received structured updates go directly into the existing replica. Source editing does not reinterpret remote updates as Markdown or reset collaborative history/epoch.
32:## Local files and recovery
36:Capture target identity and content fingerprint when opening. Before publishing an edit, verify the baseline has not been replaced or changed. Use a cooperating client lock and same-directory temporary write, flush, atomic publication and the supported platform's directory durability mechanism. Refuse a detected external edit or replacement; retain both the user's candidate and current target for explicit resolution. Document the limit of conflict detection with non-cooperating external writers; an atomic rename alone is not a compare-and-swap. Do not silently follow a changed symlink or overwrite an unrelated destination. The normal save authorizes changes to the opened target; export to an existing different path requires an explicit overwrite option.
40:For hosted documents, persist CRDT checkpoint, journal, pending update identities and bytes using a native adapter for [storage/sync](storage-sync.md). Keep drafts that have not yet passed semantic reconciliation separately from committed updates. Local Markdown export does not replace the checkpoint or outbox. Restore once with a distinct live replica/writer identity; subsequent network attachment must not initialize a second document.
42:## Hosted documents and concurrency
48:While the editor buffer is open, remote changes may advance the replica. Revalidate source-derived changes against current anchors before commit. Disjoint proven mappings may merge through the shared engine; overlapping changes, deleted targets or ambiguous source mappings produce an explicit conflict with retained base/local/current representations. Never overwrite the hosted document with stale full-text Markdown or claim CRDT synchronization resolves an arbitrary whole-source replacement.
52:## Delivery and qualification
56:Use prepared fixtures, a fake editor executable and mocked service/auth/receipt transports. Cover local Markdown and literal text, no-op/cancel, source preservation, supported semantic changes, unknown content, stale file save, crash recovery, cached offline edit, concurrent hosted edits, reconnect, revocation and wrong/missing receipts. Record actual executed/passed/failed/skipped counts and preserved failures. No paid inference, live credential loading or production hosted writes belong in automated qualification.
58:## Full client follow-up
60:Roadmap 15 delivers the built-in TUI in [tui-client](tui-client.md), reusing this external-editor/local/hosted baseline and [shared client contracts](client-contracts.md). Both clients accept validated ac:// document locators through the same catalog/authority resolver; IDs are not bearer credentials. Diff preview uses [change-diffs](change-diffs.md). Host-app MCP is a separate adapter and is not required to use or release the CLI/TUI.
