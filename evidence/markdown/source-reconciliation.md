# Portable source reconciliation qualification

2026-10-13. FMT-1.12 uses `SourceBaseline::capture`, `SourceBaseline::prepare` and `PreparedSourceEdit::commit` in the portable `editac-markdown` crate. The baseline owns exact original source, the opening checkpoint, parsed semantics and explicit ordered owner bindings. A draft is parsed once as a whole document. Scalar text/mark differences resolve through the opening UTF-16 anchors into the current document. Compatible disjoint remote edits survive; ambiguous mappings, container/cardinality changes, overlaps, deleted/moved targets, unsupported changed atoms, resource excess, wrong identity and stale commit return explicit recoverable conflicts.

Literal mode admits one literal paragraph and never interprets Markdown. No-op/spelling-only plans preserve original node/source identities and generate no update. Supported changes retain unchanged nodes and unknown data. `Document::prepare_source_edits` stages validated text, format, presentation and check-state commands on an isolated checkpoint and admits one final native update after rechecking document identity, writer, revision and checkpoint. It does not replace the document snapshot. This initial profile deliberately rejects structural changes that cannot prove stable mappings.

Required qualification ran with Node 24.19.0, offline locked dependencies and isolated exchange directories. `cargo test -p editac-core -p editac-markdown --locked --offline` passed: core 585 tests, Markdown 50 tests, zero failed/ignored. Of the Markdown tests, the dedicated `cargo test -p editac-markdown --test reconcile --locked --offline` executes 13, all passed. The zero-test doctest summaries are excluded from these counts. Unicode/marks, list/fence/reference context, presentation/check state, exact no-op, literal CRLF, unchanged unknown atoms, two-replica disjoint/overlapping updates, deleted/moved owners, cross-identity, stale plans and late second-target rejection are asserted. Rejection fixtures compare checkpoint/state-vector/history before and after; late failure never applies the first delta. Undo/redo checks preserve unrelated remote updates.

Evidence: `session-20261013/native-qualified.log`, `reconcile-identity-final.log` and `native-exchange-final/`. SHA-256 source/test/WASM/package identities are pinned in `device/manifest.json`; the workspace is dirty and HEAD alone is not an implementation identity. Earlier failed experiments and diagnostics remain under the session directory. In particular, staging multiple fresh clipboard fragments failed `invalid-before`/`nonadjacent-target`; the final source API uses semantic owner-preserving commands instead. The first full-native attempt omitted required isolated exchange directories and failed two blocks exchange tests; that log is retained as `native-final.log` and does not qualify the successful retry.

This portable API does not add CLI source-editor UI or claim structural source merging. The CLI's opening baseline/close flow can call this API under its own roadmap. Physical clipboard and release performance gates remain separately open as recorded in roadmap 05 and `../markdown.md`.
