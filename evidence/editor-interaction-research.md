# Editor interaction research

Checked: **2026-10-11**. Scope: official ProseMirror/Tiptap, Lexical and Slate documentation, source and issue trackers, to inform edit.ac interaction contracts and deterministic regression planning.

This is research evidence, not an implementation audit or a passing qualification report. No editor tests, provider calls, paid inference or browser automation were run. Upstream reports identify useful failure patterns; they do not prove that edit.ac or current upstream releases have those failures. The cases below are a bounded starting corpus, not a claim to cover every editor edge case.

## Documented behavior and design implications

| Source | Observation from the primary source | Implication for edit.ac planning |
|---|---|---|
| D1: [ProseMirror command source](https://github.com/ProseMirror/prosemirror-commands/blob/master/src/commands.ts) | The base Enter binding tries code newline, paragraph creation near a node, empty-block lifting and block splitting in order. Backspace/Delete use selection deletion, structural joining and node-selection fallbacks. `splitBlockKeepMarks` explicitly retains active marks. | Define command precedence and structural context, rather than a single universal Enter or deletion rule. Include selection and subsequent typing in the oracle. |
| D2: [ProseMirror DOM parser source](https://github.com/ProseMirror/prosemirror-model/blob/master/src/from_dom.ts) | Parsing normally collapses HTML whitespace. `preserveWhitespace` distinguishes preservation with newline normalization from full preservation; code-like nodes can preserve whitespace. | Specify typed text, plain-text paste, HTML paste and code import separately. A parser normalization policy must not silently become a typing policy. |
| D3: [Tiptap splitBlock](https://tiptap.dev/docs/editor/api/commands/nodes-and-marks/split-block), [HardBreak](https://tiptap.dev/docs/editor/extensions/nodes/hard-break) | Both document mark-preservation options with `true` defaults. HardBreak creates a line break and derives mark retention from mark split policy. | Make paragraph splits and hard breaks distinct commands. Specify which marks continue, stop, or come from the insertion point. |
| D4: [Lexical selection](https://lexical.dev/docs/concepts/selection) | Selection belongs to `EditorState`; range selection includes anchor, focus and active format. Node, table and absent selection are separate states. | A text-only assertion is insufficient. Assert anchor/focus, direction, active formatting, selected node/cells, focus and the next insertion destination. |
| D5: [Slate Editor API](https://docs.slatejs.org/api/nodes/editor) | Position iteration distinguishes offsets, characters, words, lines and blocks. Its character-position documentation warns about Unicode cases such as emoji. | Distinguish engine offsets from user movement/deletion units. Pin Unicode/platform behavior and test actual clusters instead of assuming a JavaScript string index means a visible character. |
| D6: [Tiptap Suggestion](https://tiptap.dev/docs/editor/api/utilities/suggestion) | Trigger matching can restrict prefixes and line position; spaces are configurable. Escape closes suggestions. Async item lookup has query limits/debounce and cancellation support. | Specify slash trigger eligibility, cancellation and dismissal, event ownership, and stale-result handling. Menu filtering fixtures can use local deterministic responses. |
| D7: [Lexical commands](https://lexical.dev/docs/concepts/commands) | Returning `true` handles a command and stops propagation. Tab can serve indentation or table-cell navigation; priorities resolve competing handlers. | Define exactly one owner for a key in each context: open menu, composition, table, list, code and normal editor. Preserve keyboard access out of the editor. |
| D8: [Lexical Markdown](https://lexical.dev/docs/packages/lexical-markdown) | Import, export and typing shortcuts use explicitly supplied transformer sets. | Keep dialect configuration and enabled extensions explicit across typing, paste, import and export; test intended differences as well as parity. |
| D9: [Slate normalization](https://docs.slatejs.org/concepts/11-normalizing) | Empty text descendants keep elements selectable. Block/inline shape rules support consistent splitting; normalization can add empty text around inline nodes. | Test empty nodes and inline boundaries after deletion/splitting. Define a valid engine selection independently of each adapter's DOM padding or placeholder representation. |

Documentation and `master` source are moving references, observed on the checked date. Tiptap documentation was labeled 3.x. These observations do not establish behavior for a particular dependency lockfile; qualification must record actual versions and the platform envelope.

The reporter qualified that the reduced snippet had not independently been run. | Enter splits the model but the DOM caret stays in the previous paragraph; following text goes to the wrong place. Test an actual custom block presenter and delayed view mounting. |

## Proposed deterministic regression corpus

The expected outcomes below are proposed edit.ac acceptance rules to resolve in the authoritative specs. They are not assertions that every cited framework implements identical behavior. A fixture should record the starting semantic document, selection, active marks, context and event sequence, then assert the resulting document, selection, focus, history grouping and next insertion. Invalid/no-op commands also need explicit outcomes.

| ID | Fixed scenario | Required oracle or decision |
|---|---|---|
| ENTER-01 | Enter at start, middle and end of a paragraph, including an empty paragraph; type a sentinel immediately afterward. Repeat with an adapter-rendered custom paragraph. | Correct split and retained text; sentinel lands at the post-split caret. Model and rendered selection agree. Include forward and backward noncollapsed selections. D1, I1. |
| ENTER-02 | Shift+Enter with plain and marked text, at paragraph boundaries and over a selected range. | A hard break remains inside the intended block; replaced text is removed once; retained/excluded marks follow explicit policy. Subsequent typing is on the correct side of the break. D3. |
| ENTER-03 | Enter in nonempty and empty list items, nested items, headings, quotes, code blocks and table cells. | The specified split/continue/lift/exit/newline behavior runs once. Parent structure, numbering, attributes and caret remain valid. Resolve cell and code exit rules explicitly. D1, D7. |
| DELETE-01 | Backspace and forward Delete at text, mark, block, list and inline-atom boundaries; repeat with cross-block selection. | Delete the selected content or perform the specified join/lift/select action; preserve unselected text and valid selection. Undo restores content, attributes and selection as specified. D1, D9. |
| DELETE-02 | Fixtures `1a`, `1 `, `1.`, `11`, `1😀`, each with collapsed movement, Shift+Arrow, Backspace and Delete. | Digit adjacency does not unexpectedly combine unrelated characters. Movement, selection and deletion use their declared units. I5. |
| MARK-01 | Toggle bold/italic/code with a collapsed caret, a partial range, a backward range and a mixed-format range; type a sentinel. | Distinguish stored mark changes from document changes. Define mixed-range toggle semantics, mark precedence and toolbar state; no selection loss or wrong insertion target. D3, D4. |
| MARK-02 | Toggle a mark in an empty paragraph, Enter twice, type immediately; repeat after moving away/back and after blur/refocus. | Explicitly decide which transient marks survive each transition. Toolbar and next inserted text must agree; do not infer persistence merely because an empty DOM element retains a style. I2. |
| MARK-03 | Enter and leave a link or inline code with arrows, mouse selection and insertion at both boundaries. | Honor inclusive/exclusive mark policy; adjacent ordinary text must not accidentally inherit a noncontinuing mark. Check adjacent/empty inline nodes too. D4, D9. |
| SPACE-01 | Type leading/trailing spaces, repeated spaces, tabs, NBSP, and spaces adjoining differently marked spans. | Preserve user text under the typing contract; visible rendering, semantic text and exported text must be explainably consistent. Do not use HTML parser collapse rules to delete typed spaces. D2. |
| SPACE-02 | Paste fixed plain text and equivalent HTML with LF/CRLF, empty lines, tabs, NBSP and preformatted code. | Assert each declared paste normalization separately; no accidental word concatenation at span boundaries or loss of code indentation. Repeated paste is deterministic. D2. |
| NAV-01 | Arrow/Shift+Arrow across marked spans, inline atoms, empty blocks, wrapped visual lines and document edges; Home/End and word movement where supported. | Legal selections with explicit anchor/focus direction and affinity; no stuck caret, skipped editable position or undesired document edit. Visual-line expectations belong to the adapter/platform profile. D4, D5, D9. |
| NAV-02 | Tab/Shift+Tab in body text, nested lists, code, table cells and an open slash menu. | Apply the context's declared owner once; check first/last cell and first/last list item. Preserve a documented way to move keyboard focus out of the editor. D7. |
| MENU-01 | Type `/` at document start, after a space, inside a word, in code, after an inline atom and while replacing a selected range. | Open only in allowed contexts. Query range remains correct after edits; Escape dismisses without losing typed content; cancel and selection commands have defined history behavior. D6. |
| MENU-02 | Open a menu, press arrows/Enter/Tab/Escape; repeat with zero results and with local async query A resolving after query B. | Navigation is not also a document command; no accidental paragraph on acceptance, no action on absent selection, and no stale result application after dismissal or changed query. Use prepared result lists and controlled promises. D6, D7. |
| UNICODE-01 | Fixed composed/decomposed accents, a surrogate-pair emoji, skin-tone modifier, ZWJ family, flag pair, variation selector, Indic conjunct and Thai text. | Validate engine offset conversion independently from native movement/deletion policy. Never leave invalid text or split protected engine boundaries; record intentional platform differences rather than imposing one universal Backspace unit. D5. |
| UNICODE-02 | Mixed RTL/LTR runs with punctuation, digits and marks; move, extend selection, replace, delete and undo across run boundaries. | Logical content and anchor/focus remain correct while visual movement follows the platform profile. Check caret affinity at directional boundaries, not only exported text. D4, D5. |
| IME-01 | Start/update/commit/cancel composition over a caret and over a cross-block selection; Enter during candidate selection; dead-key accent input. | Committed text appears exactly once; cancellation obeys adapter policy; candidate confirmation does not also split a block or accept a slash command. Model/view converge without duplicate history entries. |
| IME-02 | Begin Japanese/Korean composition in bold text, click a plain paragraph, then type; repeat after a Tab and next to an inline atom. | Defined commit/cancel on selection change; destination marks come from the agreed destination policy. Editor remains responsive and composition text is not lost. I3, I4. |
| PASTE-01 | Paste fixed plain text, sanitized HTML and Markdown over selected text, into lists/code/table cells and at mark boundaries. | Select the intended MIME/dialect path; replace once, sanitize unsupported content, preserve supported structure, place the caret after insertion and provide coherent undo. D2, D8. |
| MD-01 | Feed the same supported Markdown constructs through typing shortcuts, paste, import and export; include escaped delimiters and code spans. | Compare only semantics the contract promises to share. Unsupported syntax has an explicit lossless/preserved fallback or documented warning; typing shortcuts do not activate inside excluded contexts. D8. |
| MD-02 | A code block contains embedded triple backticks; an inline-code fixture contains backticks of varying lengths. Parse, serialize, reparse. | Choose safe delimiters; preserve the complete code text and intended node count. Repeated round trips stabilize under the declared serializer normalization. I6. |
| MD-03 | Paragraphs `Hi. there`, `Ok. Next step.`, `Ex) aside`, plus `0. zero\n1. one` and nested continuation paragraphs. | CommonMark/GFM mode preserves ordinary sentences and numeric list start values; optional nonnumeric list dialects are explicit and separately tested. I7. |
| HISTORY-01 | Follow split, hard break, mark toggle, list conversion, paste, slash acceptance and committed composition with undo/redo, then type. | History boundaries match user actions; no stale stored marks or selection after replay. Compare canonical document and expected selection, not internal transaction count alone. D1, D4. |

## Qualification boundaries

Use pure engine fixtures for semantics, adapter event fixtures for translation, and real browser/native interaction tests for DOM selection, event ordering, visual navigation and composition. Synthetic composition events do not establish that real IME candidate windows, native cancellation, mobile keyboards or accessibility input work. Record that gap and retain named manual platform/IME scenarios with exact build, OS, browser/control and keyboard versions.

Prioritize intersections exposed by the evidence: custom renderers plus Enter, empty blocks plus stored marks, Tab/inline atoms plus composition, and parsing plus serialization. A case should compare the semantic document and selection after each meaningful operation and after the next typed sentinel; final HTML alone can miss the original failure.

Keep the corpus versioned with stable scenario IDs, deterministic inputs and explicit expected behavior. Add a minimized fixture for each newly observed issue, link the upstream or product report, and record executed/passed/failed/skipped counts separately from these planned cases. Parser/property testing can use seeded generators and prepared corpora; menu/network behavior uses mock transports. None of this requires AI-generated test content or paid inference.
