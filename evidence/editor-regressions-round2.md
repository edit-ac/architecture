# Editor regression research, second round

Checked 2026-10-11 against primary upstream issue, discussion and patch records. These twelve patterns extend the existing [interaction](editor-interaction-research.md), [mobile platform](mobile-web-platform-research.md), [touch extension](touch-extension-research.md) and [assistive input](assistive-input-research.md) evidence. They cover transaction semantics, history, structural replacement and presenter ownership beyond the earlier composition, segmentation and mobile cases.

This is research and a proposed deterministic corpus. No upstream reproduction, edit.ac test, browser check or provider call was executed. Closed issues are not assumed fixed; reported versions are not inferred affected-version ranges. Test sequences below adapt the evidence into edit.ac requirements unless an upstream regression test is explicitly identified. Current upstream behavior remains unqualified here.

## Test-suite and review implications

Keep the semantic cases in the shared engine suite and event/presenter cases in adapter contract suites. Extension cases should use a tiny deterministic fake presenter and fake normalizer, so baseline qualification does not require shipping a rich extension. Source-browser verification remains separate: synthetic events cannot establish trusted clipboard behavior, drag geometry or real framework reconciliation on supported browsers.

Store transaction traces with operation origin, entry/exit selection, pending marks, mapping inputs, history group and presenter identity. Use fake clocks, explicit remote delivery schedules and prepared clipboard payloads. Assert the resulting model and selection, then undo/redo and subsequent typing; a screenshot alone misses unmanaged DOM, stale presenters and incorrect history. Check normalization work counts as well as final content.

Architecture review should trace one owner for each of these boundaries: semantic history grouping; transaction entry selection; selection mapping and insertion-anchor kinds; schema-fitting replacement; normalization convergence; event ownership and deduplication; presenter lifecycle; and clipboard fragment conservation. The evidence does not justify a second engine, browser-specific core semantics or a new generic plugin framework.

Research outcome: 12 additional failure patterns documented; 0 automated or manual test executions; 0 qualification passes claimed. Proposed cases need stable fixture IDs and roadmap acceptance wiring before they become executable completion evidence.
