# SYN-1.6 authorization and durable acknowledgments

Implemented `ReceiptSession` in `packages/web/src/sync/receipts.ts` and the deterministic `tests/receipts.test.mjs` harness. The host routes baseline Yjs sync separately from negotiated application receipts. The client checks immutable peer identity before attaching, delegates complete writer/sequence/content admission and transaction completion to `UpdateOutbox`, and exposes `remoteCommitted` only for an admitted durable receipt. One bounded outbox page is uploaded per host event. Denial/revocation detaches baseline traffic while retaining the engine and recoverable journal; late responses from old attachments cannot prune. Recovery export preserves the Rust CRDT checkpoint.

The harness uses actual Chromium IndexedDB, Rust WASM client/peer, loopback HTTP reference relay and SQLite FULL WAL transaction commit. Baseline peer routing and auth grants are prepared fixtures. Production authorization, deployment, hardware durability and SYN-1.7 two-browser crash recovery remain outside this evidence.
