# Desktop editing conventions and additional acceptance gaps

Date: 2026-10-12. Status: primary-source research and proposed acceptance; no editor runtime, device, performance or release qualification was executed. This extends the existing editing, rich-content, native and regression tracks. It does not create a roadmap or promise exhaustive coverage.

## Existing coverage and remaining distinction

`editor-interactions.md` already requires selection replacement before Enter/Shift+Enter, and `BRK-04` tests `a[bc]d`. `NAV-01…07` cover directional keyboard selection and visual movement. `REG-11` covers drop event ownership, move/copy modifiers and duplicate notifications. `RCH-1.17` owns structural block reorder. None of those alone proves that a selected **text fragment** can be moved to its correct destination with source deletion, preserved formatting and one undo action. The additional cases below deepen those contracts without duplicating their common seeds.

The distinction between native editing conventions and optional IDE conveniences matters. Basic replacement, pointer selection, context menus, clipboard and text dragging are baseline interactions where the host supports them. Search/replace and code transforms can be official optional capabilities with explicit registration and loading boundaries. Multi-cursor/rectangular text selection, automatic bracket pairing and overwrite mode must not appear accidentally through a native control or third-party package: they require separate supported profiles and qualified semantics before being exposed.

## Primary-source observations

Sources were read on the date above. Product documentation establishes expected interaction families, not evidence that edit.ac implements them. Proposed failure/race cases below are engineering deductions, rather than claims about upstream bugs.

Escape cancels before release. Modifier keys and native drag sessions must be qualified per platform. |

| [Apple Pages: selection and insertion point](https://support.apple.com/en-ca/guide/pages/tanf610b45cf/11.1/mac/1.0) | Selected text is replaced by new typing. This is a historical Pages 11.1 reference for the replacement convention, not a current platform-support assertion. |
| [Microsoft: Word keyboard shortcuts](https://support.microsoft.com/en-us/accessibility/word/keyboard-shortcuts-in-word) | Word documents selection extension, table-cell navigation and platform-specific bindings. | [Microsoft: delete a table row, column or cell](https://support.microsoft.com/en-gb/word/delete-a-row-column-or-cell-from-a-table) | Delete on a selected row/column clears its contents without removing structure; explicit table commands remove cells, rows or columns. This motivates separate text, cell-range and structural selection modes. |
| [Apple TextEdit: find and replace](https://support.apple.com/en-ie/guide/textedit/txtef6cfde1a/mac) | Supports using the current selection as the query, next/previous matches, case options, replacement and Replace All In Selection. Query input selection and document search scope are distinct state. |
| [VS Code: basic editing](https://code.visualstudio.com/docs/editing/codebasics) | Supports selection-seeded find, search in selection, case/whole-word/regex modes, multiline queries, and Enter/Shift+Enter result navigation while the find field owns focus. It also exposes multi-cursor and rectangular selection as deliberate editing features. These illustrate useful capabilities; they do not make a code editor's text model appropriate for rich prose. |
| [JetBrains: work with code in the editor](https://www.jetbrains.com/help/idea/work-with-code-in-editor.html) | Documents duplicate/delete/move/join line actions and multiple carets. | [Microsoft: undo, redo or repeat](https://support.microsoft.com/en-us/office/foundations-experiences/undo-redo-or-repeat-an-action) | Undo, redo and repeat are different commands; applicability is visible, and saving need not destroy undo history. A repeat-last-action feature must not be inferred from a redo key or an empty redo stack. |

## Concrete additions to existing acceptance

These are candidate sequences for the controller-owned catalog. The task references identify existing owners; bounded additional parent tasks may be appended inside the same tracks when implementing a row exceeds a current task's scope. All mutation cases also assert content, marks, semantic structure, selection direction, history, update/journal counts and peer replay. Run forward/backward selections and undo/redo. Rejection must not leave a partial deletion.

| Gap | Concrete acceptance sequence | Owning track/task boundary |
|---|---|---|
| Replacement matrix beyond one paragraph | `a[bc]d` + Enter gives `a¶d`; Shift+Enter gives `a↵d`. For compatible paragraphs, `ab[c¶de]f` gives `ab¶f` or `ab↵f` respectively, retaining unselected marks. Test selected inline atoms, hard breaks, heading/list destinations, code LF, and table-cell hard breaks. Incompatible cross-container replacement follows the declared prepared policy or rejects atomically. Composition-confirming Enter does not perform the split. | `INT-1.2`, `INT-1.7`, `RGS-1.2`; native committed-edit tasks |
| Pointer selection granularity | Double-click a word, triple-click a paragraph, then Shift-click before/after the anchor across wrapped paragraphs. Test punctuation, combining characters, bidi text and marks. Selection changes produce zero content/history changes; the selected logical range must match the qualified platform profile, with no half-grapheme endpoints. | `INT-1.5`, native selection-mapping tasks; proposed bounded pointer-selection acceptance in track 38 |
| Selection drag versus fragment drag | Drag from an unselected caret region to create a selection; separately press within an existing selection and exceed the native drag threshold to move the fragment. A click without a completed drag follows the platform's selection-collapse policy and never moves content. Word/paragraph selection and dragging must coexist. | `INT-1.5`, `REG-11`; track 38 text-drag boundary |
| Same-document text relocation | In `ab[CD]ef`, move to before `a` → `CDabef`; move after `f` → `abefCD`. Resolve the destination against the source removal so later positions do not drift. Preserve fragment marks and legal atoms, collapse/select the result according to the published profile, commit once, and restore exact original content/selection with one undo. This is text transfer, not proof supplied by a block-reorder test. | `INT-1.10`, `RGS-1.2`, `RGS-1.7`; shared prepared text/structural commands |
| Self-drop, copy, cancellation and rejection | Same-document **move** anywhere inside the selected range or at its boundaries is a no-op. Copy to an allowed destination preserves the source. Modifier changes update the operation before commit. Escape, canceled native session, invalid destination, readonly transition or failed preparation preserves the source and produces zero edits. Track the semantic source; do not trust client-supplied internal identifiers from an external payload. | `INT-1.10`, `INT-1.12`, `REG-11`; native clipboard/drop tasks |
| Cross-editor/application transfer | Two editors in one page must not both consume the same drop. Cross-document transfer records independent source/destination session ownership and never claims an atomic cross-document move unless the protocol provides it. External/untrusted drop imports a copy; source deletion is permitted only through the source owner's authenticated successful move acknowledgment. Failed/canceled destination admission preserves source content. | `WEB-1.9`, `RGS-1.7`, native `*-1.13`; track 38 transfer boundary |
| Drag autoscroll and stale anchors | Drag a selected fragment toward an offscreen destination in a scrolled container. Target indicator follows the actual insertion position; bounded autoscroll stops on drop, cancellation, disposal and loss of ownership. Edit/delete the source or target remotely mid-drag: revalidate anchored content and reject a stale or ambiguous move, with no duplicate or missing text. | `INT-1.5`, `INT-1.12`, `RGS-1.6/7`; native mapping/drop tasks |
| Context menu and native command routing | Right-click an existing selection, open Cut/Copy/format commands, then move focus to the menu. Use the captured range, not a stale current DOM selection; disabled/readonly commands remain inapplicable at commit. An embedded input owns its own Cut/Copy/Select All. Native menu actions and key shortcuts produce the same semantic result exactly once. | `INT-1.6`, `INT-1.12`, `REG-10`; native command/history tasks |
| Find field versus document editing | Open Find from selected text; query seeding creates no mutation. In the find field, Enter/Shift+Enter selects next/previous result rather than inserting a paragraph. Escape closes Find with a published focus/selection restoration policy. Searching a second editor cannot navigate the first. Browser Find remains available unless an explicit host mapping chooses the editor capability. | `EXT-1.5/7`, `INT-1.6`; optional first-party search within track 25 |
| Replace one, all and selection scope | `cat cat` with first match active: replace with `dog` → `dog cat`; Replace All → `dog dog` in one explicit history group. Selection-scoped replacement never alters matches outside captured scope. Search spans marked text without discarding unrelated marks; readonly matches and schema boundaries are validated before any mutation. Matches are revalidated against current revision/anchors before commit. Find results/highlights never enter document state or history. | `RGS-1.2/3/6`, `EXT-1.5`; optional first-party search within track 25 |
| Bounded search and advanced options | Case/whole-word rules declare locale/Unicode semantics. Empty queries, zero-length matches and empty replacement terminate deterministically. Invalid or expensive regex is rejected/canceled under explicit limits if regex is provided. Do not require regex for initial literal search. Deferred results from an old session cannot highlight or replace in a new one. Limit visible decorations and rescan affected regions rather than synchronously repainting every match per key. | `EXT-1.5/9`, `RGS-1.6`; rich-content performance owner `RCH-1.20` |
| Code-only editing conveniences | Within one code block, move/duplicate/delete selected logical lines or the caret's line; include final line without LF, reversed selection, indentation, tabs, emoji and empty lines. Move at a block boundary is a no-op; never cross into prose. Preserve literal text and selection; one command/undo. Join-lines, case transforms and expand/shrink selection require named policies; no language-aware rewrite or autoformat is implied. | `INT-1.6`, `RCH-1.5`, `EXT-1.5`; optional first-party code commands within track 25 |
| Table content versus structure | With a rectangular cell selection, Delete clears contents but retains selected row/column identities and dimensions. Explicit Remove Row/Column changes shape once and follows last-row/column policy. A text selection inside one cell uses text replacement. Navigation into a populated cell follows a declared caret-versus-select-content profile; typing must not silently erase an unexpected cell. | `RCH-1.6/8`; native table-editing tasks |
| History availability and focus | Type → undo → navigate/find/scroll → redo still redoes the edit; those view actions create no content history. Type → undo → new local edit invalidates the prior redo branch under the qualified history policy. Save/checkpoint does not itself create an undo step or replay old content. Undo in a nested form input cannot accidentally undo the outer document. | `INT-1.12`, `RGS-1.3/7`, `ENG-1.11`; native command/history tasks |

## Architecture and qualification consequences

Use the shared applicability-checked command and prepared mutation paths. Platform controls own drag sessions, hit testing, pointer granularity, autoscroll and native menu integration; Rust owns document effects, boundaries, atomicity and semantic history. Existing structural-move support is not automatically an identity-preserving arbitrary text-range move primitive: qualification must explicitly identify the available representation and conflict policy.

First-party search/code functionality must declare capability, supported selection modes, command conflicts, platform presenters, cancellation and fallback. Registering two competing command handlers must fail or resolve deterministically; it must not change behavior with extension load order. Optional modules must retain the existing loading budgets. Do not put search highlights, drag previews, selection overlays or code decorations into collaborative document state.

Use fixed-clock synthetic documents, deterministic drag/replace fault injection, real engine assertions and actual native input evidence. Replay can validate routing but cannot prove OS drag negotiation, selection granularity or menu integration. Measure long selection drags, autoscroll, many search matches and large code-line transforms at the existing supported document envelopes; a promise of low work requires recorded latency, allocations, invalidated/rendered range and cancellation evidence. No source above establishes edit.ac performance or universal editor correctness.

## Standards cross-check

The [W3C Input Events Level 2 working draft](https://www.w3.org/TR/input-events-2/) names replacement, drop insertion and drag deletion intentions and distinguishes target-range/data exposure for contenteditable and text controls. It explicitly says an input type's presence in the specification does not mean every implementation supports that operation. These are protocol clues for adapter correlation and browser qualification, not proof of an observed event order.

The [WHATWG drag-and-drop processing model](https://html.spec.whatwg.org/multipage/dnd.html) separates source, target, allowed effects and negotiated operation. edit.ac's source-preservation, same-document atomic move and conservative cross-document receipt rules are product contracts built on that boundary. A MIME label or a foreign drag effect is insufficient evidence of an internal authorized session or durable storage outcome. Both sources were checked on 2026-10-12.
