# Use one durable document format before publication

User decision: 2026-10-23. Until the first published, externally consumed editor contract, maintain one production document schema/profile and one current implementation of each API, wire and ABI contract. Earlier development iterations are regression fixtures and design history, not supported production versions. This supersedes earlier instructions to retain executable v1–v4 profiles or synthetic previous/current SDK matrices. It authorizes no publication.

User clarification, 2026-10-24: the project is pre-alpha. Use unversioned canonical names: schema `editac.registry.editor` and profile `editac.yrs-yjs.editor`. This supersedes the earlier instruction to retain the `.v5` suffix. There is one current format and one production implementation, with no numbered schema variants, legacy aliases or previous/current package support matrices. New code selects `DocumentIdentity::current`; SDK versions and development iteration numbers do not become document-format identity. The [durability contract](../specs/document-durability.md) defines the required invariants and remaining proof.

The witnessed structure remains the one current layout; removing a development suffix does not remove its semantic guarantees. Protocol 1, Yrs/Yjs update encoding 1, UTF-16 offsets and necessary ABI discriminators still describe real wire/encoding contracts with one current supported value each. They do not imply maintaining multiple editor formats. Numbered historical specification filenames and fixture inputs remain development history only.

The existing core/Session current-format cutover owner must propagate the unversioned identity through creation, restore, journal scope, sync, WASM/FFI, native consumers and current fixtures, then provide focused evidence before dependent SDK acceptance. Until that implementation lands, the new names are the required target, not a claim that existing binaries already emit them. Adopt at the existing coordinator's safe checkpoint; do not edit an active runner snapshot or start a second controller. Preserve original stored bytes and real user data; do not add a runtime `.v5` alias, relabel a checkpoint on open or silently rewrite a database. Any necessary real-data conversion remains an explicit offline operation under the policy below.

Remove obsolete production admission, replay, projection, command, serializer and consumer paths after their current-format replacements and affected checks pass. Move older independent mappers to fixture-only oracles. Preserve their input bytes and historical failure dispositions. Port useful behavioral assertions to the current format; do not delete a regression because its original fixture used an older profile. Unsupported old/future envelopes fail before mutation and preserve recovery bytes. Do not add a production compatibility feature flag, parallel legacy crate or silent profile relabel as a workaround.

Review other pre-release version layers as well. Replace fabricated previous/current package endpoints and unused unpublished API aliases with current-consumer tests and explicit unsupported-input tests. Keep distinct numbers only where they describe distinct real contracts: document identity/epoch, user revision history, CRDT update encoding, protocol framing, external import formats, and necessary ABI/descriptor validation. One current supported value per such contract is enough. An external file format or a genuine document revision is not an obsolete editor version.

Any needed conversion of real development data is an explicit offline, separately reviewed operation: preserve original checkpoint/journal bytes, validate the converted content and unknown data, write a fresh destination/epoch, and leave the original available. No automatic reseeding, reset, downgrade or in-place rewrite is allowed. Discover actual data before deciding a converter is necessary; no converter is required merely to preserve synthetic old fixtures.

Compatibility obligations begin with actual published artifacts and data. Before first publication, record and freeze the canonical document layout, protocol and ABI, identify the published baseline, and approve a recovery/migration policy. Do not infer version stability or publication from an internal alpha or passing source checks. Existing same-format durable data must remain reopenable independently of SDK build hashes.

Feature completeness remains the delivery priority. Correctness, data safety and a real missing shared API still block their dependents. A bundle-size target or provisional latency result cannot block independent implemented feature work. Limit pre-feature size optimization to one 45-minute batch or two materially different measured repair hypotheses per milestone, whichever ends first; then checkpoint useful changes and move remaining work to final performance/size owners. Do not repeat unchanged failed inventories. The 512 KiB total / 32 KiB editor-JS gzip hard caps remain mandatory final publication/readiness gates; this changes sequencing, not limits.

The controller must put the canonical-format cutover and its focused regression/durability gate before new dependent native work. After that gate, queue feature delivery before remaining web/native optimization and exhaustive qualification. Preserve the stopped run, dirty source, exact accepted results and original task/case IDs. One root-workspace runner on the existing main branches remains the only authorized controller.
